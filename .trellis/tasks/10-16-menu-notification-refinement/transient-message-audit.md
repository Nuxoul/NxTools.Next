# First-party transient feedback audit

## Scope and method
User authority: notification-unification.md. Reviewed first-party Desktop renderers plus their operation callbacks, not just Alert imports: Alert/inline_error/state helpers, status/notice/error assignments, Saved/enabled/disabled/copy operation copy, popup/window hosts and notification entry points. Also inspected C# native error presentation, browser popup/content status and CLI/BrowserHost channel boundaries. This is a source inventory, not proof that every operation was physically exercised. No new transport, store or manager; all Desktop transient feedback uses the original NotificationCenter. The interrupted audit worker supplied partial edits but no completed review/report; the parent verified and completed the inventory.

## Non-Desktop channels
- C# Windows/ErrorDialog.cs is a bounded one-shot startup-failure dialog requested through --error-dialog when GPUI could not initialize. There is no living NotificationCenter then. DesktopTrayController owns a tray icon, not balloons/toasts; no ShowBalloonTip operation path was found. Ordinary native results return typed correlation/native codes to Rust.
- Browser extension popup.js::setMessage and content-script.js::setStatus are browser-requested feedback in a separate browser process and must report native-host absence without starting Desktop. They are not duplicate Desktop overlays. Keep approved browser UI and demand-only Native Messaging; no new cross-process toast protocol in this bug fix.
- CLI intentionally uses stdout/stderr and exit status; BrowserHost uses bounded Native Messaging replies. Headless errors cannot depend on a visible Desktop notification window. Installer/bootstrap failures remain their dedicated requested channel.
