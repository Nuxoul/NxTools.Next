# Clipboard styled-menu preparation timeout correction

## Cause / narrow change
The production menu creates an independent hidden GPUI HWND, waits for C# `PrepareStyledSurface` to confirm final work-area client bounds, places the official PopupMenu, then formerly waited for `window.on_next_frame` before sending visibility. Hidden Windows HWNDs do not supply that ordinary frame loop: visibility depended on the callback that depended on visibility. The existing 3s watchdog consequently cancelled an otherwise prepared menu. This is a concrete source-backed lifecycle defect, matching the prior screen-notification finding; **the new menu native chain has not yet been executed in this delegate**, so installed symptom/causal reproduction is not claimed.

`native_context_menu.rs:457–525` now checks GPUI's actual device viewport against native readback, places/rebuilds the official menu, explicitly builds the hidden scene using public `Window::draw` after the source/view leases, then defers reveal to revalidate exact session/phase/trigger/source-session. Mismatched viewport fails closed, never a default-size/clipped show. Visibility acknowledgement still precedes a distinct activation command; activation acknowledgement alone sets ready. Existing watchdog, take-once terminal, disabled-ancestor eligibility, original callbacks, cascade, outside/Escape and focus owners are unchanged. No C# product change, framework/vendor patch, show-first workaround, new manager or fallback.
