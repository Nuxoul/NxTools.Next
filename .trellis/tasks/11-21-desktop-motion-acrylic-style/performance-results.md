# 原生材质资源对比

日期：2026-11-21。比较对象为同一隔离 GPUI Debug 可执行文件的 Solid / Acrylic，不是已安装软件。

## 结论

当前负载下，Acrylic 的新增成本主要落在 DWM，而不是 GPUI 进程：

- GPUI 私有内存的配对中位增量在 −0.063～+0.051 MiB，CPU 差值随配对波动，没有观察到稳定的应用进程增量。
- 单窗口静置时，DWM 私有内存配对中位增量为 **6.52 MiB**，专用显存增加 **4.94 MiB**，最忙 GPU 引擎增加 **0.082 个百分点**。
- 移动背景下，单窗口 DWM GPU 增量为 **0.218 个百分点**；同进程三窗口为 **0.358 个百分点**。相应整机 CPU 配对中位增量为 **0.094 / 0.156 个百分点**。
- 输入和滚动负载的更新计数相近，未观察到 Acrylic 带来的稳定应用帧间隔恶化。实际负载没有达到目标60Hz，不能据此宣布满帧性能验收。

这些结果支持继续制定全软件主题接入方案：每个 HWND 共用一个材质底层，正文、输入和选中层使用统一实度，不对每个子控件重复模糊。现有主题 / Acrylic 仍是两套完整主题，配色和字体独立；本轮没有修改正式产品。

## 方法与完整性

- Windows11 build22631，100% DPI，12逻辑处理器；主工作区2560×1400。显卡为 RTX4060Ti，驱动32.0.16.1088，系统另有 GameViewer Virtual Display Adapter。
- 固定 Kit/Base/Component/Assets0.8.0 + gpui-pre0.3.9、私有 UnderBorder 夹具、Sarasa UI SC、同一深色配色、尺寸及合成内容。两种模式使用同一个二进制和相同原生准备流程，只改变实底/透光填充及 Accent0/4。
- 五场景，各三组配对，顺序依次为 Solid→Acrylic、Acrylic→Solid、Solid→Acrylic，共30次。每次预热8s，目标测量15s，正常关闭尾段1s。
- 计数器和阶段日志每250ms轮询；分析裁去两端各0.5s。阶段观察时长14.843～15.209s，各进程实际 CPU 差分区间13.392～14.000s；使用各自实际 QPC 时长计算，不按名义15s除算。
- 30次均正常完成、退出码0；分析区间包含1600行普通采样、5101个 GPUI 呈现记录、27020个 DWM 呈现记录。60份 PID 限定帧 CSV 均有对应阶段数据。
- 42个实际客户区均在工作区内；六次三窗口运行均为同一 PID 的900×600、480×540、620×60三个互不重叠客户区。
- 临时管理员观察器和定时 PresentMon 会话均已正常退出。没有更改用户组、权限、服务、系统设置或真实应用数据。

表中的 `Δ` 均先计算每组 `Acrylic−Solid`，再取三组中位数；范围是三组配对差值的最小/最大值，不是置信区间。两列独立中位数之差不一定等于配对中位差值。

## 负载与帧

- 输入：每次15s均完成240次真实 InputState 更新，约16Hz；目标是20Hz。实体身份未更换。
- 滚动：Solid完成514/516/518次，Acrylic完成517/521/516次，约34～35Hz；目标是60Hz。六次均实际绘制到第980行，列表总数1000。
- 移动背景：普通背景场景39.525～39.961次更新/s；三窗口39.744～40.009次更新/s。两种材质使用相同背景实现与目标间隔。
- 静置没有 benchmark 更新任务，每次分析区间观察到26～27个 GPUI 呈现记录，与输入光标闪烁节奏相符；不将它解释为60Hz动画。

| --- | ---: | ---: | ---: |
| 静置 | 518.230→517.855 | 0.266→0.288 | 0.481→0.508 |
| 移动背景 | 518.730→517.915 | 0.371→0.542 | 0.511→0.567 |
| 输入状态更新 | 68.323→68.126 | 0.312→0.279 | 0.482→0.510 |
| 虚拟列表滚动 | 35.387→35.325 | 0.337→0.288 | 0.485→0.510 |
| 同进程三窗口 | 逐交换链数据见JSON | 不跨链汇总 | 0.536→0.581 |

三窗口 DWM 的 p95帧间隔中位数为28.90→33.16ms，运行范围分别为28.51～29.18 / 27.72～33.26ms。这个背景计时场景不是满60Hz动画，不能换算为动画掉帧率。

第一组三窗口 Solid 在分析区间记录到三条交换链共308个呈现，其余三窗口运行仅活动搜索框交换链各27个；三个 HWND 的几何回执始终完整。保留这次额外重绘及其资源数据，不将其作为 Acrylic 收益。逐交换链结果保留在JSON中。

FrameTime包含主动节奏和等待。PresentMon CPUBusy也可能包含 Present 之外的事件循环等待，不等于执行中的CPU使用率；DisplayLatency不是本试验的物理输入到显示延迟。不能把静置的约518ms或输入的约68ms呈现间隔称为同等长度的渲染卡顿。

## 限制

- 这是固定几何、单台Windows11/100%DPI、Debug夹具的方向性测量，不是全软件或Release验收。实际滚动未达到60Hz；输入不是物理键盘/IME输入。
- DWM服务整个桌面，含共享缓存、显示适配器和其他桌面工作；三组配对的范围不能替代大样本置信区间，也不能按窗口数线性外推缓存/显存成本。
- 采样及背景绘制的开销高于部分被测差值，未评估无观察器环境下的精确成本。
- 功耗、Windows10、混合DPI、系统透明偏好回退、长时间泄漏和正式产品接入后的性能尚未验证。此次没有打包、安装或修改正式应用主题。
