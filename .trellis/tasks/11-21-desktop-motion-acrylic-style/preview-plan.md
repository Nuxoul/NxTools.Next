# Theme preview delivery

## Boundary

Deliver a browser-viewable whole-app theme study and three finite stageshow stories. The preview owns only synthetic scene state, not product settings or Windows behavior.

Add `docs/ui/theme-preview/` with React scene source, scoped CSS, a copied MIT stageshow kit, a reproducible build entry, and self-contained static output. Keep toolchain installs, gold recordings, browser traces and intermediate captures in session scratch. Add verification evidence and preview links to this task. No product source, vendor, Cargo, native runtime, service or package changes.

## Visual plan

- Base palette: Frappe canvas #303446, lower #292c3c, raised #414559, selection #51576d, text #c6d0f5, supporting text #a5adce. A second independent Graphite palette verifies theme/color separation; both have light counterparts.
- Family: bundled Sarasa UI SC Regular; existing Consolas role for identifiers only. Host title 28/36, UI 13/20, secondary 11/16. Do not change product typography.
- Material: shared blurred desktop backing, translucent shell, more opaque reading/selection layers, one thin contour. Solid theme has the same colors and data with opaque surfaces. No animation in wallpaper.
- Layout: one large workbench, full-height 176px module rail, compact toolbar and recognizable tool tiles or download rows. A smaller supporting window is placed over quiet margin; content and actions stay whole. Compact view is a 358px redesign around the active subject, not a scaled desktop.
- Stories: a search produces three results; pointer intent reveals one clipboard preview; explicit Apply changes all visible windows to the acrylic theme while color/font remain unchanged.
- Controls: theme, color scheme and light/dark are independent host controls. Scene picker + explicit Play/Replay. Reduced-motion preview shows the completed poster, and OS reduced motion is honored.

## Composition review

The requested visual identity is the restrained dark frosted desktop reference, not a marketing dashboard or macOS clone. Keep Windows controls, actual NxTools module names and synthetic product-shaped content. Distinguish hierarchy with material and surface depth rather than equal cards or decorative accents.

Use the stageshow `panel-annotation` and `overlap` composition, and `raycast` only as interaction reference. Record the gold before authoring, then inspect wide and compact payoff stills, complete motion contact sheets, intermediate transitions, host controls and reduced-motion state. Timing is a proposal, not product performance evidence.
