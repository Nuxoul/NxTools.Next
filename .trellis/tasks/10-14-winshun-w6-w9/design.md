# Cross-feature extension design — approved W6–W9

Status: user approved implementation; joint W7/W8/W9 verification is active. Applies to parent R1–R12 and both children. Canonical W6 then joint W7/W8/W9 order; W10 deferred. Source/reference evidence is in research/reference-and-current-owners.md. Contracts below are the approved target; actual implementation and remaining acceptance are recorded in child outcomes/checkpoints, not inferred from this design.

## 1. Modules, interfaces and dependency direction
Create one `nxtools-extensions` Rust workspace crate for manifest/catalog/package identity, validation, trust snapshots, invocation state, ordered resolution, bounded event routing and protocol models. Keep it host-neutral: no GPUI, Windows API, Finder or DownloadEngine dependency. Reuse workspace serde/JSON/UUID/SHA256/URL/error dependencies; no new external interpreter, VM or framework.

- Core configuration composes extension registry/enabled/trust/event/chain settings with existing atomic section save. Extension crate does not depend back on Core or create another AppConfig owner.
- Finder/Desktop Adapters translate declared actions/provider items to existing command preparation/result/native execution. Domain modules do not import GPUI/C# processes or reimplement ranking/storage.
- Download defines a narrow injected `DownloadRequestResolver` interface with cancellation/operation identity and validated resolution/provenance. Default no-op Adapter preserves every old request. Extension composition provides the real Adapter at both GUI and background engine construction. One shared lower acceptance function handles direct submit/enqueue/idempotent/browser paths; requests are resolved before HTTP probe/task persistence/scheduler lock, not in the render/view only.
- Desktop owns one extension application/feature dispatch composition; weak views observe immutable projections and defer cross-entity work. Background download host creates the same catalog/invocation/resolver module without GPUI.
- C# introduces `--extension-host` mode within existing PlatformHost executable, isolated from ordinary EventWindow/serial native command session and from SYSTEM/elevated deployment modes. This demand-started broker manages finite once-per-invocation process trees and Credential Manager operations; no tray/hooks/service registration. Broker existence is not W10 resident plugins: scripts still start/exit per invocation. Rust keeps a bounded current-user authenticated pipe/process lease; GUI/background share this composition inside their already exclusive desktop owner.
- Broker is an Adapter for native execution, not a second feature dispatcher. Full host calls route back to Rust feature Adapters, never raw Windows callbacks from plugin JSON. Demand-start/supervision/disconnect cleanup is documented and tested; no auto-start plugin code at application initialization.

Small external interfaces: import/preview/commit package, approve/revoke content identity, invoke/cancel handler, publish committed event, route typed host call. Each owns validation/pending/terminal ordering internally; callers do not reconstruct process/trust state machines. Adding a new feature Adapter extends the advertised operation registry, not the runtime's process protocol.

## 2. Package and trust storage
Import source: W6 standalone JSON file; W7 local plugin folder containing `extension.json`, manifest-listed scripts/assets and optional package-local executable/dependencies. No ZIP/network installer in this slice. Preview is read/validate only. Snapshot listed code/assets into application-owned per-user `extensions/<id>/<content-hash>`; plugin writable data lives in a separate `extensions-data/<id>` so settings/output do not constantly invalidate code trust. Use bounded staging, sync then publish registry pointer; old version remains selected on any failure. Reject path traversal/absolute package code paths, reparse/symlink traversal, duplicate normalized files/IDs and unsupported required versions. This is trust identity, not a same-user security ACL claim.

Content hash covers normalized manifest including permission/handler/settings declarations and sorted listed executable bytes; it excludes plugin data/secret values. Trust record binds package ID + content hash + chosen interpreter identity/path. Revalidate before invocation and before applying returned results/effects. Changed package code/declarations or executable/interpreter identity needs renewed trust. External module imports outside the staged package cannot be exhaustively monitored; explain full-user trust and no supply-chain guarantee. Manifest authors must list package-local dependencies. No elevated/manual-command flag is inherited by package actions.

Enablement and trust are distinct. Imported content disabled/untrusted; W6 explicit enable confirmation previews actions; scripts require whole-plugin trust first. Revoke disables dispatch, cancels owned runs, invalidates visible results/receipts and chain references. Remove cancels before removing active registry/version pointers; preserve user data unless explicitly removed. Same ID/version update uses preview and explicit replace, no silent overwrite. Keywords conflict with manual commands/other enabled package handlers; block conflicting enablement until alias changed or one disabled. Existing manual command records never flatten into packages.

## 3. Manifest and versioned duplex protocol
`schema_version=1`, stable ID/name/version/source/author, required feature API versions, declared permissions[{id,reason}], files[], handlers[], settings[], runtime(optional). Each handler has ID, kind, feature, entry, title, module scope, bounded match declaration, runtime entry/action descriptor and requested budgets within host caps. Handler kinds: `action`, `provider`, `request`, `event`. Unknown required feature/method/schema rejected; optional namespaced metadata bounded and ignored only where explicitly optional.

Script transport: UTF-8 newline-delimited JSON over stdin/stdout, per-run `protocol_version`, `run_id`, `correlation_id`, generation/feature/handler/content identity and causality context. Initial invoke includes immutable typed context and nonsecret setting snapshot; configured secrets delivered only on requested credential call through pipe/stdin, never argv/env. Python/Node/PowerShell can implement this directly; document tiny wrappers/examples for all four forms rather than requiring SDK installation.

Matching version1 uses normalized schemes, exact/domain-suffix hosts and linear bounded path globs (max32rules/handler,2KiB pattern,32KiB URL); host performs no user regex/backtracking/expression evaluation. Complex dynamic matching belongs in selected handler code returning not_handled, or a future separately versioned matcher. Duplicate JSON object keys are rejected rather than last-wins, including nested manifests/settings.

Frames:
- host→script: `invoke`, `host_result`, `cancel` (cooperative hint), fixed terminal error.
- script→host: `result_batch` (stable item IDs, partial/replace/sequence), `host_call` (call ID, versioned method, typed params), `complete` (handled/not_handled/success/error, typed value).
- Process exit before valid completion = typed failure, not success/empty. Duplicate/late frames cannot re-complete an invocation. Resolver requires one terminal request result; search provider may stream bounded batches. stdout only protocol; stderr bounded user-visible diagnostic tail, never production log output. Reject invalid UTF-8/oversized/malformed/out-of-order frames before growing collections.

Host-call dispatch binds run/trust/feature context; no arbitrary reflective method calls. Unknown operation gives fixed unsupported result. Up to8 in-flight host calls/run, dedup call IDs/side-effect idempotency; no reentrant nested lease or direct synchronous write back. Calls to existing operations use the same validation/correlation/cancel/confirmation rules as native UI. Resource caps and headless operation availability are advertised via `host.describe`; not pretending a permission declaration limits OS access.

## 4. First-release feature API / freedom
| Feature | Registrations | Host operations / outputs |
| --- | --- | --- |
| Downloads | URL resolver, selected-task manual actions; created/completed/failed lifecycle events individually opt-in | validated resolve result (URL, optional filename/headers/Cookie/Referrer/expiry), probe, submit/enqueue, list/get, pause/resume/cancel; returned data from existing DTOs and task IDs |
| Quick Launch | keyword command and explicitly enabled ordinary-query provider, selected-result action | stable search rows and typed open/copy/program/query effects; shared Finder search, current-context query update; no direct MFT/native engine access |
| Clipboard | selected-item/manual content processing, committed-new-content event opt-in | bounded text/file/image-reference snapshot, query/get, create derived history entry, copy replacement text/files through existing C# action; original stays unless user uses existing explicit edit/delete action |
| Tools/common | registered named manual tool actions | open target/program without elevation, copy, nonmodal text notification/result data and request an existing feature operation |

Operations grow via versioned Rust Adapters. Feature-required methods and settings are visible before trust. `clipboard.get`/download request context may contain private content only intentionally delivered to trusted handlers; UI lists this. Huge image/native formats are represented by short-lived owned asset references with bounded read operations, not giant base64 frames. No automatic full-history/header dump to every event handler. Main feature defaults remain intact when no packages are enabled.

Headless availability: download operations/catalog/runtime remain available without windows. Search can return available in-memory/catalog data without opening popup; UI-only query/input effects return `ui_unavailable`. Clipboard capture events require the ordinary running desktop capture owner; background download host does not install another clipboard listener. External scripts may independently access OS under user authority; host API is not a sandbox.

## 5. Download resolver and explicit chains
Default selection: user's per-rule preference first; otherwise declared priority then explicit match specificity. If top candidates tie, reject as a visible conflict rather than arbitrary script choice; UI offers one choice/persisted preference, headless callers receive actionable conflict. Only selected plugin executes. No-match/not_handled preserves original behavior; selected handler failure stops and offers explicit retry/bypass original, never silently attempts all plugins.

Explicit chain stores ordered handler IDs (max8), each enabled/trusted and each stage receives previous validated output plus original URL and causality. Stage `not_handled` passes through unchanged; no URL output is not success. Every returned URL validates HTTP(S)/bounded context before next stage. Whole-chain clock includes queue wait/start/host calls/output/cleanup admission. Repeated normalized changed URL or repeated stage routing produces fixed cycle error; unchanged pass-through is allowed. No automatic rediscovery of a new matching chain after each rewrite. Chain failure stops, trace shows fixed stage/outcome in UI and metadata-only diagnostics. Original/processed URLs are visible in requested UI, not logs.

Flow: original request → ordinary validation/policy → selected/explicit chain resolver → validated effective request → existing probe/confirmation/acceptance/scheduler/HTTP. Preserve save path/category/user-chosen name/schedule/rate/connection/TLS policy; plugin can suggest filename only if user did not supply one. Typed HLS/DASH manifest selection attaches to resolved source under existing media validation; do not arbitrarily rewrite segment/audio/video URLs after selection. Blob import bypasses URL parser.

Original request fingerprint/idempotency is checked before running resolver where a durable receipt already exists, then rechecked under existing scheduler gate before commit. Only unresolved new submissions parse. Effective request/provenance is stored with task under backward-compatible optional fields; old tasks stay valid and never require plugin to resume. Internal opaque resolution receipt binds original request+effective context, resolver content/settings versions, operation/session and expiry, issued by host (never trusted from arbitrary client JSON). Bounded session cache256 receipts, default10-minute validity clamped by plugin shorter expiry. Probe outcome may carry optional receipt/effective request; UI/Browse/CLI submit consumes matching host receipt, no blind second parse. Expired/unavailable receipt before acceptance returns explicit resolution-required retry, no hidden network side effect; callers can explicitly rerun resolution. After task acceptance normal resume/segment requests use effective request and existing ETag/size validators; changing resource requires new resolution/new or explicitly validated task operation, not silent byte concatenation.

Credentials: same-origin caller headers remain subject to existing validation; any origin change drops automatically inherited request headers/Cookie/referrer (conservative, avoids custom credential header leakage), and invalidates prior media context. Trusted plugin may explicitly return new headers/Cookie/Referrer for the final origin, which are bounded/validated as an intentional new context. No Cookie/Authorization merge from old origin. Input private request context supplied only to the chosen declared handler, not unmatched plugins. Host-managed probe/transfer retains current network policy; plugin-owned HTTP is ordinary user networking and not automatically forced through NxTools proxy.

Cancellation is checked before resume, each stage/host effect, before probe publication and before task persistence. No plugin work under scheduler/store lock or GPUI entity lease. Default no-op resolver must preserve exact behavior/results/cost for existing downloads. Share injection at GUI/background construction and all lower submit/probe entry paths; CLI remains pipe caller, never creates engine/DB/plugin owner.

## 6. Committed events, stable rows and loop prevention
Download Adapter subscribes at engine composition, not only DownloadApplication::handle_engine_event, so background completion works. Dispatch only after successful task/state commit/final artifact transition, dedup `(engine generation,task,state transition sequence,handler)` within bounded window. No task-progress ticks. Event handler failure cannot turn completed transfer into failed or close user windows. Primary engine event drain remains independent/nonblocking; private subscription queues have bounded drops and fixed rate-limited error counts.

Clipboard worker gains a bounded post-success commit notification with stable entry ID, format kind and causality; current persist_capture returns only Result<()> and discards capture IDs, so return/reply seam changes are necessary. Failed capture/staging cleanup produces no committed event. Derived-copy/write host calls attach operation origin and existing suppression token; plugins do not synchronously run in ClipboardCaptured callback or while worker DB transaction/GPUI owner is leased.

Causality: root event/operation ID, origin plugin, invoked-handler set and depth(max4). Handler is not invoked twice in the same chain; own output does not feed the same handler; dedup ring<=4096ids. Cannot reliably attribute arbitrary direct external OS writes by trusted scripts; rate/concurrency/debounce/circuit guard also applies and UI explains host-managed loop prevention is not hostile-code containment. Default circuit policy: three repeated failures within one minute pauses that automatic handler until user retries; fixed reason/notification, not a crash/restart storm.

W8 Quick Launch: namespaced `(package,handler,item)` IDs mandatory; keep ordinary Finder ranking, merge plugin lane under explicit bounded quotas (ordinary query3/provider12total, keyword200). Existing local/index provider completion and plugin batches share current session checks without holding ordinary results hostage. Late provider output cannot move selected identity or insert above committed selected row; new rows append below protected selection, same-ID updates in place. Removed selected ID uses nearest remaining existing selection; do not run held Enter automatically. Execution rechecks handler content/trust, generation, selected ID/action before existing native command.

## 7. Proposed resource defaults and native supervision
Defaults are part of final plan review, not immutable claimed measurements:
| Resource | Default / hard cap |
| --- | --- |
| Search provider debounce/deadline |150ms /3s default,10s max |
| Resolver stage / whole chain |10s stage default,30s max;60s whole-chain cap incl queue/start |
| Manual action / event handler |30s default,120s max |
| Concurrency |1 invocation per plugin,4 total; pending queue32; superseding search coalesces |
| Native child count / job aggregate commit |8 processes,512MiB default/1GiB max per job;2GiB total active broker commit budget |
| Per-frame / input / stdout / stderr |256KiB frame,1MiB input,4MiB stdout total,64KiB stderr tail |
| Results / host calls |200 keyword items; ordinary3/provider12total;8 active calls/run;64 calls total/run |
| Import |1MiB manifest,4096 files/256MiB listed bytes;100handlers/100settings/package,256packages |

Broker startup creates its outer kill-on-close Job and assigns its own process before accepting any plugin invocation; failure reports native denial and launches no scripts. Rust keeps the exact broker process/transport lease; broker waits on a SYNCHRONIZE handle to the authenticated parent PID and terminates all jobs on parent death/control EOF. Inner job handles are never inherited. Verify broker and pipe identity/current user/session, not client payload claims. Broker crash closes outer/inner jobs and kills ordinary owned children; no service or machine daemon. Test parent-death, broker-kill and admission ordering with owned fixtures before enablement. If nesting/admission fails, fail closed instead of launching unmanaged or silently relaxing ownership.

C# mode verifies non-elevated same-user token; if host inherited high integrity/SYSTEM fail closed, no automatic token fishing/elevation. Spawn interpreter/EXE directly with explicit argv, CREATE_SUSPENDED + STARTUPINFOEX handle allowlist; only stdin/stdout/stderr inherited, no private pipe/key handles. Create/configure Job with kill-on-close, aggregate job memory and active process count, no breakaway; assign then check child token then resume. Failure terminates suspended child and releases exact-owned resources. Concurrent readers drain stdout/stderr with byte caps; blocked input write/start counts against deadline. Cooperative cancel optional, TerminateJobObject mandatory for timeout/revoke/disconnect; close owned handles and observe job empty before freeing slot. Stuck cleanup stays bounded/unavailable, not false success.

Request contexts exceeding protocol budget fail explicitly or use approved bounded asset references; no truncation pretending complete content. Host clamps requested runtime limits and UI displays actual effective limits. Budget values express resource/lifecycle contracts, not sandbox switches. Broker launch itself uses ordinary process composition; no Rust Windows API owner or competing elevated helper is introduced.

Interpreter resolution uses configured full path or known installed PATH lookup at enable/test; no fetching runtimes. Python unbuffered entry, Node script, PowerShell `-NoLogo -NoProfile -NonInteractive -File` with UTF8 wrapper/protocol setup; no automatic execution-policy bypass. Missing/runtime-policy failure shown clearly. EXE entry within staged package. Structured argv separate from command text; configured nonsecret environment may be passed, tokens/secrets never argv/env.

## 9. Compatibility, rollback and acceptance
Default empty extension config preserves old config/commands/download/Clipboard behavior and no broker/script startup. W6 old config additions default empty; no data migration destructively rewrites manual commands. New download optional resolution fields preserve old tasks/frames via defaults; incompatible required feature versions reject early. No source hash/release trust changes until separately authorized packaging; protected desktop tuple remains atomic.

Failure rollback: imported version staged before registry change; old registry selected on failure. Trust change retires runs before publish; process cleanup has terminal ownership. Resolver failure creates no task, keeps UI input/explicit retry; event failure does not undo domain success. Secret compensation cannot claim complete success when rollback fails. Plugin external effects cannot be rolled back by host.

Acceptance seam matrix: real import/config persistence; real common probe/direct submit/browser/CLI/background caller; actual plugin pipe with synthetic executables and ordinary children; GPUI input/selection/actions/settings; clipboard commit worker; download durable events; injected credential store. Red before implementation at each vertical slice. Full source/static/compiled evidence separate from installed/DPI/user scripts. No external website/production service/Clipboard mutation/installer work in this task.
