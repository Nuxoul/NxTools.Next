## REF-17: one explicit size in the original form

Original `CreateDraft`, `OperationForm`, Core ArchiveSettings and `remember_accepted` own optional `create_volume_size { value:u64, unit:KiB|MiB|GiB }`; missing unit means MiB and absent preference means no split. The existing integer `volume_mib` draft entrance keeps MiB as its default. Opening only hydrates original stable InputState and SelectState entities and does not write config. No compatibility store or background migration is needed.

Preset choices: 不分卷, 自定义,100MiB,700MiB,2GiB,4GiB. Choosing a size explicitly changes intended bytes; choosing 自定义 retains the value. Unit switching is display-only: checked exact division must succeed, otherwise retain the original integer/unit and show why. No fractions, rounding or reinterpretation. Number input uses the original InputState with default floating-point step disabled; one deferred checked-integer Step subscriber owns +/-1. Invalid/overflow/intermediate text stays visible and blocks Submit.

Unit-switch rejection preserves the original parsing/minimum/range reason; exact-divisibility guidance is reserved for valid normalized bytes. Actual preset Select and NumberInput +/- controls must reach the original deferred callbacks with exact bytes, stable input/focus and no outer Submit. Actual Create Submit freezes the same volume_bytes in original JobRecord and PlatformBridge commands, independent of subsequent retained draft changes.

`CreateDraft::options` normalizes checked positive integer×binary multiplier once and returns bytes in its option snapshot; all per-source requests reuse that value. Retain64KiB minimum and existing output-budget upper bound, format/password/level/method/solid validation and native maximum-family/capacity rules. Format switching keeps the split value/unit, revalidates and displays the unsupported reason; the split selector remains reachable so the user can explicitly choose 不分卷. Existing password-clear confirmation and format/name/method ownership remain.

Remember captures original settings baseline plus desired accepted size. Core `merge_create_preferences` changes only leaves differing from that baseline inside the existing `AppConfig::update_section` lock/reread/write. The size pair is one semantic leaf. Unrelated stale create defaults must not overwrite concurrent preferences. Failed persistence does not undo the already accepted operation. No secrets or paths enter preferences.

Data flow: official controls → stable inputs/Select events → deferred local draft synchronization → checked option bytes → original typed ArchiveJobCreate → native ArchiveJobSession/runner → distinct ZIP/7z writer → all-candidate validation/readback → original native per-volume publication/cleanup. No writer checks or source/CRC/auth/readback requirements are removed.

## REF-18: explicit ordinary numbered-file operation

Entry is a new official ListItem tile in original Other Tools grid, named 普通编号文件合并. It opens/reuses one slice-local form through the existing main-window ownership pattern. It never registers an association, auto-detects an archive or executes output. State is local input → inspecting → discovered preview → explicit confirmed running → terminal. Change/reinspect/close/disconnect retires preview and exact pending ownership. A weak view/connection/generation/operation ID guards every deferred result.

Typed `raw_numbered_join` command supports inspect, start, cancel with explicit operation identity. One native per-pipe operation owns bounded metadata and actual work; use the original detached dispatcher and existing BoundedStaOperationRunner rather than a new scheduler. Admission is finite, cancellation is installed before work is observable, and disconnect cancels then waits for actual completion. Control receipts are not physical completion. Long file IO never runs in the serial reader or EventWindow.

Discovery accepts a selected later `.001`-style part, enumerates exact same-directory basename plus numeric suffix and sorts numerically. Require ordinals starting1, no gaps/zero/aliases/ambiguous widths, bounded names/count/aggregate metadata and checked signed-file total. Classic `.z01` is not accepted. Preview displays all discovered names/order/count/total and fresh output location, with visible warning that an unknown final part cannot be proven absent. Start references the exact native frozen preview ID; native re-admission verifies its stored set and actual source objects before any output. No archive decoding or completeness claim.

C# owns original held no-reparse parent/source/output APIs, read-only protected source handles and native error codes. Rust owns operation state/layout/eligibility, GPUI renders. Stream one source at a time with one fixed64KiB transfer buffer and actual bounded reads/writes; retain metadata only. Recheck source identity/length/version at the appropriate open/close boundaries. Fresh no-replace output cannot alias sources or an existing destination. Do not add content hashes, second scans, deletion of parts, manifest/fingerprint files or candidate verification for raw bytes.

Failure/cancel closes actual handles then deletes only this attempt's incomplete owned output. Success stays success on late cancellation; cleanup/native errors remain explicit. A terminal is emitted only after real worker/handle completion, and a hung operation retains its admission slot. Source changes/output conflicts/IO failures do not authorize overwrite or replay.

Native preview retains at most1024 names and metadata-only `ArchiveSourceLease.ReadmissionIdentity` values inside the original pipe session; Start references that exact preview ID rather than accepting client-supplied source versions. Inspect and Start are cancellable bounded operations. Re-enumeration compares family names and native versions without reading content; admitted read-only source leases stay held until actual completion. Use `ArchiveOutputSession.Prepare` with an existing parent, `BeginExtractedFile(overwrite:false)`, Write and Commit/Cancel: direct final-name ownership, no candidate hash/rename/readback. Total length is checked against this output owner's32GiB per-file limit; transfer uses one64KiB buffer. The existing BoundedStaOperationRunner waits without an outer timeout/cancel return while the operation checks its own token, so cancellation never releases the slot before actual worker/handle completion. The original router reserves one same-connection cancellation and retains the long command until its terminal result; the original Desktop notification forwarder remains the sole receiver.

## Diagnostics

REF-17 retains original form/job correlation and existing accepted/start/creation phase/native terminal diagnostics. Size preferences use original bounded save events. REF-18 defines correlated accepted, inspecting/preview-ready, started, cancelling and terminal with elapsed/bytes/cleanup and C#-owned native code; progress is coalesced state, not chunk logs.
