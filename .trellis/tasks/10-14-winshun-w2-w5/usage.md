# W2–W5 usage and acceptance boundary

- W2: type an ordinary Chinese name, e.g. 年度报高. Only if normal merged results are empty, a bounded homophone fallback may find 年度报告. Subtitle explicitly says 同音近似匹配 and retains the target path. Local ordinary applications/commands complete before the indexed request; a local hit disables indexed approximation but not ordinary indexed search. Explicit/excluded/path/drive/parent filters stay parsed and unchanged; no pronunciation rewrite of negative/exact terms. Normal result scores and ranking are retained.
- W3: ordinary Quick Launch index requests opt into separate bounded file/directory candidate retention. Final Finder ranking remains authoritative (no added folder bonus or forced low-relevance folder quota). File dialogs remain default-off. Candidate work may be higher than before because two existing kind-filtered searches run; this is correctness, not a measured speedup.
- W4: enter `recent:` in Quick Launch; add an optional ordinary name filter after it, e.g. `recent: report`. Lists indexed files by true last-write time, limits folder/project representation and suppresses reviewed scratch/build/cache descendants only in this view. Normal search still finds them. Recent-directory visit history/button is separate and unchanged. Unknown/nonpositive/future modification times are not fabricated. The launcher explicitly opts into this mode; the same prefix in file-dialog search retains ordinary query semantics and a terminal ordinary batch.
- W5: while a new query is pending, Enter/number shortcut/pointer/action-mode requests cannot execute the retained old rows. Wait for current results, then activate again. No automatic held execution. Deferred primary action is rechecked against open state, query generation/input and selected target identity. Action-mode execution also rechecks mode ID, menu level and selected typed action, including Shell session/command identity; input changes, close/reopen or replacement actions cancel old deferred work. IME confirmation gate unchanged.

## W4 production data migration

Old caches contain unknown timestamps for unchanged files. This source implementation does not automatically rescan or backfill them on desktop reconnect; a legitimate index rebuild is required to populate them. New/recently changed files hydrate accurate last-write through existing MFT worker and bounded USN maintenance. No rebuild, volume scan or service operation was executed here.

Timestamp data is already persisted in the version3 mapped base/delta format; source tests confirm recent results after mapping/delta reload. Initial rebuild now performs attribute-only OpenFileById/FileBasicInfo for records on the snapshot worker; no query filesystem IO. Cost of this initial metadata ingestion is unmeasured. Production scan API still has no external cancellation token; cooperative injected seam tests do not claim native scan cancellation.

Runtime USN time reads are deduplicated and capped256uniqueIDs per poll. Deferred cursor remains at the first unprocessed record; stale last-write isn't replaced by journal event time. Recent classifier marker memory/depth/candidate work is bounded; overflow extra cached reads have1Mwork budget. Over-budget returns current-generation SearchFailed, not a false empty success; UI requests a narrower query/retry.

Source/synthetic pass does not certify packaged LocalSystem startup/restart/base+delta, real search/idleCPU, native first-index latency, installed keys/pointer/IME, highDPI or visuals. Those remain separate authorized release checks. This task does not build/install a package, mutate user history or implement W6–W10 plugins.
