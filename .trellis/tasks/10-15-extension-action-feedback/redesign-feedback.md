# Invocation feedback correction

## Selection contract (before implementation)
- Mission: show the current invocation outcome and next safe action, not a wall of runtime metadata. Use the existing bounded ManualRun ledger, original host-confirmed item IDs, weak ClipboardOrigin/session/window and deferred cancellation/navigation.
- Shape: official Dialog with a single observing entity inside public Dialog.content; that entity owns both one shrinking scroll body and a nonshrinking DialogFooter. A body-only observer with an independently captured footer is rejected because terminal actions must repaint together. Recent activity uses compact, wrapping rows on the same ledger, not a second controller.
- Exact source reviewed: published gpui-component0.7.1 `dialog/dialog.rs::{Dialog::content,title,footer,render}`, `content.rs::DialogContent`, `header.rs::DialogHeader`, `title.rs::DialogTitle`, `footer.rs::{DialogFooter,DialogClose::trigger,DialogAction}`, `button/button.rs::{Button::outline,Sizable::with_size,prepare_for_toolbar}`, `alert.rs::Alert::{new,success,warning,error}`, `accordion.rs::{Accordion::item,on_toggle_click,AccordionItem::open}`. Component/current table and full locked index reviewed.
- Adopt Dialog.title (official DialogTitle) and public content slot; DialogHeader reviewed but no duplicated heading required. Adopt DialogFooter and DialogClose::trigger with actual outlined Medium32 Buttons. DialogAction dispatches Confirm and is intentionally NOT a cancellation/result-navigation wrapper. No Toolbar.child: it would force ghost+compact. Alert separates host-confirmed history evidence from plain, explicitly plugin-provided explanation. Accordion is only for secondary safety/details, never the outcome or critical actions.
- Reuse Kit Default Light/Dark semantic foreground/muted/status/border, existing CJK typography and text_sm; 4/8/12/16px rhythm, theme-owned control radius/focus/hover/press. No new palette, motion dependency, timers or idle animation. Official disclosure/motion remains reduced-motion-aware; no custom motion.
- Do: wrap identity once, distinguish plugin-reported success from host save, keep Close presentation-only, bound result navigation even at64 IDs, defer cross-owner writes. Don't: raw package-ID wall, duplicate name/status tables, blind Retry, automatic copy/show/re-execution or promises about unrecorded automatic events.
- Assumption: multiple saved IDs use a bounded pinned result selector (previous/next + View Result with the original indexed ID) rather than up to64 footer buttons. A stale/closed origin leaves result viewing disabled with an explicit explanation; it never creates a new window.

## Acceptance and verification
Implementation details, regression names and verification limits will be recorded after the source changes. Cargo/build/product launch and real plugin/native clipboard operations are explicitly parent-owned/forbidden in this slice.
