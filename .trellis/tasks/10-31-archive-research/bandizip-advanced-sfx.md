## SFX creation, embedded configuration and shipped-stub consumption

The format index `2` selects the ZIP-compatible SFX writer; `0x14016ceb0` selects `bdzsfx.x86.sfx` if no explicit prefix was supplied. For new SFX outputs, the coordinator `0x14013d910` inserts `; Bandizip sfx settings\r\n` and localized `[LANG]` strings into descriptor `+0x30` **only when that field is empty**. The parent form SFX-settings command (`0x520`) calls `0x1400f9790`: it opens modal template `0xcc` (`CSfxSettingDlg`), copies `CArchiveDlg+0x140..+0x164` into the child, and copies the four strings and two booleans **back only on OK**; Cancel leaves them unchanged. The GUI submission owner `0x140144390` constructs the same `CArchiveDlg`, runs its modal form, and **only on modal result 1** calls `0x140144480` with that same form object. This routine invokes `0x140142e10` on form `+0x140`: nonempty `TARGET`, `TITLE`, `RUN` (quoted when necessary), `MESSAGE` (escaped/quoted), `AUTOCLOSE` and `RUNASADMIN` become `KEY=VALUE` lines. The settings owner `0x140164e40/0x14016a570` names fields `sfxTarget/sfxTitle/sfxRun/sfxMessage/sfxAutoClose/sfxRunAsAdmin` at `+0x580..+0x5a4`. The accepted GUI form and the six-field serialization are connected: `0x140144480` appends the localized language block from `0x140123530` to the custom settings, then copies the combined text into descriptor `+0x30`. The coordinator supplies a default header plus language block only when that descriptor field is still empty.

The options setter retains supplied archive comment at compressor `+0xa0`; ZIP `0x180065a70 → 0x1800666b0` includes comment in central-directory/EOCD material. Output `0x18001f510` first copies the shipped PE stub, then writes `BANDIZIPSFX` and ZIP bytes. The x86 stub opens its own file at initial window `0x00417a45`, locates the embedded PE overlay/ZIP through `0x00409755`, reads archive comment into `DAT_00452ea0` with `0x00401aba`, and parses `[CONFIG]` through `0x004147c2 → 0x004023e8`. It applies title, target and `[LANG]` strings. Automatic entry `0x004188fa` checks elevation and can relaunch itself through `0x0040114a → ShellExecuteExW` with `runas`; ordinary entry shows destination/overwrite UI. Timer `0x00418871` sends Extract for `/auto`. Extract command `0x00418017` handles password admission, destination/overwrite and `0x0040b234` extraction; only a successful result reaches nonempty RUN `0x00414cde` or completion/autoclose. Missing/corrupt embedded data has a separate error/close path.

RUN helper `0x00414cde` sets the extracted destination as current directory and tries the configured command through dynamically resolved `CreateProcessW`. On failure it splits command/arguments with `CommandLineToArgvW` and attempts dynamically resolved `ShellExecuteW` with verb `open`. Its void return does not turn a failed launch into extraction failure. The [active-cancellation trace](bandizip-sfx-cancellation.md) connects message pumping, the dialog cancel flag, extractor result `0xa0000017`, current-output close and re-enabled terminal controls. Delete-on-cancel is a distinct context policy initialized to zero; partial-path deletion is not established.

## Failure, cancellation and limitations

Format gating rejects unsupported method/password combinations before write (`0xa0000403`) and unsupported 7z methods (`0xa0000019`). The inspected TAR data writer `0x180065010` reports cancellation (`0xa0000017`), output failure (`0xa0000030`) and source-read failure (`0xa0000102`) through distinct paths. GUI form Cancel leaves the six-field settings unchanged, and canceling the parent modal form does not call the create coordinator; worker stop/join and optional post-create test are separate stages recorded in `bandizip-create-edit-repair.md:68-77`. Active SFX cancellation terminates selected extraction, suppresses RUN/completion/autoclose and restores enabled controls with Cancel relabelled Close; current-output deletion and rollback of completed members are not guaranteed. No Bandizip, Arkview, Amsiman, SFX stub, GUI or archive was executed. No registry, personal settings, credentials or user logs were read, and no product/build artifacts changed. The record establishes shipped-code mechanisms, not an end-to-end SFX runtime result or license/edition coverage.
