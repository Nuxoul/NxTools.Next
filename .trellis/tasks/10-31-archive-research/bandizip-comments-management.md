## ZIP comment: reader → dialog → edit plan → writer → replacement → refreshed browser

- **Show and prefill.** On successful source open, `0x1401579a0` calls `0x1401584c0`, which builds the tree and list from the opened reader and invokes its virtual `+0x178` to obtain the decoded archive-comment string. If absent it hides/clears the comment presentation; otherwise `0x1401a43d0` places the string in the pane's HWND with `SetWindowTextW` (or the alternate pane backing control). On close `0x140157560` clears that HWND and the catalog. This is archive-level comment, distinct from member comments/column settings. [M01–M04]
- **Edit dialog.** File/Edit command `0x80c7` enters `0x140152940`; `0x140154360` first refuses non-editable opened archives (ordinary ZIP only, excluding split/SFX/broken as detailed in the existing creation report). It seeds `CEditCommentDlg` from the same reader virtual `+0x178` and opens owner-bound modal dialog `0xce`. `0x14010e7d0` handles OK: read UTF-8 checkbox `0x40c`, save its state to settings `+0x608`, read multiline text control `0x494`, then `EndDialog(...,1)`. Cancel `EndDialog(...,2)` does not call the edit owner; only modal return 1 invokes `0x140152bd0`. Settings state is committed on OK *before* compressor result, not after successful replacement. [M05–M07]
- **Load TXT.** Command ID 4 in the same dialog opens owner-bound `GetOpenFileNameW`, with `TXT` filter, title `TEXT_SELECT_TEXT_FILE`, and flags `0x1804`; a cancelled chooser releases its file buffer and leaves the editing text alone. After selection `0x14004b2c0 → 0x14004b4b0` opens and decodes the text (including UTF-8 BOM/no-BOM and UTF-16 branches), with typed open/read/convert results; open failure reports `TEXT_ARKERR_CANT_OPEN_FILE`, success sets the edit HWND text. Reading a TXT changes dialog text, not the archive until OK. [M07–M09a]
- **Compression handoff.** `0x140152bd0` creates `.temp`, gets the compressor, requires the reader's update/import interface `+0x70`, fills options with `0x14016cd60`, imports the current ZIP and submits descriptor action `0x0d` to `0x14013be50`. On an empty new text it marks the empty-comment condition, rather than treating it as a cancelled edit. `0x14013be50` retains an explicit edited comment or obtains the original reader comment for other edits; it builds the same archive-progress worker used by ZIP updates. `0x14016cd60` maps settings `+0x608` to compressor options `+0x40`, copied by `ark!0x18001fd80` to compressor `+0xb0`. `ark!0x18001ee20` receives the new UTF-16 comment as its third argument: non-UTF8 uses configured code-page conversion, the UTF8-selected branch converts with CP65001 and adds EF BB BF, caps resulting comment bytes at `0x8000`, then dispatches ZIP writer `0x180065a70`. ZIP directory/end writer `0x1800666b0` writes EOCD signature `0x06054b50`, the byte count and comment bytes. Empty comment yields a zero-length EOCD comment. The UTF-8 selection affects archive encoding, not the TXT chooser's file-write semantics. [M06,M10–M14]
- **Result and cleanup.** If the compression/edit coordinator signals failure, `0x140152bd0` deletes its `.temp` output and does not replace the source. Only its success path enters `0x140154650`, which performs temporary reopen/configured test before the original→backup and temp→original moves, attempts restoration if the second move fails, then reopens original and refreshes tree/list/comment/location through `0x1401579a0 → 0x1401584c0`; backup cleanup is distinct. The [nested-writeback report](bandizip-nested-writeback.md) records the full replacement boundary. A successful encoder is not a successful replacement. [M06,M01,M02,R1]

### Shell result contract

`0x14002e820` returns true when it invoked `SHFileOperationW` and the call returned zero. It records an optional numeric result but does not inspect `SHFILEOPSTRUCTW.fAnyOperationsAborted`. Microsoft's API contract requires that flag as well as the return value to establish completion; the Shell may return zero after cancellation. Its documented legacy codes identify `0x71` as `DE_SAMEFILE`, `0x75` as `DE_OPCANCELLED` and `0x78` as `DE_ACCESSDENIEDSRC`. These are Shell result codes, not `GetLastError` values. The Save As special case therefore reopens the existing same-file target, while wrapper acceptance is weaker than independently confirmed copy/delete completion. This is a static result-handling finding, not an observed failed copy or deletion. [M19,M20,A1]

## Limitations

1. **Directory-member details:** the connected [new-folder trace](bandizip-folder-commit.md) establishes commit/cancel, directory planning, ZIP output and publication. Exact encoded separator/external-attribute bytes and visible native label-edit behavior remain unverified.
2. **Save As runtime outcomes:** successful native copying, Shell cancellation/error presentation and successful browser readmission remain separate acceptance boundaries. Static code establishes the same-file special case and the unchecked aborted flag, not the result of a live operation.
3. **Window launches:** exact child argument parsing, UAC refusal presentation, activation/focus and launched HWND cleanup remain unconnected. The two commands do invoke separate normal/elevated Shell entry points.

No target executable, archive, installed setting, registry value, service, product code or build artifact was run or changed. Source-delete-after-compress is a separate earlier traced completion path; this report's delete commands target the entire currently opened archive.
