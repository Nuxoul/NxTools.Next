| Header sorting [B4,B5,B6] | List sorting owner `FUN_1401a6c20` maps *visible header position* through enabled column flags `settings+0x434..+0x45c` to semantic column `list+0x54`; clicking the same column flips `list+0x58` descending, changing column resets to ascending. It changes header direction indicators with `HDM_GETITEMW/HDM_SETITEMW (0x120b/0x120c)` and invokes `LVM_SORTITEMS (0x1030)` with comparator `FUN_1401a6da0`. Comparator keeps folders before files, compares name/extension and metadata fields including compressed and original size, and reverses applicable comparisons for descending. `settings+0x184/+0x188` are persisted sort values; this trace does **not** demonstrate exactly when those settings are copied back after a click or every comparator tie-break. |

| Window snapping setting → effect [B1,B8,B18,B19] | Backend `useSnap2` reads/writes setting `+0x194`; at main-window creation, `FUN_140145640` tests the value and calls `FUN_140082a90` with the window HWND, which subclasses its WndProc. `FUN_140082ff0` handles enter/exit size-move (`0x231/0x232`), enumerates neighboring windows/monitors, adjusts `WM_WINDOWPOSCHANGING (0x46)` via `FUN_140083430`, forwards other messages to the prior proc, and unhooks on destruction. This establishes connected native window-message behavior, not just a setting field. Settings-dialog checkbox→state update and immediate enable/disable of an already-created window were not inspected. |

## Shell DLL: special verbs and preview, separate target

| Surface and evidence | Connected behavior / boundary |
| --- | --- |
| Admission and invocation [S1,S2] | Existing `IShellExtInit` CF_HDROP selection and `InvokeCommand → FUN_180016d1c` apply to these verbs too. `FUN_180019398` validates a numeric verb index and dispatches the retained verb ID; invalid indices/string verbs return `0x80070057`. Full command length >2000 uses the existing `/usemmf` path. This reference does not repeat the ordinary extract/smart-destination path. |
| Compress and email [S3,S4] | DLL `0xbbd` builds `c -email` with the normal ZIP destination and selected sources. The [delivery trace](bandizip-shell-delivery.md) joins EXE parsing to descriptor `+0xdc`, CLI receiver `FUN_140159f90`, create coordinator and one-attachment ANSI `MAPISendMail` request for compose UI. Handoff is not gated on successful creation; ANSI conversion uses insufficient declared capacity and ignores its return, and the MAPI result is discarded by the caller. The ordinary output archive is retained, not a mail temp file. Actual client acceptance/transmission remains unobserved. |
| Custom output name/date rule [S4,S5,S6,S7] | The DLL expands `${NAME}`/`${EXT}` and date fields, sanitizes invalid filename characters, uses `.zip` for an empty expansion and retains the result at `owner+0xad8`. Menu command `0xbc9` reads that field, joins it with base `+0xa70` and passes it as the EXE's output descriptor `+0x08`; the coordinator uses it for the actual create task. This [selection→destination chain](bandizip-shell-delivery.md) is distinct from menu text alone; ordinary creation/overwrite/collision outcomes retain their existing owners. |
| Preview and tree preview [S4,S8,S9,S10] | Recognition `FUN_180014540` precedes owner-draw preview admission; flat/tree painter `FUN_18001e5f0` consumes retained Ark catalog records and distinguishes loading/encrypted/unreadable/empty/timeout/broken/loader results. The [worker/lifetime trace](bandizip-shell-preview.md) joins native worker start, Ark loading/open/enumeration and 200-ms menu publication. Effective `shell_PreviewSize` is `[1,20]` non-directory members in flat mode; tree mode bypasses that setting, while both have a 700-file stop threshold. Deadline is a per-member callback test at elapsed >2000ms, not a watchdog. Owner cleanup requests cancellation, waits 30seconds and can forcibly terminate; ordinary completion loses its stored thread handle without closing it. Exact popup-close→COM-release timing and publication-timer retirement remain unresolved. |
