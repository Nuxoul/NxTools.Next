## Implications and limitations

The reference architecture is a single batch parent, one active archive worker at a time, queued UI-owned decision dialogs with explicit worker responses, persistent apply-all choices, and a progress owner which may remain visible after the worker finishes. Model pause/stop as worker control and join rather than closing the window first; keep item failure distinct from explicit batch cancellation. The native reader confirms the archive-open-error continuation, but complete decoder-internal per-file error policy, exact output rollback on cancellation, and **compression each-input-to-its-own-archive** behavior are outside this extraction coordinator. The modeless progress creation call returns its result without an explicit local message loop; avoid inferring every possible ownership/visibility interleaving from this static call chain alone. Static reconstructed calls are not a runtime observation.
