# Source-delete qualification / protected recycle foundation

Canonical phase: **Phase A — Engine contracts and safety foundation**. Two independent foundation
defects repaired in [repair evidence](source-deletion-remediation.md);native/PhaseA/A–F not accepted.

## Change boundary and approved seams

The gap is lifecycle-derived qualification and a once-only, operation-bound native authorization
seam. Rust owns facts, fixed refusal reasons and finite source IDs; C# owns the original captured
objects, their Windows leases and the independent per-source recycle result. Tests drive actual
ArchiveEngine extraction and actual C# Start/Job/Rust/native output, then the production
qualification/authorization path with a recording backend. A fake result is not Shell acceptance.
No UI, product queue, launch routing, public PlatformCommand, ZIP editing, Explorer integration,
output-publication/TOCTOU redesign, dependency upgrade, package or install work.

Expected files: Rust control/source_deletion/engine and existing worker completion boundaries;
creation plan remembers original roots; worker private request/result only; C# runner/source
capabilities plus a dedicated authorization/execution owner; focused Rust/C# fixture registration;
reference/owner/task evidence. No unrelated refactoring or reset of dirty user work.

## Qualification rules

- Consent is explicit per original job, absent/legacy means no backend call. It is not settings.
- Full extraction only, all expected files and directories complete, zero skip/link/special,
  successful decode/integrity/metadata/MOTW/final directory completion/source recheck. Test-only
  never qualifies. Selected-only remains ineligible even if its selected IDs cover every entry.
- Creation requires actual acknowledged final publication after full held-partial readback,
  structural/decode/hash verification and original source revalidation. Encoder finish alone,
  partial commits, postcommit failures, uncertain publication and cancellation do not qualify.
- The original root set, not archive-relative names, defines authority. This foundation refuses
  **every directory source** as directory_coverage_unproven (and actual exclusions explicitly as
  members_excluded). This is conservative refusal, not a change to delete-source product meaning.
  It does not substitute deletion of individual archived descendants for a whole original root.
- Default Thumbs.db/desktop.ini exclusions are retained user data. Strip-root, empty-tree or
  successful planned-entry traversal cannot authorize recursive deletion. Existing bounded
  optimistic traversal is not an atomic snapshot; later directory members cannot be discarded.
- Only bounded original regular-file roots can produce candidates. C# must verify exact issued
  IDs against its original operation/source set, full object identity/version, source/output
  alias/ancestor rejection and active browser-temp provenance. No worker paths/parents/recursive
  flag are delete authority.

## Execution, retry and outcome rules

No permanent deletion or fallback exists in this seam. Retain the original source protections;
never treat check-ID -> close lease -> path Shell delete as proven object binding. Production
native execution stays refused until an approved implementable protection contract is established.
A recording backend may be injected only through the internal isolated test construction.
Qualification/acceptance/start/in-flight/terminal are separate; one token can be consumed once.
Duplicate/concurrent/cross-job/late requests cannot redispatch. Cancellation before start has no
backend calls; after start cannot pretend the operation was interrupted. Missing acknowledgement
or backend exception after dispatch is OutcomeUnknown, never a retry opportunity. Per-source
Recycled/Cancelled/Unsupported/Failed/OutcomeUnknown/NotAttempted remain distinct, with real native
codes only when supplied by their owning boundary. Partial results do not overwrite archive
success, committed count/state, output or cleanup facts. State/result storage and workers are finite.

Repair invariants: original private Run captures session+source capabilities at source_acquire;
only its completion owner qualifies/executes/retires. No static factory taking worker JSON,
caller success/request clone/new lease;request-reference weak keys are not authority. Observable
attempt cannot start backend;actual execution remains owner-only and awaited before retirement.
Rust begin produces private lifecycle identity;every completion matches it or is discarded.
Later open/test/extract(begin even on failure) invalidates older finish;consumed remains operation-wide.

## Diagnostics

One original operation correlation spans qualification, execution accepted/start, bounded state,
per-source aggregate counts, terminal/elapsed/native code. Fixed reasons only, no source path/name,
contents, password, output path or capability token. Coalesce source outcomes in one bounded batch,
not per-byte/member logs. Diagnostic sink failure is observational only. Existing archive terminal
and independent recycle result must not be conflated.
