# HZ5 schema1 implementation contract

Public `ArchiveJobExtract.reclamation` and private `extract_options.reclamation` are optional objects `{ "mode": "start" | "continue", "recovery_id": UUID }`. Absence is ordinary extraction. A nonnil recovery ID is mandatory. Reclamation requires a full extract, `strategy: here`, `conflict: ask`, `single_file_folder:false`, no selection, no readmission, no DeleteSource and no confirmed overwrite. Destination is explicit and fixed. Continue is a fresh Start command with mode `continue`, not live Resume. The native C# validator and Rust validator enforce the same shape. Start and continue use the existing queue and runner.

## Private native calls

Reuse `NativeCall` and `NativeReply`; no new top-level fields. Data is UTF-8 JSON encoded as the existing bounded byte array, at most65536bytes. JSON replies use `read_data` directly; only `hz5_read` uses base64. All actions are refused outside the admitted mode. Source acquisition still returns the existing `{path,volume_paths}` object. Typed native refusal codes start with `reclamation_` and remain available to original Job failure diagnostics.

- `hz5_info`: no body. Reply JSON `{schema:1,recovery_id,cluster_bytes,journal_bytes,source_identity,root_identity}`. Native identities bind immutable volume/full file ID/length, not old source mtime/digest. For Start, this admits geometry/root only; the first qualified `hz5_plan_entry` creates the companion, not a source marker. `cluster_bytes` is the actual release quantum: the larger of the NTFS volume cluster and64KiB sparse deallocation unit. Continue opens the existing matching marker/companion and validates their identities.
- `hz5_read`: offset/length, maximum65536; returns base64 bytes from the held journal. Read-only and bounded to observed journal length.
- `hz5_plan_entry`: JSON `PlanEntry` below. Start only; contiguous index, no duplicate paths/extents. Append/flush/readback before ack. At most4096 entries.
- `hz5_seal`: JSON `{count:N,structure:BASE64}`. `structure` contains only retained ZIP structure bytes (headers/descriptors/central/end), not payload. Native persists it opaquely; Rust compares it on recovery. Size must fit the64KiB call; larger retained structures are explicitly refused. Native checks the complete plan's target namespace and source-object overlap before any output, then persists sealed and binds/flushes/readbacks the source ADS marker before acknowledgment. Existing target files or source aliases refuse without consuming source data or marking an unsealed original. No output/punch before this boundary; a created but unsealed companion grants no source-mutation authority.
- `hz5_select`: body `{index:N}`. Binds the original output owner to this planned unit, requiring its exact path/size. Original `begin` automatically logs native partial identity before returning; metadata and `commit` remain in the original output transaction. A durable ready record containing native identity/fingerprint/metadata/MOTW is written before the single publication. Final verification retains a read handle without write/delete sharing.
- `hz5_observe`: body `{index:N}`. Native validates/reopens the exact recorded objects and required content/metadata/MOTW. Reply JSON `{status:"absent"|"published"|"applied",released_bytes:U64}`. A recorded ready partial can be published through the original owner; an incomplete partial is an explicit preserving refusal, never arbitrary path cleanup. Applied outputs must be reverified before any next release. Pending must be reconciled against actual allocation. This call does not itself punch or approve a new pending record.
- `hz5_pending`: body `{index:N}`. Native requires an exact verified retained published output, captures source allocation/free-space observations and appends durable pending authority for the plan's exact interval. Zero-length intervals still advance through pending/applied without a sparse mutation.
- `hz5_apply`: body `{index:N}`. Requires that exact durable pending record and retained verified output. Recheck cancellation, exact source identity and approved range; set sparse/punch/flush/query actual allocation and volume free space, append applied observation. If applied logging fails retain pending. Idempotent pending reconciliation observes already-unallocated ranges and avoids double counting. Reply JSON `{released_bytes:U64}` is the held source's net allocated-byte reduction from pending to applied, including first sparse-conversion tail allocation overhead; it cannot exceed the released interval allocation. Interval/source allocation and free-space observations are also retained. Nominal hole length is not reported as reclaimed space.
- `hz5_complete`: no body. Require all units applied, append `completed_consumed`, retain marker, companion and published outputs.

`PlanEntry`: `{index:u32,ordinal:u64,path:String,header_start:u64,payload_start:u64,payload_end:u64,record_end:u64,release_start:u64,release_end:u64,size:u64,crc32:u32,metadata:OutputMetadata}`. `path` is the fixed original safe relative output path. All entries in this wire plan are regular files; ordinary explicit directories are represented by retained source structure and the existing Rust extraction plan. Empty files are valid with a zero-length release. Directories are created/finalized through the original output owner. Stored size equals payload length.
Zero-length release intervals use the canonical `release_start = release_end = 0`. They authorize no source mutation. A whole plan without a nonzero interval is refused.

## Persistent framing and records

One stable companion, append-only, maximum32MiB. Each record is `u32LE(payload_len) + UTF8_JSON + u32LE(payload_len)`, payload maximum65536. JSON envelope is `{schema:1,sequence:U64,kind:String,value:Object}`. Sequence starts at1, strictly contiguous. Flush and exact full-frame readback precede acknowledgment. A torn final append is not an acknowledged record; preserve all complete earlier frames. No complete corrupt frame/invalid transition is ignored. No checksum inventory or journal replacement.

Kinds: `header` (native identities/mode/recovery ID), `plan_entry` (`PlanEntry`), `sealed` (`count,structure`), `partial` (at least `index` plus native facts), `ready` (at least `index` plus native receipt), `pending` (at least `index` and preallocation facts), `applied` (at least `index,released_bytes` plus native observations), `completed_consumed` (terminal). Native may record additional receipt facts inside value; Rust requires the fields used for transition decisions and preserves unknown receipt fields. No unknown record kinds. A single unit may be current; index advances only on applied. A repeated applied call returns recorded observation rather than appending a duplicate. Rust compares every plan entry and sealed structure with a newly qualified retained ZIP plan before continuation; it validates all prior outputs with `hz5_observe` before selecting an unfinished unit.

Diagnostics use original operation/correlation plus recovery ID and bounded stage/sequence/allocation facts; never raw records, paths, member contents or private tokens. Process fault hooks stay Debug-only. No Release package or power-loss acceptance is implied.
