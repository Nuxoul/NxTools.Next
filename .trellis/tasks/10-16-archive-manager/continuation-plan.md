## Design boundaries

### Original owner reuse and diagnostics

Rust owns typed edit/reclaim/batch state, logical job/attempt/source generation and scheduling; GPUI only renders original entities; C# owns Windows held paths/processes/COM/native source mutation. Native handles/capabilities remain opaque, command/session/generation-bound and bounded. Install pending before dispatch; cross-entity work next turn, cache-hit included. One bounded queue and one OLE loop, detached serial pipe reader; timeout/cancel does not release actually blocked native slots. Correlated accepted/start/state/terminal/elapsed/native errors, no archive paths/member content/passwords/headers/cookies/identity tokens in diagnostics; no per-byte/frame/pointer logging.

### Drag and result location

Trace actual GetData/FileContents vs worker materialization vs Explorer stream read. Do not start OLE after async extraction/mouse-up, move all work into a competing drag framework, or claim selected cache output is final target publication. If async IDataObject capability is needed, verify actual SDK and implement complete Start/End/COM reference/lease/abort lifecycle before advertising it; Task.Run/early success alone does not fix synchronous consumer blocking. No modal password UI in GetData; preserve explicit unlock+fresh gesture and current budgets. Never reclaim a source used by live drag/preview/browser/read/modify leases.

### Multi-format edit route

Read [local-source review](../../../docs/reference-code/archive-editing.md) plus exact pinned sources first. bit7z/NanaZip provide update intent/index/newprops/newdata/subtree semantics; Ark provides stream rewrite/filter handling. Do not copy PeaZip delete-destination-then-rn, 7-Zip/NanaZip delete-old-before-move, conditional bit7z MinGW replacement or Ark unchecked close/commit. C# existing verified candidate/recheck/native publication wins; existing accepted final TOCTOU limits remain explicit, not claimed ID-CAS. RAR write excluded unless a separately approved external-tool/license design; no automatic WinRAR dependency. Existing split/SFX/signed application/unknown unsafe structure editing stays refused.

### Crash/recovery and HZ5 authority

Persist bounded operation/mode/schema/source-volume/fullID/output IDs, mutation frontier and tail/decoder state where necessary. CRC is not authority; source hashes necessarily evolve under approved mutation and cannot validate themselves using an untrusted journal. Held all-volume ownership, output/source overlap and hardlink exclusion, no arbitrary path reopening or journal-directed recursive deletion. Missing/corrupt/newer journal refuses and preserves evidence. Recovery must offer truthful inspect/resume/restore-remaining/discard choices only where implemented; source may no longer be generally openable, restore usually cannot restore full original and some midstream states cannot produce a standard remaining archive. Passwords never persisted.

Mandatory ordering: real output publication + identity/content/metadata/MOTW verification/readback → durable checkpoint replacement → exact approved source cut/punch → terminal/cleanup. Ambiguous output/native commit/flush/password/corruption never authorizes next cut. After source punch, indispensable partial/output/history is NOT disposable temp; no retry from byte0, no old readmission reset. Native source mutation is a new narrow capability, not widening ArchiveSourceLease sharing, an arbitrary FileStream path, DeleteSource or Recycle Bin fallback. Block/suspend conflicting leases first. Keep-mode/ordinary extraction remains byte-preserving at every crash hook; mode cannot be changed by omitted flags on restart.

Initial recommendation is whole completed Stored-ZIP file units; no arbitrary source punch while codec reads. Source/output must share actual verified volume where savings are claimed. Deflate resume needs valid block/bit boundary+32KiB history+CRC+retained restart byte; solid7z requires full block, no mid-block promise; solid RAR destructive mode excluded, encrypted/header-encrypted/links/split/compressed streams unqualified until separate proof. No automatic destructive fallback when disk is low, no 2GB reference reserve copied, no default change to HZ1 reserve0/budgets. Windows directory-sync no-op reference is not durability proof. Process abort tests do not certify power-cut survival; VM/filesystem acceptance is separate.

## Product decisions still requiring confirmation

1. HZ5 first accepted matrix: recommend unencrypted single-volume Stored ZIP whole-file units first; broad7z/TAR/Deflate/RAR/split support is later qualification, not first-step claim.
