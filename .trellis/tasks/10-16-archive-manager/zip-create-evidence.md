## Resource/identity interface

See zip-create-contract.md for exact reference sources/APIs. ArchiveCreationSources owns held root/ancestor chains (<=32×65), at most one directory enumerator or active source file with one transient chain (<=64). All descendants carry operation-private IDs and retained full volume/128-bitID/size/mtime/ChangeTime. Before enumeration/open/read/close/final checks native handle-relative opens and identities are compared. No content is read through an ordinary mutable source path. No permanent handle per descendant, all-file content Vec, one-shot full-tree hash scan or duplicate runtime.

Directory enumeration checks cached versions before and after; final object/ancestor checks catch observed additions/deletions/replacements. Access/reparse/special files fail, never silently skipped. This optimistic bounded check is not a filesystem atomic snapshot. Root namespace remains protected through real process/Job cleanup; descendant file read handle denies write/delete while active. Closed descendant changes are rejected at final validation. Native tracked metadata plus fixed64KiB enumeration buffer and Rust conservative per-depth/path reservations precede retained allocation; working budget minimum64MiB covers bounded globs/codec/transient buffers. Output remains current native root/CreateName only; ConfirmedOverwrites cannot authorize a different name.

Schema2 create_zip adds optional zip_options; C# SourcePaths stays host-only, first path binding required. New request fields are omitted in legacy requests. Host requires source_lease_v1,budget_reservations_v1,partial_read_v1,source_tree_v1,zip_create_v1; missing each rejects through the same production capability validator. Invalid methods/strength/level/name/count/irrelevant fields and schema1 create reject. Product PlatformCommand, packaging helper mapping and capability UI remain future Phase A work.
