# Reduced motion common capability — implementation boundary

This is common capability work within the canonical five-stage migration of `design.md`, before consolidated visual/interaction closeout; it does not rename, reorder or complete a phase. The Windows SPI client-area animation preference, not a saved NxTools flag, is the source of truth; see `docs/reference-code/ui-motion.md` for SDK and lifecycle evidence.

Windows adapter reads and deduplicates the native value on its event STA in response to `SystemEvents.UserPreferenceChanged` (the existing message-only HWND cannot receive broadcast `WM_SETTINGCHANGE`). It removes the existing subscription in `Stop`, publishes bounded nonblocking typed events and retains the last sampled snapshot for every session handshake, regardless of discarded queued events. Failures and disconnected Rust policy default to reduced motion. Rust protocol carries correlation, boolean and native error code; desktop GPUI global owns UI policy, no synchronous leased-entity updates. Parent render migration may call `crate::ui::motion::motion_allowed(cx)` and skip Animation construction entirely when false; no render files were changed here. No runtime/service/installer/registry mutation is in this slice.

Safe unrun compiled test names: Rust `system_motion_preference_event_round_trips_with_correlation_and_failure` and `native_motion_policy_defaults_safe_and_tracks_transitions`; C# harness filter `system motion synthetic reader and wire round trip`. Static architecture check: `tests/architecture/ui-motion-policy.ps1`. Acceptance still requires compiled tests/build authorized by parent, real preference toggles while PlatformHost is running (including re-enable and disconnect/reconnect), no animation at all render sites when reduced, unchanged short durations when enabled, and GPUI/Windows window lifecycle checks; no synthetic test is native toggle proof.
