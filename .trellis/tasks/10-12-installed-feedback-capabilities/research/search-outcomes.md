## Outcome
Implemented Finder catalog-owned match materials and an exact old-score prepared-name path (retains the ASCII exact-word boundary implementation rather than replacing it with Unicode boundaries). Initialisms still use original capitals and pinyin still uses the legacy GBK table. Catalog replacement computes material before replacing entries; failed refresh leaves both last-good vectors intact.

Indexer `BaseSearchData` derives exact-name groups/row fanout plus folded ASCII 3gram postings from hot owned/mapped name sections. Clones share it through Arc, compaction constructs new data, overlays never mutate it and delta search stays independent. No persistence serializer, version, MFT enumeration, USN or service-session code changed; `mft/cache.rs` change is a synthetic mapped-constructor regression only. Existing mask, candidate headroom, filtering, preference rank, deterministic tie order and underfill fallback are unchanged.

Caps: <=1,000,000 base rows; grouping rejected when conservative groups/hash/row allowance exceeds32MiB; <=2,000,000 postings and65,536 terms, <=1024byte indexed ASCII name, <=256byte required query. Exceeding posting limits retains unique grouping but disables narrowing; grouping over-budget falls back to old row scan. Candidate allocation/verification <=32,768 groups AND <=one-quarter of unique groups, with every non-ASCII group included. Explicit ASCII exact/word/prefix/suffix queries can narrow; ordinary fuzzy input never does. Budgeted high-unique/large snapshots therefore deliberately receive no auxiliary acceleration.
