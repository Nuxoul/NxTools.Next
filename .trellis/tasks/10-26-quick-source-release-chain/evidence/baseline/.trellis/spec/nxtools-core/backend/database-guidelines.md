# Core persistence (SQL not applicable)

Evidence: `repo:rust/crates/nxtools-core/src/lib.rs#save_to`, `repo:rust/crates/nxtools-core/src/lib.rs#update_section`, `repo:rust/crates/nxtools-core/src/lib.rs#load_or_create`.

Core has no SQL connection/schema. AppConfig JSON uses typed section wrappers and locked reread/merge; save_to writes a sibling temporary, syncs, closes and renames. Missing/corrupt update targets error, never silently replace unrelated sections. Returned merged config refreshes cache. First-run load_or_create directly creates defaults—observed initialization, not same locked-update guarantee. See [durable section contract](../../shared/engineering.md).

Application blacklist canonical entries hold independent Clipboard/Quick Launch flags per normalized executable basename. Absent entries migrate legacy shared flags and Clipboard exclusions once; present-empty entries are authoritative and never reimport stale exclusions. Clipboard exclusions are a derived native projection only. Global settings atomically commits network/system/rules through one locked transaction, then defers no-persistence consumer publication. Only migration worker changes live storage root; ordinary clipboard save preserves disk latest root. Tests: stale cached update keeps other sections, canonical-empty reload/removal, mixed scopes, legacy-once migration, corrupt config refusal and missing config non-resurrection. Don't invent SQL migrations or log raw JSON/path/error context.

The later new-computer built-in-extension correction supersedes the earlier unguarded first-run initialization description: load_or_create now takes the same sibling lock as section updates, rechecks existence, validates existing config, stages compiled built-in packages through the original immutable store and saves the registry plus one-time marker atomically. Existing package IDs/sections win; already-initialized startup returns without writes, even after user removal. AppConfig::default/load_from do not seed or write. Failed parse/stage/commit does not replace last-good bytes or mark initialization complete. Bootstrap adds only bounded correlated lifecycle diagnostics, no raw error/path/script payload; see bundled_extension_tests for fresh/legacy/removal/concurrent/failure/explicit user-state fixtures.

SystemSettings.notification_position is a serde-default six-value enum (legacy BottomRight), persisted by the existing atomic global-settings transaction. Draft selection/Cancel has no write or live publication; persistence failure leaves the prior NotificationCenter location. Successful save defers presentation publication independently of later Windows startup/tray acknowledgement; a location-only save must not enqueue shell reconfiguration. Core six-value/default/roundtrip and Desktop actual selector32px/Cancel/Save/failure tests protect this boundary. No separate notification settings file or payload persistence.

CurrencyConversionSettings is nested in ClipboardSettings, serde-default off/CNY. Normalize trims/uppercases target and validates identifier syntax (2..16 ASCII alphanumeric bytes, at least one letter); malformed identifiers fall back to CNY. Do not reintroduce a fixed ISO allowlist: provider catalogs include USDT,1INCH and future codes. Desktop owns current catalog membership and retains a valid but temporarily unavailable saved target, so restart never silently erases a new provider currency. COMMON_CURRENCIES is localized display metadata only, not availability. Desktop set_currency_settings changes only clipboard.currency_conversion through AppConfig::update_section, preserving latest storage root/unrelated sections; save failure retains previous live enabled/target. Catalog/rates are disposable versioned Desktop cache, not Core config or copied payload persistence. Core dynamic-code/default/locked-merge and Desktop corrupt-config retained-state regressions protect this boundary. Evidence: `repo:rust/crates/nxtools-core/src/lib.rs#CurrencyConversionSettings`, `repo:rust/apps/nxtools-desktop/src/clipboard/currency_tool.rs#set_currency_settings`.

Presentation settings2026-10-22: `ClipboardSettings.image_view_mode` serde-defaultAuto and `QuickLaunchSettings.row_style` serde-defaultSeparated (gap4DIP,Continuous0). Persist only the owning field with AppConfig::update_section; preserve disk-latest Clipboard storage root/other sections and live cached panel size. Failure does not publish requested value. No native capture/indexer/service configuration is needed for presentation-only updates. Evidence: `repo:rust/crates/nxtools-core/src/lib.rs#ClipboardImageViewMode`, `repo:rust/crates/nxtools-core/src/lib.rs#QuickLaunchRowStyle`; Corelegacy/default/allsix/bothstyle/fieldmerge and Desktopactualselector/failure/noIPC tests.

Chrome store scoped amendment: `DownloadSettings.chrome_web_store_extension_id` is serde-default empty (first upload has no ID), trim then strict32a–p; malformed loaded values clear to empty/local fallback, invalid UI draft is rejected before persistence. Existing DownloadSettings section transaction preserves other sections. Store-ID registration is issued only after durable success and again on connection; failed persistence keeps previous live ID and cannot publish native mutation. Store ZIP uses original export owner, strips only manifest.key in copy and never touches local source identity/PEM. Exact full chain and tests: [extension contract](../../browser-extension/contracts.md#scenario-key-free-chrome-store-upload-and-optional-exact-identity).
