# Confirmed ordered UI queue brief

## Authorization and execution
User requests an AI Task Queue for remaining UI changes/replacements, preserving
ambiguous items for the final report and reviewing one consolidated screenshot
collection at the end. Adding queue entries does not start them: PI-Desktop's
AI Task Queue panel requires confirmation. No per-surface aesthetic approval pause
is required after queue confirmation; final user visual acceptance is consolidated.

Read this brief, current PRD/design/implement/adoption ledger, official component
index and matching reference note before each queued task. Latest implemented
Settings/Form evidence supersedes earlier source-audit findings only where named.
Canonical order remains **1. Foundation -> 3. Quick Find -> 2. Downloads ->
4. Clipboard + Tools -> 5. Global settings + supporting surfaces**. Shared catch-up
belongs to the currently owning consumer stage, not a silently renumbered stage.

## Common constraints for every task
- Workspace D:\Code\NxTools.Next-main; preserve all dirty work. No reset, wholesale
  restore, automatic commit/push, delegation or simultaneous same-file writers.
- Read docs/reference-code/gpui-kit-component-index.md COMPLETELY, corresponding
  official compound/released0.7.1 API, applicable Trellis specs and indexed legacy
  source chain first. Downloads: AB Download Manager before old NxTools.
- Use actual styled compound/leaf components. An import, suppressed appearance,
  manual duplicate chrome or one entire old page in a custom slot is not adoption.
- Official built-in settings search/presentation features are allowed by the user.
  Preserve all existing product functions, fields, actions, persistence policies,
  stable input entities/IME, shortcuts, controller generations, cancellation and
  failure/retry. Do not invent domain workflows or alter reset/commit semantics.
- Keep approved neutral semantic palette and released visual grammar/official tiers.
  Preserve native fixed/default/minimum clients. Adjust bounded composition/scroll
  instead of removing controls, enlarging windows or shrinking global typography.
- Rust owns state/layout, GPUI renders, C# owns Windows APIs. One dispatcher/focus/
  scroll/session owner; defer cross-owner writes, including cached/immediate paths.
- Approved launcher search effect stays untouched. Official Quick Find Settings /
  command Form just completed is not redone; only verified remaining gaps are changed.
- Existing narrow sidebar-focus, Clipboard project-menu, recorder, passive-window
  and OLE ownership exceptions are not whole-page exemptions.
- Exact dependency/backend graph remains. No upstream/registry edits, library fork,
  toolchain/dependency upgrades, Release package/install/service/real-volume indexing,
  ordinary runtime launch or real-user config/history/Clipboard/network operations.
- Use only temporary synthetic fixtures/disconnected bridges/localhost test data,
  scratch intermediates and explicitly isolated production-render previews.
- Every Rust command, including background wrappers, inherits CARGO_BUILD_JOBS=1,
  CARGO_INCREMENTAL=0, RUSTFLAGS=-C codegen-units=256; one Cargo at a time, full logs
  and actual exits/counts, full-operation timeout, no duplicate build after timeout.
- Add red-capable regression before replacement; preserve functional/native-budget
  assertions. Run focused behavior/bounds/focus/lease checks, fmt and strict scoped
  lint/check as applicable. Run integrated Desktop gates after shared/broad changes.
  Compilation/screenshots/test totals never certify adoption or physical acceptance.

## Ambiguity and blockers
Resolve recoverable implementation/test issues yourself. For genuinely ambiguous
behavior, unavailable public capability, new dependency/native change, or a conflict
with an existing function/budget: do not guess, weaken tests, fork or broaden scope.
Keep that narrow production boundary unchanged, append a concrete deferred record
and continue independent unambiguous work. Do not call an entire task complete if
its ambiguous slice is deferred. Do not disguise an actual compile/test regression
as ambiguity: fix it, or report the genuine blocker; task queue failures pause by
plugin policy. A documented deliberate defer with remaining work verified is a
valid task outcome, not an instruction to force the queue to green.

Use **ui-queue-outcomes.md** in this owning task as the single running record;
create it in the first queued task. Each task appends/updates its numbered outcome:
- actual source changes and adopted compound/leaf constructors;
- preserved functions and real checks/logs/exits/counts;
- completed / partially completed / deferred / blocked status;
- deferred item: exact file/symbol, official candidate, evidence, behavior tradeoff,
  why unresolved, recommended alternatives and decision needed from the user;
- screenshots acquired vs actually inspected, user/native/physical/DPI/reader limits.
Update adoption-ledger.md and implement.md at their actual evidence level. Maintain
TodoWrite for each multi-step task; settle all checklist entries when it ends.
