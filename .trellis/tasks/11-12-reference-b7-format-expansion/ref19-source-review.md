## Verified format distinctions

### ALZ

The selected real samples start with `ALZ01`, version10 and a two-byte zero-based volume ordinal. Continuations repeat the same header with ordinals1,2,… . Each nonfinal part ends with the16-byte `CLZ01 / two zero words / CLZ03` structure; the final part ends with `CLZ01 / comment-length word / zero word / CLZ02`. The two public reader implementations omit8-byte continuation heads and16-byte nonfinal tails from their logical stream. Their permissive discovery alone does not validate the header/ordinal/end contract required by B7.

Local headers carry raw names, DOS attributes/time, encryption/data-descriptor flags, legal size widths0/1/2/4/8, method, original CRC and packed/expanded extents. Methods0/1/2 mean Stored/ALZ-modified Bzip2/raw Deflate. Method1 is not a standard Bzip2 stream: it removes standard framing/CRCs and uses DLZ markers. Password verification is traditional12-byte ZipCrypto with CRC-high-byte or descriptor-time check; it is probabilistic, so mismatch must remain AuthenticationOrDataError rather than an invented definitive WrongPassword.

### EGG

The14-byte EGGA header includes version and unique Header ID. Split Info carries previous/next IDs; first.prev=0, last.next=0 and adjacent links must agree. A continuation's complete header/prefix/mandatory End marker is framing, not compressed payload. A payload block can span volumes; file/header groups do not. Validate the full protected chain before constructing logical ranges, not suffix order or arbitrary concatenation.

The file catalog carries original File IDs and declared size; names may be authoritative UTF8, locale-coded, encrypted or parent-relative. Windows/POSIX kinds must not materialize links/special files as regular content. Blocks have method, packed/expanded sizes and decoded CRC; block-header End is mandatory. The final archive End is distinct from prefix/file/block End. Methods0/1/2/3/4 are Stored/Deflate/Bzip2/AZO/LZMA. LZMA has a9-byte EGG prefix, not the standalone13-byte stream header. Solid state crosses files/blocks and cannot be decoded by resetting a decoder per file. Global/name encryption must not be skipped into an empty successful catalog.

## Integration decision boundary

Keep original native source acquisition and held volume lists, isolated worker, metadata credit, immutable BrowserContext/entry ordinals, password sessions, limits, typed first error and native output owner. Do not call either upstream filesystem extraction or automatic volume discovery. The existing Rust primitives cover ordinary Stored/raw Deflate, standard Bzip2/LZMA, CRC and required crypto building blocks; only a demonstrated method gap justifies an additional dependency. No upstream source/tests/resources are copied into product implementation.

The upstream ALZ index deliberately permits truncation, and ALZ modified-Bzip2 / EGG LZMA/solid paths can buffer encoded blocks. Those defaults are not adopted. Product qualifications and unqualified combinations are recorded in the accepted capability matrix and coordinator report, supported by independent oracle and original-worker/native tests.

## Remaining name, kind and short-authentication boundaries

Pinned CC0 EGG sections8.1/8.3/8.4 and unegg `archive.rs::parse_file_entry/resolve_relative_paths` → `encoding.rs::decode_filename/normalize_path` establish filename payload order: optional UInt16 locale under0x08, optional UInt32 parent File ID under0x10, then actual name bytes;0x04 denotes encrypted names. Code pages932/949 are explicit format metadata, while locale0 means system default. The upstream lossy unknown-locale fallback, removal of leading separators/control characters and one-level-only parent resolution are not integration candidates. Preserve original raw names and unsafe-path rejection; resolve accepted parent relationships under existing finite metadata limits without silently dropping a parent or converting encrypted names into clear text.

Unchanged CC0 `posix.egg` is identified by its source README as an Android-produced archive with real20-byte mode/uid/gid/Unix-mtime metadata, despite the format note's older unused-in-practice wording. Independent raw-zlib/CRC qualification verifies3files/98bytes; real Worker and production native extraction preserve exact bytes and Unix mtime. Windows and POSIX sub-headers cannot downgrade an already identified link/special kind into a regular materializable file when header order changes. Native output metadata policy remains authoritative.

Pinned unegg `EncryptionMethod::payload_lengths` → `read_encrypt_payload` recognizes AES/LEA salt-plus-verifier records both with and without the ten-byte HMAC. Excluding the method byte these are20/10bytes for128-bit methods and28/18bytes for256-bit methods; total payloads are21/11 and29/19. A candidate length must end at the mandatory End marker. The product's supported authenticated profile requires full HMAC. Independently qualified project-owned short records now prove typedUnsupportedEncryption at real Worker and production Read/Job boundaries; malformed declarations/End/truncation remain CorruptArchive. No lenient candidate scanning or declared-length fallback is adopted.

Independent qualification verifies unchanged CC0 Android `posix.egg` with raw Deflate EOS/consumption, format CRCs and mode0100660, uid10121, gid1023, mtime1785088885. Separate project-owned specification fixtures combine Windows/POSIX regular, directory, link and FIFO identifiers in both orders; producer type-profile evidence is not implied. Exact11/19-byte short AES128/256 and LEA128/256 fixtures independently verify PBKDF2 verifiers, ciphertext, raw Deflate/size/CRC without a full HMAC. These origins and authentication limits remain distinct in the capability matrix.

## Raw-name qualification boundary

The original `path_policy::components/annotate` preserves each decoded name and annotates UnsafePath; `worker_formats::admit` invokes it before metadata publication. Test remains read-only and verifies payload integrity. Extraction rejects an UnsafePath warning before opening native output; separator conversion occurs only at the native boundary. Production `ArchiveReadMetadata` preserves names and warning codes, including empty/control-containing names, rather than sanitizing the catalog. The original Job selection and output owner remain authoritative.

The name qualification uses separately labelled project-owned Stored ALZ/EGG specimens with15raw paths per format, including traversal, rooted/drive/UNC, empty components, devices, trailing characters, alternate streams, controls and an empty name. An independent CPython struct/literal/CRC oracle verifies every payload and final extent. Five EGG locale/parent specimens independently establish UInt16 locale followed by UInt32 parent and actual encoded name; current support deliberately rejects these flags with UnsupportedMethod. Encrypted-name and reserved Global Encrypt specimens prove declaration refusal only, not valid producer encryption or decryption. Both remain UnsupportedEncryption. No format-codepage provenance, parent resolution, lossy fallback or name normalization is added.

Production declaration qualification exposes the native terminal boundary: `ArchiveVolumeSources.ReadEggPrefix` rejects Global Encrypt as unsupported_encryption; `ArchiveWorkerRunner`'s source_acquire catch stores that first failure before cancelling its metadata pump. `ArchiveReadSession.OnRunnerEvent` must preserve this source category over the pump's consequential Cancelled frame, just as it already does for missing/source/resource admission. The minimal repair extends that original terminal-priority branch to its four existing corrupt/unsupported format categories; no Runner, source lease, cancellation or mapping owner changes.
