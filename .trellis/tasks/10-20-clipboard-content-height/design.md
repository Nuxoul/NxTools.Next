# Design boundary

Preserve300x440resizable history popup and one passive preview. Existing official Kit0.7.1 ListItem + TextView supports non-scroll fit-content rendering; compose natural text with existing metadata and outer ListState, not a new list controller. Styled Small outlined source Button remains, no language menu/second control. No Toolbar adaptation. Remove hardcoded prose buckets/four-line body clamp and plain Markdown height authority. Use exact official render/GPUI layout measurement, cache on content/width/mode, preserve full original action payloads.

Expected files: ui/history.rs (row constraints/text flow), ui/preview.rs + ui/preview_rich.rs (rendered measurement/body/footer/source only), clipboard.rs and preview lifecycle tests only if actual native target must receive measured size; existing tests/records/specs. Native API/style/readback/show/hide remains unchanged. Cross-entity callbacks always deferred; no render -> application reentry. Parser resource budgets remain and no HTTP/file image load.

References: docs/reference-code/clipboard-clipkeep-tiez.md and clipboard.md; re-read old ClipboardPreviewWindow.cs Update/ApplyTextSize/PlaceNear/passive constructor, ClipboardHistoryPopupWindow open/hide; ClipKeep natural text card structure. Reference legacy uses text estimates but has no Markdown renderer, so its estimate is not correct authority for new rich layout. Supplied screenshot is rejected acceptance evidence, not approved design. Official Component text/compat delegates to Base TextView; non-scroll document natural rendering and explicit layout measurement must be tested, not guessed.

## Actual implementation
- Natural history text row height replaces fixed slot/card/content heights and four-line clamp. Metadata remains24DIP, compact row minimum retained; original320row paging,400char cached safe projection/native payload hydration remain. Page stride reads actual ListState item bounds, falling back only for unmeasured rows.
- Preview measures official TextView non-scroll layout during render/request-layout at chosen width, caches by item/mode/width, uses real text-system measurement for bounded source/code. Beyond parser budget, retain bounded original scroll without measuring unbounded source. Parsed source, not rendered copy emptiness, determines readiness (e.g. thematic break).
- First hidden/reused offscreen MeasureInitial/MeasureReuse stages install current token before deferred view work, wait bounded3seconds, discard cancelled/oldtoken/generation/HWND; measured dimensions flow into original native SetWindowBounds. First final-size frame is explicitly drawn after bounds ACK before topmost/show; public draw arena token is cleared. Reuse retains native policy/move/bounds/frame/reveal chain; nontext replaces content normally.
- Rich scroll body is explicit, nonshrinking and contains size_full TextView; footer is separate/nonshrinking. One Small outlined source/render toggle remains. Manual language Popover/state/API are removed; automatic code grammars/highlighting remain.
- Screenshot rejection and later source bounds results remain distinct. No new screenshots/product/native/DPI acceptance was performed. Global full checks can be blocked by unrelated concurrent Archive edits; preserve them and report exact errors rather than edit/suppress them.
