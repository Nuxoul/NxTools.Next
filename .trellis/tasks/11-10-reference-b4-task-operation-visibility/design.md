# B4 design

## Original owners

- Core `DownloadSettings` → `DownloadHttpPolicy::parse_snapshot/apply_to_request` → immutable `DownloadRequest` → original engine probe/HTTP client/segmented runner → SQLite task/plan/segment/artifact. Settings changes affect future snapshots only.
- Desktop `DownloadApplication::open_settings_window` → original `DownloadSettingsView` stable TextareaState → current_draft/save → deferred `apply_settings` → original Core locked reread/atomic save → returned configuration/runtime publication. Cancel closes presentation only.
- Original typed DownloadCommand and DownloadEngine own task operations. Original BrowserBatchSubmit admits at most32items, ordered individual outcomes and original destination/duplicate reservations. Template confirmation will use that command, not sequential new admission or hidden splitting.
- Original engine progress/selected detail projections own written facts. The keyed DownloadTaskWindowView renders coverage alongside existing metrics/Server/limit/actions, without network, sampling clock or scheduler.

No reference code/comments/tests/assets are copied.

The command carries the opened source URL, engine generation and a fresh operation ID. Original EngineTaskState owns a candidate DownloadResolutionOperation; the existing cancellable probe runs without task/store/scheduler locks. Resume is refused while this lease exists. The store commits request/probe/plan metadata in one transaction without touching segment rows, queue membership or artifact identity. Publication follows commit. Duplicate/stale confirmations fail the source/generation/lease check. Desktop supplies the original cancellation control before spawning, so closing before worker admission also cancels the candidate.
