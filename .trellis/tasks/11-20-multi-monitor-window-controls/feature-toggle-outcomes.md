# R7 — Quick Launch and Clipboard enablement

## Controls and persistence

Both main pages place one official Component0.8.0 Medium Switch above their existing Settings content, outside the native caption. The component owns checked state, semantic label, pointer and keyboard behavior; one requested-value callback defers the original application-owner update. No parent click handler or Toolbar adaptation is used.

Each setter saves its owning section before publishing live state. Save failure retains the previous durable/live value and session. Core normalization preserves persistent Clipboard enablement while retaining the existing shared image/file capture capability policy. Native configuration status distinguishes desired intent, pending, success, rejection, timeout and disconnect. Reconnection reapplies durable intent; old receipts cannot update current status.

## Availability and retirement

Quick Launch disablement retires panels, preview, pending presentation/activation, query and file-dialog search. Native and assistant events predating the latest transition are rejected. Auto-switch/file-dialog preferences and index data remain intact; the shared indexer service is unchanged.

Clipboard disablement retires pending loads, reveal/activation, previews, links and menus; local and native admission reject disabled capture/summons. Retained history/assets/preferences and admitted history writes remain intact. Detection/currency generations are retired. Temporary capture pause and its deadline remain independent.

The original ConfigureClipboard parser defaults omitted enabled to true. Native disable unregisters its hotkey and blocks reads/publication. Re-enable establishes a fresh sequence baseline without backfilling disabled content. Configuration uses correlated start/terminal/elapsed/native-code diagnostics without payload logging.
