# Release 45 — native virtual-drag progress and staging observation

## Existing boundary

The original `ArchiveEntrySession.VirtualMaterialization` retains one Rust worker operation per drag. The worker's `op=progress` snapshots enter `ArchiveEntrySession.OnVirtualRunner`, then the bound `ArchiveVirtualContent` callback, `ArchiveVirtualDragSession.ProgressGate`, and the existing `archive_virtual_drag_progress` public event. A worker snapshot is applied only to its current live operation and `drag_demand` request ID / full descriptor index / original ordinal; malformed, decreasing, mismatched, cancelled and post-Seal snapshots are ignored without changing worker/output/terminal authority. Progress callback failures cannot change materialization.

The event has five optional trailing fields: `current_request_id`, `current_bytes_done`, `current_bytes_total`, `bytes_processed`, `sequence`. `bytes_done` and `files_done` remain *sealed-cache* totals. `bytes_processed` is sealed bytes plus current decoded bytes only while that member is active; after Seal it equals sealed bytes, without double charging. The current pair resets to zero/descriptor-known-or-unknown on each distinct demand, while aggregate unknown size stays unknown. On Seal, the current pair reflects actual sealed size; `target_copying` and receiver-reported `finished` remain different from native cache completion. Publication of the state and strictly increasing sequence happens under the existing 100 ms coalescing gate; dropped coalesced snapshots can produce sequence gaps, not reordering. A late previous-index `GetData` cannot overwrite a newly active member's phase.

`ArchiveEntrySession` records aggregate Seal and verified-cursor count/time with `Stopwatch`, emitted at original operation terminal and cleanup, not per read. `ArchiveVirtualFileDataObject` observes only first successful descriptor HGLOBAL delivery, async Start and End. The session records OLE loop return and existing requested/ready/receiver/terminal events under the same drag correlation and elapsed clock. These do not log names, paths or content and make the source phase comparable with a separately authorized target event trace; they do not establish a DOpus staging cause or destination-write completion.

## Boundary verification

`ArchiveVirtualAsyncLifecycleTests.ActualMultiDirectoryUnknownProgressAndEndOrdering` remains registered in its existing fixture family. It begins with `ActualMemberByteProgress`: owned 2 MiB stored ZIP, original real worker and 25 ms original native-write probe, `GetData` on the original COM data object and actual target-held `IStream`. It requires a nonzero current byte snapshot **before Seal**, checks request/descriptor identity, sealed-versus-processed accounting and ordered wire events, injects one wrong-demand frame at the original `OnVirtualRunner` while real work is active and verifies no oversize progress or failed real output. The existing two-member tree fixture separately checks current reset, nullable unknown total, distinct source ordinals, End-before/after-loop behavior and receiver-reported terminal. The extra tree write-probe delay only ensures the 100 ms gate has an observable reset; it does not substitute a mock byte source. Controlled fixtures use an explicit matching worker and GUID-owned scratch; no physical target, GUI, DOpus, service, registry or package operation.

The real-worker fixture passes with nonzero current bytes before Seal, correct request/index binding, stale callback refusal, member reset and both End/loop orders. Original native ABI/state references, slow consumer UI return, receiver cancel/abort/disconnect and preview lease adoption also pass against the final Debug worker. The retained context fixture confirms one worker/source/catalog for1/2/16 demands, first-ready before worker cleanup and actual final cleanup. [Executed verification](release45-repair.md).
