## 1. Outcome

Deliver the union of the original optimization review, later supplements and the owning task's applicable workflow requirements across five required workstreams:

1. Open/browse, Test, materialize and extract selected/all members without repeating archive-sized work for each member.

## 3. Required extraction and update efficiency

- **PERF-01 — Open once per attempt.** Separate catalog-only work from editing qualification. A browser needing edit facts qualifies its already opened source/catalog; Test/extract/materialize do not independently discover unused edit capability. Ordinary eligible ZIP browser admission must not add another pair of whole-source scans just for capability discovery. Independent public qualification and unleased engine callers retain their fresh source-change contract.
- **PERF-02 — Constant source work across selected members.** Under actual ordinary native held-source authority, full-source revision work is outside the member loop. For the same ZIP, source revision pass count is independent of whether 1, 2 or 16 files are output. Every member retains ordinal, structure, complete codec end, CRC/MAC, actual-size, cancellation and native publication checks.
- **PERF-03 — Reuse format work.** One current-operation verified TAR spool and one ordinal-indexed validated ZIP record plan serve discovery and execution. Metadata/work/spool reservations and cleanup remain finite. No persistent/global source-content cache is introduced.
- **PERF-04 — Validate unchanged/new ZIP payload at the correct place.** Retained encoded records continue to copy without recompression. Retained/new payload is completely verified in the final candidate; removed/replaced-away old payload still receives any source verification required by today's corrupt-source refusal. Additions retain structural checks but do not undergo a second redundant complete payload decode before final-candidate validation.
- **PERF-05 — Single-pass selection expansion.** Normalize paths once, merge selected directory prefixes and scan the catalog once. Extraction, directory drag and edit planning share component-ended subtree semantics without replacing original ordinals/names. Avoid selection-count × catalog-count scans and repeated per-candidate allocations.
- **PERF-06 — Consolidate only equivalent native observations.** Source/target digest reuse is limited to one archive-edit stage after proving the same continuously protected object. Final fresh edit-source/target validation, reader-close evidence, FILE-only handoff, candidate output fingerprint and postpublication checks remain authoritative for archive Create/Edit; ordinary destination extraction has no output fingerprint or postpublication reopen.
- **PERF-07 — Efficient private bulk transport and ordinary output.** Create/Add source reads, archive candidates and retained-cache outputs keep negotiated bounded binary payloads and their required acknowledgements. Ordinary destination extraction separately negotiates `extraction_output_v1` inside bulk v1, sends <=32KiB coalesced records through the original anonymous pipe without per-record ACK, and uses the single Host stdout pump as the bounded consumer. Keep typed controls/prompts/results, first native write failure and close-after-drain ordering; do not create a second public IPC/Job runtime or raise global deadlines/concurrency.

## 5. Required Add, creation and extraction workflows

Target flow: **choose/drop/paste → review sources and fixed internal directory → resolve complete namespace → encode accepted new data → retain supported old records → verify one final candidate → one native publication → refresh original directory and select actual results**.

Archive path, original tab/window, generation, snapshot, source revision and internal directory are frozen and rechecked at final submit. Navigation/source replacement cannot silently retarget the draft.
- **ADD-02 — Complete intake.** Keep file multiselect/repeated folders and per-source removal. Window drop offers explicit Open-first, New-from-all and capability-gated Add; New reuses the original create form and full source list. Paste files uses bounded C# `CF_HDROP` reading and the original Add/New policy, accepting standard HDROP-only data. Text-input Ctrl+V retains text behavior; COPY/CUT never grants deletion authority. Existing Add root limits remain distinct from archive member/drag descriptor counts.
- **ADD-03 — Resolve same-batch naming.** Distinct filesystem roots with the same basename enter Add-specific namespace planning rather than fail before Ask. Directory-directory inputs merge logically and child-file conflicts use existing tickets; file/directory conflicts still refuse. Overwrite/Skip/AutoRename/Cancel and ApplyAll remain current-attempt-only. Overwrite changes one candidate plan, not source files or a separately committed archive.
- **ADD-04 — Reserve all requested names.** ZIP/7z/TAR-family planners reserve original archive names and the complete incoming name/type set before any AutoRename. Generated names cannot consume later incoming original requests. Descendant naming and content/source-ID association stay coherent.
- **ADD-05 — One verified update.** Qualified ZIP, ordinary single-volume 7z and TAR/TGZ/TXZ use their existing adapters and capability refusals. ZIP new entries keep their currently explicit Deflate/unencrypted policy; old records preserve compression/encryption/metadata. Do not imply encrypted-new-entry inheritance or ZIP-like cheap solid/outer-compressed updates. Cancel/all-skip is zero publication; no delete-old-first or two-commit overwrite.
- **ADD-06 — Select actual results.** Return bounded, private, display-only affected-member outcomes after Skip/Overwrite/AutoRename. Only matching committed/cleaned-up work refreshes the original browser and remaps final paths to NEW snapshot IDs. Large outcome sets remain bounded with truthful total/subset presentation; business changes are not truncated. Member names are not logged or treated as write authority.
- **ADD-07 — Multi-folder intake.** System multi-folder selection is required later delivery through the current owner-bound STA picker, retaining repeated folder additions, cancellation/focus, correlated pending retirement and the existing source-root budget. Share this intake with New, not a second picker lifecycle.

- **CREATE-04 — Verification and source retention.** Candidate/readback verification precedes publication; configured post-create Test follows successful creation/cleanup in the same logical job. Do not release/widen protection or reacquire paths after post-Test to mint deletion authority. Report per-source recycle outcomes separately from archive success; no permanent-delete fallback. - **CREATE-06 — Created-result and publication facts.** Capture native-confirmed archive/family location before output disposal. Carry original commit/journal/counts, `output_published` and location through post-create Test; Test's no-output false cannot erase created publication. Expose manual Locate on qualified success/warning terminals only. Do not infer location from requests or enable Locate/Retry for failed post-Test merely because bytes were published.
