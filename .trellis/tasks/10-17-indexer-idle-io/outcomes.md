## Root cause
Actual production path: `usn::windows::poll_snapshot -> apply_journal_batch -> IndexerService::poll_journals -> persist_system_delta -> persist_delta` serialized the **entire cumulative overlay** on every CursorAdvanced/Updated, flushed/synced a fresh temp and atomically replaced the delta. Its own indexed-volume temp/replace changes produce new USN work; metadata/close records were also classified as content change solely by records-nonempty, even when no effective change occurred. A small live update therefore amplified to megabytes everypoll and self-cache activity sustained more polls/saves.

The actual temp-file writer regression was added and run before the fix:2,761,844-byte overlay,three one-row updates wrote **8,285,532process bytes**, failing the32KiBcap. Log `indexer-idle-io-write-amplification-red.log`. This matches the runtime full-delta rewrite signature, rather than blaming normal MFT startup scanning.

## Source fix
- New `mft/cache/journal.rs` stores checksummed append transactions for changed replacements/deletions/resets with their matching cursor+visiblecount. Initial/checkpoint full frame atomic, later frames diff only; each successful commit syncs. It is not a timer-only throttle or indexing exclusion.
- `MftSnapshot` clones share per-base last-successful durable checkpoint, separate from existing immutable searchable snapshot/live overlay. Failed commit never acknowledges changes; original maintenance retry saves lateststate and retains original persistence error/last-good search contract. No `IndexerService` orchestration, search rank/session/auth/wire or external dependency changes.
- Base VERSION3 remains unchanged; old version3delta accepted and first new save atomically migrates once without full-volume scan; a second update proves actual append. New128bytechecksummedheader binds immutable base-version filename/mount/originalbasecursor/rowcount. Mapped reopen applies only a matching complete journal. Incomplete finalappend cannot expose newer cursor/rows; retry truncates residue, including a complete write whose sync was not acknowledged. Missing/short backing delta atomically rebuilds latestmemory, preserving normal fault/retry if that fails. Wrong journal/base/checksum/shape rejects delta into original base+USNcatch-up recovery. FirstframeFULLonly; stalecursorrejected. Startup evaluates base/delta pair effectivecursor within samejournal beforecleanup, preserving olderbase+newercursor over newer-stalebase.
- Atomic rewrite/checkpoint occurs only after bounded append growth exceeds checkpoint+max(checkpoint,1MiB), not everypoll. Unchanged snapshot writes0; cursor-only transaction72bytes. The finite frame budget is256MiB; storage failure remains explicit, not silent lost persistence.
- USN poll now classifies actual applied overlay/count change; no-effect metadata events remain CursorAdvanced/NoChange and retain existing idlebackoff. Actual time/path/delete change remains Updated.
- Existing `indexer-idle-cpu.ps1` keeps protected tuple/LocalSystem/restart/hash/readiness checks and now reports process read/write/other. AssertRegression also rejects controlled idle read+write>=64KiB/s by default; it is process logical I/O, not physicaldisk attribution. Only parser/source checks ran in this task, NOT RestartService or new packaged service acceptance.
