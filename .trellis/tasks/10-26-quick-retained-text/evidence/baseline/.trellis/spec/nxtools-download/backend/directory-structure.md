# Download structure

Evidence: `repo:rust/crates/nxtools-download/src/lib.rs#TransferPlan`, `repo:rust/crates/nxtools-download/src/engine.rs#DownloadEngine`, `repo:rust/crates/nxtools-download/src/message.rs`, `repo:rust/crates/nxtools-download/src/engine/segmented_runner.rs`.

lib defines domain request/task/segment/plan; message owns command/event/fault projection. engine.rs keeps shared DownloadEngine/inner state, command orchestration, admission and transfer lifecycle. Private engine/browser.rs owns browser handoff/dialog/Blob publication and compensation; engine/queue.rs owns queue order/admission and daily/delayed schedule wakes; engine/projection.rs owns full/compact snapshots and selected-task details. These implement the same engine, not forwarding managers. Existing segmented/HLS/DASH runners remain transfer owners; http owns network validation/streaming; artifact/capacity own disk publication; storage owns SQLite; media/ffmpeg_install own bounded child/explicit third-party install; organization/request_policy/rate_limit own reusable rules. GPUI/windows/chrome stay outside library. Don't split by file size without real seam/test benefit or leak raw requests into logs. [Architecture](../../shared/architecture.md).
