# Extensions persistence

Evidence: `repo:rust/crates/nxtools-core/src/extensions.rs`, `repo:rust/crates/nxtools-core/src/lib.rs#try_update_section`, `repo:rust/crates/nxtools-extensions/src/registry.rs`.

No SQL owned here. Core AppConfig.extensions serde-default empty preserves old configurations. PackageRegistry.validate checks identity/hash/trust metadata, duplicate enabled keywords, aliases/settings and exact event/provider/chain references before load/save. Core locked reread transaction rejects before write and preserves other sections. Import/replace disabled/untrusted, aliases independent of hash; manual/package conflict checks in both save directions. Bundled code is staged/synced before registry pointer commit; no mutable source import or inherited replacement authorization. Password settings cannot serialize; settings_transaction reads previous secrets and records attempted mutation before native writes, reverse compensates on config failure and reports CompensationFailed. Live Credential Manager remains C#; fake stores only in fixtures, native2560byte blob bound. Durable download provenance uses existing task JSON, not a second store.

Runtime environment uses serde-default `runtime_defaults` (python/node/powershell/pwsh) and optional package `runtime_override`; no second config store. Resolve override -> default -> legacy approved executable only when no configured selection; EXE always staged. Original locked Core setters validate absolute/nonempty/bounded/control-free paths before mutation; saving may name a missing executable but does not approve it. Effective-path changes call original revoke (disable, clear trust/automatic intents), unrelated explicit overrides and no-op selections retain authorization. Publication/execution reject selected-path versus approved-identity mismatch. [Executable contracts](../../../tasks/10-15-extension-runtime-settings/code-spec.md).

ZIP intake performs bounded validation without filesystem extraction; immutable preview retains declared files only. Declarative snapshots also persist their normalized manifest, while legacy entries without snapshot remain readable. Ordinary UI uses Core `import_extension_preview_checked`: compare the reviewed previous hash/absence against the latest registry inside the original locked reread before staging/install. Cancel/stale/failed validation writes nothing; private staging failures clean only their owned stage. Published content-addressed snapshots are not deleted after config failure without an exclusive sharing lease. [ZIP contracts](../../../tasks/10-15-extension-zip-import/code-spec.md).

Production bundled defaults are compiled from the three existing example sources by `bundled_previews`, not looked up in the development checkout or downloaded. Core load_or_create takes the original sibling config lock before create/load, stages missing packages in config-parent/extensions, commits the existing registry and `bundled_defaults_initialized` together, then returns the committed config. Existing same-ID entries win without changing settings/trust/enablement; once initialized, user removals/empty catalog are authoritative. New/legacy bootstrap remains disabled/untrusted with no interpreter install, process/network/effect or automatic event/provider opt-in. Ordinary AppConfig::default/load_from remain side-effect free. Partial stage failure retains prior config bytes; published snapshots are not unsafely deleted. `bundled-extensions.ps1 -DesktopExecutable` verifies exact embedded package resources in the packaged binary; Core first-run tests independently verify registration.
