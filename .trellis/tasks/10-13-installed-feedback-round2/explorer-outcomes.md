## Implemented semantics
- Production opts into exact target observation (`ExplorerShellActivation.cs:109-169,201-204,428-430`). Older synthetic IExplorerShellPlatform implementations retain their existing foreground-only contract through default interface members; no production implementation takes that compatibility route. Existing public command/result shape remains unchanged.
- `ObserveTarget:254-266` requires a nonzero root/view, visible active view and matching normalized full directory. A file request additionally requires the exact case-insensitive full filesystem path in that view's selected items. Directory request does not require a selection. Existing folder, same-root foreground, native S_OK and executable launch alone never establish file success.
- Native observation `274-373`: ShellWindows collection -> existing IWebBrowser2 HWND contract -> IServiceProvider QueryService(SID_STopLevelBrowser,IShellBrowser) -> QueryActiveShellView -> IOleWindow.GetWindow -> visible view under expected Explorer root -> IShellView.GetItemObject(SVGIO_BACKGROUND=0,IID_IDispatch) -> active view Folder.Self.Path/SelectedItems.Item.Path. This does not trust LocationURL or arbitrary same-root browser Document. Visibility/root is read again after snapshot. Directory observation skips selected-item enumeration.
- Exact IUnknown COM IIDs/vtables include IOleWindow preceding slots (`377-419`); PreserveSig keeps native HRESULTs. Each acquired COM reference is released in finally; nested apartment enter/dispose remains on the existing detached STA worker. Native failures retain HRESULT without raw exception text/path.
- The existing eight-attempt loop, seven 75ms waits and at most one executable fallback remain. Counts are capped at 256 ShellWindows entries and 4096 selected items; excess/unsupported selection is fail-closed. No new worker, nested poll loop, thread, timer or unbounded retry. A stuck COM call is still not synchronously interruptible; this change does not claim a hard wall-clock native timeout.
- Once exact target is observed, one restore/activation/readback is best effort: success Data remains `foreground_confirmed` when foreground matches; otherwise success Data is `target_confirmed_foreground_not_confirmed`, Error=null. Activation exceptions retain NativeErrorCode with successful target result. Confirmed target does not trigger a recovery launch just to steal focus. Dead observed window or removed target still fails; missing/unobserved/wrong selection fails (`target_missing`, `target_window_destroyed`, `target_not_confirmed`).
- Stages distinguish `target_readback`, `target_confirmed`, activation/readback, optional `foreground_activation_failed`, foreground result and target-not-confirmed. Existing adapter correlation/stage/terminal/elapsed event ownership is preserved; no paths/raw COM payload or polling logs added. Rust current HWND/generation close, failure copy, cancellation/stale/disconnect remain parent-owned and untouched.

## Pending acceptance / limits
- No live Explorer/COM, browser/navigation, registry, service/install/package or Cargo operation was executed. Build and fake snapshots do not certify the actual Windows11 provider/tab behavior or installed interaction.
- Separately authorized installed acceptance must cover new/reused/minimized Explorer, active/inactive Windows11 tabs under shared roots, exact file selection, denied foreground with success-only completion close, wrong/missing target failures, UNC paths, and originating-window generation/stale/cancel/disconnect handling. No unconditional click-close or accepting folder-only evidence.
- Native reader can fail closed on unsupported namespace/non-filesystem paths, provider/API errors or bounded collection caps; it does not invent a success or spawn replacement workers. Existing general Shell adapter per-command STA creation is outside this owned slice; no worker-pool redesign was performed.
