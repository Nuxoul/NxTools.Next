# Markdown Reader Design

## Surface and controls

```text
[official file tabs]    caption drag space    [代码 | 分栏 | 预览] [actions] [— □ ×]
[chapter rail / pinned tree] | centered Markdown article (Preview)
[source editor]              | Markdown article (Split)
[source editor across the workspace] (Code)
```

Keep official file tabs, mode choices and document commands in the native caption's public slots, separate from drag and window-control targets and outside `Toolbar.child`. Reserve command width; truncate long filenames and retain official horizontal tab scrolling. In Split the header spans both panes. Source and preview body share one requested font size and 1.5 leading, using their existing mono/UI families. Keep the existing theme roles and one official resize handle between panes.

| Surface | Locked API and final placement |
| --- | --- |
| Other Tools | Existing 180×160 catalog layout and official `ListItem` / `Icon` / `Label`, shared `tool_status`, and one Small outlined `Button` labeled `配置…`. The configuration action does not activate the reader or toggle its state. |
| Configuration | Reuse `feature_settings_window` and its first-body-row `Switch` and status. Put reading defaults and Markdown association/status/actions in the same scroll body via official settings field or Form/Field slots, preserving the other tools' caption and spacing. Use Small outlined buttons for Windows default-app and manual preview actions. |
| Reader window | One activatable, resizable Kit `Root`; existing `caption_window_options` / `slotted_controlled_titlebar` supplies native drag and window controls beside official document components. |
| Mode controls | Official Small outlined segmented ToggleGroup with Code, Split and Preview. Derive one checked item from the reader mode and defer the requested transition. Selecting the active mode is a no-op; disable when no document is eligible. Preview is read-only. No mode key bindings. |

## Ownership and lifecycle

- Keep the single reader owner under Desktop `tools/markdown_reader`. The configuration action has its own reused feature settings window; manual preview and the Explorer launch intent both reach the original reader owner. Reopen activates the existing reader window; normal close retires it, its pending chooser and file observers. Apply open requests and worker completions only to the original live window, tab and document revision, on a later application turn even on cache hits. No disk, asset preparation, SQLite or export in render.
- Rust owns paths, drafts, document state, export preparation and history. GPUI owns viewport, selection and IME rendering. PlatformHost owns Windows file dialogs and native PDF generation. Use its existing owner-bound picker/STA seam with Markdown open and export filters, no timeout on human selection; reuse its detached command/result route and cancel/retire on owner loss. Send one correlated machine export after successful selection, separate from human wait. Do not route through a feature-specific archive picker or the GPUI sample's unowned chooser.
- Keep immutable last-good committed file bytes separate from the draft and parse projection. Normalize the opened file path for tab identity; reject non-regular inputs. Preserve UTF-8 BOM and original byte representation on unchanged save; disclose unsupported encodings rather than rewriting them. For an edited document, check the current disk bytes against the captured baseline, including before restore; normal external save/replacement comes through one debounced open-document observation, refreshes clean tabs and surfaces a conflict on dirty tabs. Save and restore stage a sibling file and replace only after a complete write. Missing/locked files and stale results never clear the last-good view or draft. No extra digest is needed to compare bytes already held or read.
- Keep one draft per tab and one source editor across Code/Split. Reuse unchanged TextViewState across layout changes. Mode changes never write the file. Preview only selects/reads content; source edits belong to Code and Split. Defer cross-entity mode, focus and viewport effects beyond leased callbacks.
- Bind `TextViewState::rendered_text`, `set_range_highlights` and `reveal_range` to the committed parse revision. Outline jumps use each heading's source span and the corresponding laid-out block; document links and find retain the TextView range-reveal path. Keep one scroll owner per pane. Align split positions by source offsets and committed top-level block boundaries, not by relative scrollbar pixels. Scroll within a single tall block is not line-for-line across panes. Suppress reflected scroll and retire queued offsets when content changes.
- With two or more nonempty headings, the rail tracks the last heading at or above the viewport top, or the last visible one at the document end. A deliberate jump keeps its target active until independent scroll. Hover opens after 200 ms without moving text focus; keyboard activation opens the same outline. Clicking the collapsed marks is not a toggle. Escape dismisses the transient layer. Pin only where the preview column fits; preserve the preference when falling back to the rail overlay.
- Use the existing source `Language::Markdown` and Kit's registered fenced-code highlighter with the current theme. Validate resolved and visible token colors in both themes, and plain text plus exact copy for unsupported fences. Keep the first implementation confined to this reader, without changing parsers or dependencies.
- Resolve local image paths relative to the source document on a worker and feed approved assets through the GPUI Base image resolver. This reader policy does not widen passive Clipboard/Quick Launch/Archive projections, auto-fetch remote images or execute document HTML. Same-document anchors and relative Markdown links stay in the reader; external web links open only on explicit user action.

## Winc Markdown visual target

Use the supplied `INSTALL.md`, outline and typography images with the [Winc visual reference](../../../docs/reference-code/markdown-reader.md#winc-markdown-visual-acceptance-reference). Keep native caption semantics and compact official tabs/mode controls. Open, Save, Export, History and Find retain their owners. Avoid duplicated titles or unrelated chrome changes.

Keep `TextViewState`, the committed layout and source-identity mapping. Apply pane geometry and type roles through the locked `TextView`/`TextViewStyle` public heading, paragraph, code and table slots. Use the existing `code_block_actions` slot and a GPUI Kit `Button` with a copy icon, XSmall size, ghost variant, named accessibility and hover/keyboard-focus reveal. Keep it out of layout flow and outside `Toolbar.child` adaptation. Keep one block copy action and preserve raw text and code highlighting.

Match the 600-DIP pane-local inset switch and outline clearance, 1.50 body leading, relative heading rhythm/rule placement, quotes and list density, compact code background/insets, and table density and overflow. Use the same body size and content bounds in the comparison, and compare content roles in both themes without changing the shared app palette. Where the pinned `TextView` public slots do not expose a Winc block treatment, identify the actual gap from the measured fixture before choosing a reader-local adaptation. Do not replace the renderer/parser, patch Kit, or broaden this to other Markdown surfaces.
- **Outline.** Keep the short chapter marks next to the centered article. The normal read-only Preview and the Split render pane do not draw or reserve space for source line numbers. Use an in-pane deferred layer because Kit Popover has click-toggle semantics and a trigger-edge anchor. The card holds its position while scrolling or jumping; its visible bounds expand from the intersection with the outline marks, without reflowing the heading rows. Reuse Tree, single-line ListItem and the official pin Button. Treat marks, card and scrollbar as one hover region: 200 ms dwell, 160 ms retract on leave, no toggle on the collapsed marks, no collapse on heading click, deliberate pin/unpin, and a separate keyboard route. Keep the original committed source positions and briefly tint the measured target after a jump.
  Floating and pinned outline containers own their bubbling left-button down event, so it cannot start the Root's window text-selection gesture. Heading clicks retain the official Tree's selection and the Root's mouse-up cleanup. Deferred jumps never clear arbitrary text selection or synthesize mouse releases. Verify this boundary with the production Base Root and real TextView selection before and after a directory click.
- **Code and Split.** Render the existing source entity once through the locked Kit `component::input::Editor` with `bordered(false)` and reader-local monospaced typography and padding. Keep its gutter and syntax highlighting; no editor replacement, duplicated state, minimap or changes to standalone Preview. Use an official Component `resizable::resize_handle` with its hairline/active appearance because the grouped `h_resizable` builder has no public reset gesture slot. Store one reader-local proportion and clamp both render panes to at least 240 DIP. Use the measured right pane for article geometry; resizing must not be interpreted as an independent scroll or rebuild the editor.
- **File tabs.** Official Folder/Small TabBar with truncated labels, built-in scrolling and XSmall ghost close Buttons in the public suffix slot. Keep official shape and state colors, one selection/close owner and a label-only dirty marker. Leave the optional file-list dropdown off.

## Shared export and version boundaries

- On explicit export freeze the visible source revision, including a draft if active, and resolve its assets once. Use the workspace Markdown crate for a GFM HTML projection with bundled styles, heading anchors and embedded supported local images. Do not execute HTML supplied by the document or depend on remote assets. Missing resources have a visible fallback; supported discrete images are actually inlined. HTML needs no browser engine to generate. `PrintToPdfAsync` consumes that same standalone print-styled representation on a bounded dedicated STA, using a staged local file handoff rather than putting HTML in the pipe. No persistent renderer, HTTP server or WebView in the reader. Publish only a successful PDF; remove partial staging on failure. A missing WebView2 Runtime affects PDF only, with actionable feedback and no automatic install. The SDK/packaged loader integration is limited to this adapter and must pass its native gate independently.
- Use the existing Desktop `rusqlite` and app-data root for a reader-owned local store. Record document identity, committed bytes, event kind, time, optional name and stable version ID. Compare to the last stored version to skip unchanged consecutive content; retain a bounded timeline with a documented retention policy, protecting intentionally named versions. Store no unsaved draft as a committed version. A pre-restore snapshot must be durably committed before altering the file, and subsequent restore failure must not claim that the document changed. If history recording fails on an ordinary completed file save, report the save and history outcomes separately; don't claim rollback of the saved file.
- Required diagnostics: one operation ID across Desktop, protocol and PlatformHost as applicable; accepted, start, relevant transitions and terminal result plus elapsed time and native code at the boundary that owns it. Coalesce watcher activity into applied reload, conflict or failure. Do not log document contents, queries, paths, file names, HTML or keystrokes. Keep writes/diagnostics off render and preserve original owners when closing or superseding a request.

## Configuration and shell launch

- Persist feature state and reading defaults under the existing Core section-update path; merge only changed fields. Feature enabled defaults to true to preserve current in-app access, and no association registration is written by default. Native registered/effective-default facts are observed Windows state, not copied from the requested toggle. Show distinct pending, registered/non-default, default and error results; refresh after returning from Default Apps. Existing open documents and unsaved drafts stay live if new admission is disabled.
- Settings saves and explicit association actions publish one invocation-specific result through the existing NotificationCenter, with the originating settings window retained across workers/IPC and deferred center updates. Use Success for durable saves/registration/removal, Info for manual status refresh and default-app guidance, Error for failed or refused operations. Constructor/activation association queries are silent on success and failure. Keep actual per-extension status and fixed instructions on the page, without a private transient feedback field or result Alert. Current-operation matching precedes publication; duplicate/stale results remain silent. A successful disable query continues into the original durable save and emits only that terminal result.
- C# PlatformHost owns registration for an independent Markdown ProgID and only the `.md`/`.markdown` `OpenWithProgids` entries plus the application capability entries needed by Windows. Use the installed NxTools desktop identity and a quoted `--markdown-open "%1"` command. Reuse the existing `OpenDefaultAppsSettings` adapter for the system-owned selection, `AssocQueryString`-style effective association lookup and normal Shell notification. Do not write Explorer's private default preference or foreign values. Do not remove the handler while it remains an effective default; expose the corrective action instead. Keep archive registration, installer policies and existing application defaults unchanged.
- Route the explicit Markdown open intent through the existing authenticated desktop listener and instance-conflict recovery pattern, with a typed Markdown payload rather than masquerading as an archive. Preserve the archive wire contract. Cold startup suppresses the main window and opens the target in the existing normal reader. Warm startup forwards the request before generic main-window summon, reuses the current reader, and uses canonical per-tab deduplication. The receiver checks enabled state and file eligibility before admission. Use the original logical operation correlation for native registration, launch intake, dispatch and terminal diagnostics without paths or content.
- Keep file-open/admission, tab selection, visibility and Windows foreground activation as distinct results. One explicit Shell operation may activate only its reader HWND, including restore from minimized. Read back actual foreground identity through the owning Windows boundary; preserve the same correlation ID across protected redirect, single-instance forwarding and activation. Decide the foreground handoff boundary from the cold/warm reproduction; reuse the native adapter where applicable. Do not add a synthetic input workaround, persistent topmost behavior, global focus-policy changes, or post-action retries that steal focus after a later user gesture.
