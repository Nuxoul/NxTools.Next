# Extraction metadata and MOTW handoff

Evidence: `repo:rust/crates/nxtools-archive/src/metadata.rs`, `repo:rust/crates/nxtools-archive/src/formats/zip.rs`, `repo:rust/crates/nxtools-archive/src/formats/tar.rs`, `repo:rust/crates/nxtools-archive/src/worker_codecs/rar.rs`, `repo:csharp/NxTools.PlatformHost.Tests/ArchiveMetadataTests.cs`.

## Scenario: Typed archive metadata through the original publication

### 1. Scope / Trigger
Phase A extraction mtime and supplied Windows readonly/hidden, plus default-on original-source MOTW. Not UI, source deletion, product IPC/queues or packaging. Read the task's [source matrix](../../../tasks/10-16-archive-manager/research/extraction-metadata-sources.md) before changing a format adapter.

### 2. Signatures
`OutputMetadata { modified: Option<ModifiedTime>, attributes: Option<WindowsAttributes> }` is immutable and Copy. `ModifiedTime::{DosLocal{date,time},FiletimeUtc{ticks},UnixUtc{seconds,nanoseconds,precision_ns},Invalid}`; attributes are two booleans,never a native mask. Rust retains metadata by live output token and ordinary `ArchiveOutput::commit_extracted_file(token,metadata)` carries it to C# for same-handle application and close. `finalize_directory_metadata(relative,metadata)` uses previously registered layout authority. Unsupported adapters fail closed.

### 3. Contracts
- ZIP original central records: NTFS100ns UTC -> UT unsigned Unix seconds -> DOS local2s. All-zero DOS is absent. Central UT length5 may contain only mtime even when local-header flags include other times. Supplied malformed higher-priority time is not fallback. Windows-origin0/10/14 permits low1/2 only.
- 7z presence flags gate NtTime100ns since1601 and Windows attributes; raw zero is not absence when present. No upper POSIX/raw bits replay.
- RAR DLL mtime low/high is normalized UTC FILETIME; zero means unavailable in that API. Public Windows host2 gates attrs. Original encoding/precision/RAR4 zone ambiguity is not recoverable. Exact bundled `dll.hpp` is pack1; do not use mispacked upstream HeaderDataEx. Private packed codec FFI checks win64 size10244/CmtBuf6188/Mtime6268 and copies arrays before references.
- TAR mtime uses only its fixed12-byte checked octal/GNU signed base256 decoder; GNU markers0x80/0xff, full-field sign extension and checked i64 conversion. Never use unsigned Header::mtime or truncate to low64bits. All-NUL/space is absence; malformed/overflow is Invalid; valid signed values retain Unix semantics and existing native-range validation. Size/other numeric fields stay unchanged.
- PAX mtime is Unspecified/Set/Delete, not empty decimal. Local Set > global Set > header; global Delete removes persistent override and restores later member headers. Local Delete suppresses both global and header for the current member only; next member retains global context. Last same-key record wins; nonempty malformed values remain Invalid. Bounded64-byte signed decimal/fractions use no floats/exponents; negative discarded sub-ns digits preserve earlier100ns floor. TAR compounds share the parser and original compressed-source authority. See [source semantics](../../../tasks/10-16-archive-manager/research/extraction-metadata-sources.md#tar-time-p2-source-clarification).
- Gzip first genuine RFC1952 MTIME describes aggregate output; zero absent. BZ2/XZ/ZST have no fabricated mtime/Windows attrs.
- Schema2 extract-only `extract_options:{copy_motw:bool}`; omitted fields stay omitted for legacy wire. New C# caller omission means default-on. Ordinary host requires extraction_metadata_v1+motw_v1+extraction_output_v1; old raw wire gets no new metadata-bearing close.
- Preserve full codec/source/cancel checks before ordinary commit. TAR/7z/RAR retain metadata in Rust with the live token until whole required stream/block integrity succeeds. Commit drains earlier original-pipe records,applies fixed MOTW/time/whitelisted attrs on the open final-name handle,verifies the required API/observed metadata result and closes. No ordinary partial,rename,output fingerprint,published reopen,per-file directory reverification or durability flush. Explicit directories finalize deepest-first; ordinal lookup is bounded,not repeated linear entry search. No Rust Windows APIs or ADS bytes.

### 4. Validation & Error Matrix
Missing/not-provided -> absence. Supplied invalid/out-of-range -> InvalidMetadata. DOS stays local; native ambiguous/nonexistent calendar fails. Native unrepresentable value or metadata/ADS failure cannot be full success. Valid FILETIME0 currently succeeds as a native no-op: C# verifies exact observed mtime and fails metadata_time_not_supported at close rather than treating it as absent. A failed metadata/close deletes only the current incomplete owned ordinary output; earlier successfully closed facts remain.

### 5. Good/Base/Bad Cases
Good: independent ZIP/Python/external7z/syntheticRAR archives plus native Windows file-info/ADS oracle. Base: no metadata still extracts ordinary bytes; default source MOTW applies through the common C# seam. Bad: source stat/current time/extension supplies fake metadata, DOS relabeled UTC, Unix mode becomes readonly/hidden, or public binding names substitute for verified native ABI.

### 6. Tests Required
Retain real Start -> Job -> Rust -> native tests for each supported metadata source and absence format,directory ownership/deepest-first,signed precision/zero/invalid values,options negotiation,default/disabled/missing/empty/budget ADS,native failure/cancel/close and privacy. TAR regressions assert raw GNU negatives/full-width overflow,global clear/local suppression/scope,exact compound content/native UTC time and true prior closed files after a later failure. New ordinary regressions must prove commit-carried metadata on the final-name handle,no separate metadata call/partial/rename/flush/fingerprint/reopen,and incomplete-only deletion. Boundary-year oracle uses Windows GetFileTime UTC directly because .NET GetLastWriteTimeUtc can overflow via local conversion. Keep wire compatibility,full isolated archive tests,default+isolated strict Clippy,fmt/workspace check and original C# selection union new tests. Current results belong to the [single checkpoint](../../../tasks/10-16-archive-manager/phase-a-checkpoint.md).

### 7. Wrong vs Correct
Wrong: `attributes = raw`,set final-path metadata after close/reopen,or trust SetFileTime success without observation. Correct: Rust-held typed values -> ordinary commit -> fixed MOTW/time/whitelisted attrs on the live final-name handle -> observed metadata -> ordered close; Create/Edit candidates retain their separate verification/publication.
