# Ordinary single-volume 7z edit contract — Phase E

## 1. Scope / Trigger
Actual opened ordinary single-volume7z Add/Delete/ReplaceContent/file rename/directory subtree rename/NewDirectory. This is a slice of **Phase E — Format expansion and ZIP editing**, not a new phase or a TAR/RAR/volume editor. Evidence: `repo:rust/crates/nxtools-archive/src/worker_sevenz_edit.rs`, `repo:rust/crates/nxtools-archive/src/sevenz_edit_header.rs`, `repo:rust/crates/nxtools-archive/src/sevenz_edit_plan.rs`. Accepted ZIP record-preserving editing is separate and unchanged in policy. Exact results/remaining acceptance belong to the task checkpoint and outcomes.

## 2. Signatures
- `ArchiveJobModifyAction::ReplaceContent` uses wire `replace_content`; SevenZ only, exactly2paths/1ordinal/valueNone. ZIP replacement remains unavailable.
- `ArchiveJobModify.source_prefix: Option<String>` / C# `SourcePrefix=null`: SevenZ directory rename only, one original descendant ordinal plus original slash-ended prefix and slash-ended destination. Never infer selected parent level from a descendant or sorted row.
- `ArchiveBrowserContext.sevenz_edit: Option<SevenzEditEligibility>`: actual worker-open eligibility, typed refusal or no refusal; absent legacy facts do not enable UI editing. Final private `modify_7z` always rechecks actual source/header/native binding.
- Private schema2 `modify_7z` requires original Job execution, matching SevenZ intent, `sevenz_modify_v1`, `source_tree_v1`, `partial_read_v1` and original source/budget capabilities. Rust/C# validate action shape; no new output authority or protocol-version reset.

## 3. Contracts
Locked `sevenz-rust2=0.23.0` remains isolated. Every old stream is fully consumed, including deleted/replaced members; survivors stream directly to the writer. Only encoded anonymous spools exist. Decode and encode memory reservations are summed; actual decoded bytes, per-entry bytes, metadata/count and encoded candidate output remain finite. Native added-source IDs reuse original no-reparse/identity/version/self-output protection. Zero-length files must still open/check EOF/close; directories are not opened as files.

Output is single-thread **non-solid LZMA2**, with full reencoding even for a rename. Known old member ctime/atime/mtime/Windows attributes/kind/content/empty directories are compared against the complete decoded candidate; uniform AES and encrypted-header state are retained with original private password flow. Mixed plaintext/AES blocks, unpreservable encryption, links/reparse/anti/special items, unsupported coder graphs and unknown semantic properties reject before publication. Old compressed blocks, compression ratio/layout, unknown properties, NTFS ACL/ADS and arbitrary source metadata are not preservation claims. Added sources currently supply name/type/content through the original source contract; their DOS-local wall time must not be relabeled UTC.

Edit-only raw/decoded header admission validates the entire property payload, CRC/signature/tail and finite descriptors before general parse/decode. Pinned7Zip `kDummy=0x19` is bounded repeated **zero-only** alignment, not unknown semantic metadata; nonzero padding rejects. Encoded-header synthetic Header/MainStreamsInfo must have a real FilesInfo/stream map; require complete descriptor consumption and nonempty pack mapping before `BlockDecoder`. Never patch registry dependencies or catch-and-ignore a panic.

Omitted optional SubStreamsInfo means one unpack stream per folder (pinned7Zip/NanaZip), not corrupt metadata. The private streamed synthetic Header bridge must materialize an empty SubStreamsInfo `[8,0]` only when absent, because locked0.23.0 `read_files_info` requires that mapping. Keep original archive bytes/PackPos and explicit descriptors unchanged; require exactly one metadata stream. Regression controls: `hz4_encoded_metadata_omitted_substreams_default_one` and `hz4_encoded_metadata_explicit_substreams_control_and_crc` cover PackPos0/7, optional folderCRC and mismatch rejection.

Secondary-reader failure is not product corruption merely because it occurs after publication. HZ4's opt-in `--qualified-bsdtar-partial-attributes` may separately classify only the [parent-approved four-entry structure](../../../tasks/10-16-archive-manager/hz4-7z02-reader-decision.md) as `reader-unsupported`, not PASS. It must still run bsdtar and validate exact reader hashes/version, bounded encoded/decoded headers/CRCs, canonical inline definitionsTTTF/values32,32,16 and unchanged full primary manifest/native/process/fresh-refusal gates. Unknown hash/version/structure/CRC stays FAIL; canonical/swapped/all-defined executable controls discriminate0/1,2/0,0/0. Do not remove metadata, fabricate the added-directory attribute or change the writer to appease a reader.

Deletion uses immutable ordinals and component-ended subtree prefixes, deduplicating overlaps without matching `ab/` for `a/`. Rename validates all final safe names, case keys, duplicate and file/directory prefix collisions, self-descendant destinations and stale prefixes. AutoRename checks explicit and implicit directory reservations before choosing a numbered candidate. Add conflict response tickets remain original once-only; apply-to-all is attempt-local. All-skipped Add returns original warning counts with0commits, without reencoding the archive.

Complete encode/finish/flush -> local full candidate metadata/hash/decode verification -> held native partial readback/hash/full verification -> close every old source reader -> original `edit_reads_complete` -> C# held-source fullID/version/hash/target recheck -> final cancel -> FILE-only release -> one existing atomic publication. Parents/candidate remain protected. The approved final-check/close/path-publish TOCTOU is not ID-CAS. Failed-before-commit preserves original; published/unknown facts outrank late cancel and never auto-retry.

Original `OperationControl`, serialized ProgressWriter, queue(max2running/32queued), attempt/generation and progress window remain. Fixed phases `edit_planning`, `edit_reading`, `edit_reencoding`, `edit_verifying`, `edit_committing` use original progress payload; unknown totals remainNone. Only the five fixed7z phase transitions use the existing bounded business queue; same-phase byte updates retain100ms sampling and single-slot coalescing. Codec processed bytes are not saved bytes/100%. Cancellation/pause are cooperative; backend header encoding is not claimed immediately interruptible.

## 4. Validation & Error Matrix
Stale ordinal/revision/native binding/add-source change -> SourceChanged. Unsafe lexical path -> UnsafePath; duplicate/case/file-prefix collision -> OutputCollision. Unknown metadata/special source -> UnsupportedOperation; unsupported coder -> UnsupportedMethod; mixed/unpreservable encryption -> UnsupportedEncryption. CRC/readback/hash/metadata/decode mismatch -> CorruptArchive; finite reservation/actual bytes -> ResourceLimit. First source/spool/control errors survive codec wrappers. Exact native edit commit failure retains original native code/state through C# terminal, not a later generic IoFailure. Unknown commit retains evidence/no retry.

## 5. Good/Base/Bad Cases
Good: independently7Zip-produced time/attribute archive edited once, exact hashes/metadata verified by stock7Zip; implicit `a/b/c.txt` selected as `a/` renames all descendants and leaves `ab/` alone. Base: ordinary solid/nonsolid and AES/header-AES survive supported edits with disclosed reencoding. Bad: suffix enables writes, Add pretends replacement, encrypted output becomes plain, unknown fields vanish, finish alone authorizes commit, or all-skipped input claims a publication.
