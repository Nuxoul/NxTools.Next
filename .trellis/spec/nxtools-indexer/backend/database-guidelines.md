## Persistence failure state (2026-10-13)
IndexerService tracks per-volume persistence errors separately from journal poll/build/compaction errors, and a separate settings-save error. refresh_last_error includes all owners. Preserve the original cursor/delta save-attempt before publishing the usable in-memory snapshot; write failure never drops last-good search or falsely acknowledges durable state. Idle NoChange retries only a previously failed current snapshot using the existing maintenance cadence; it clears that volume's fault only after successful persistence. Healthy other volumes, RebuildRequired and ordinary rebuild/rediscovery do not acknowledge a failed save. Settings same-value updates retry when an earlier write failed and clear only their own error after commit. Rediscovery retains error state for still-present volumes and settings. Fixed status copy/native code avoids exposing backing paths; diagnostic failure/recovery transitions are deduplicated. Required real-maintenance injected and temp-file boundary regressions use persistence_fault_ filters in lib tests. Release LocalSystem restart/base+delta/search/idleCPU remains separately authorized.

## Scenario: Proportional durable delta transactions (2026-10-17)
### 1. Scope / Trigger
Sustained idle writes were reproduced: every CursorAdvanced/Updated rewrote the cumulative delta; cache temp/replace USN events fed later polls. CPU-only idle checks missed this. Keep live searches/durability; no blanket user-file exclusion or polling-delay-only workaround.
### 2. Signatures
`mft::persist_system_delta(&MftSnapshot) -> Result<()>` delegates to `cache::journal::{persist,decode}`. Snapshot clones share `Arc<Mutex<Option<DeltaCheckpoint>>>`, the last successfully synced per-base disk state, not a second live index. Base VERSION3 and legacy DELTA_MAGIC reader remain. New NMJLOG journal version1:128byte checksummed header binds immutable base-version filename, mount, original base cursor and row count; length-prefixed frames contain cursor/visiblecount/replacement/delete/reset counts and32byte SHA256. Initial FULL frame only, later diff frames. No service wire/config change.
### 3. Contracts
Persist before existing memory publication; only successful sync/atomic replace advances durable checkpoint. Failed append keeps last successful overlay/cursor so next original maintenance retry includes all missing changes. Cursor-only commit72bytes; unchanged snapshot0writes; one-row commit proportional to row. Atomic checkpoint only when append growth exceeds checkpoint+max(checkpoint,1MiB), not everypoll; maxframe256MiB. Legacy first new save migrates atomically without rescanning/replacing base. Complete checksum-validated frames alone expose their matching cursor+rows; incomplete last append leaves last-good and is truncated before retry. Journal ID and cursor monotonicity bind per-base owner; only first frame is FULL. No high-frequency diagnostics or payload logs.
Restore evaluates complete base/delta pairs before cleanup; within the selected journal retain highest effective committed cursor, not highest base-filemtime. Do not compare cursor numbers across different journal IDs. New-format sidecar binding is checked before applying overlay/count/cursor to a base; legacy remains readable until one-time migration. Missing or externally shortened delta can be atomically rebuilt from current memory; only successful sync/replace updates its shared durable owner.
### 4. Validation & Error Matrix
Torn last frame -> last complete cursor/overlay; complete corrupted frame/wrong journal/invalid lengths/duplicate reference/misplaced FULL -> reject delta, original base+USN catch-up recovery. Save/sync/replace failure -> visible original per-volume persistence fault, searchable last-good/new memory retained. Stale cloned cursor -> reject, never regress disk. Checkpoint failure -> old journal remains and original retry owns recovery. Unknown/new format cannot silently fabricate results.
### 5. Good/Base/Bad Cases
Good:2.76MBoverlay/three one-row updates894actual process-write bytes in temp fixture, replay latest. Base:oldversion3delta opens then migrates once. Bad:serialize every cumulative row after any USN, cursor durable without corresponding change commit, full checkpoint appended midstream, source tests claimed as installed idle acceptance.
### 6. Tests Required
`idle_io_` actual Windows process write counter, temp-file mapped reopen/delete/reset/cursor/noop, every truncated append prefix, checksum/journal/base-binding reject, failedappend and complete-unsynced-residue retry, missing/shortfile recovery, boundedcheckpoint, staleclone/misplacedFULL, authoritative base+delta selection before cleanup, migration-once then append. Existing `persistence_fault_`, synthetic USN/search/admission plus strict/workspace/fmt remain. No unrestricted real-volume suite. Separately authorized packaged LocalSystem restart/base+delta/search/hash and CPU+I/O regression gate required before release acceptance.
### 7. Wrong vs Correct
Wrong: `poll -> persist_delta(all_overlay) -> temp/replace -> next USN -> repeat`. Correct: `poll -> apply actual changes -> diff against successful checkpoint -> one checksummed append+sync -> publish memory`; periodic bounded atomic checkpoint, matching recovery cursor. ## Publication retirement and legacy allocation bounds (2026-11-01)
`cleanup_published_snapshot` derives its directory from the actually published snapshot cache path and mount-derived prefix. Service rebuild/compaction terminal handling cleans only after publication, release of old service snapshots and quiescence of all build/compaction workers. `apply_build`/`apply_compaction` alone never sweep: another worker may already have persisted an unpublished pair. Keep the current base/delta pair and the existing restore authority. Native deletion/sharing failure is deferred to a later cleanup; outstanding searches retain valid mapped ownership whether Windows allows deletion or refuses it. Emit one bounded correlated retirement summary, not per-file payloads.
The compaction terminal event is an ownership handoff: `spawn_snapshot_compaction_with` first stores the compaction Result, explicitly drops its input snapshot, then sends either CompactionCompleted or CompactionFailed. Removing an active-worker marker alone does not prove that the worker released its old mapping. Both terminal paths must release before send; temporary mapped-input/rendezvous-channel regressions observe Weak ownership before the receiver can trigger cleanup.

Before any legacy replacement/deletion map capacity allocation, checked `replacement_count * DELTA_RECORD_SIZE + deleted_count * 8` must fit the actual post-header payload. Reject impossible/overflow/maximal counts through the original base+USN catch-up recovery, without changing VERSION3, delta journal bindings or recovery selection. Tests `m3_` use temporary rebuild/compaction pairs, leased old files and mapped search reads; `l11_` observes actual allocator requests and restores the base through `load_cached_snapshot` after corrupt maximal headers. Full signatures/state/error matrix: [quality contract](quality-guidelines.md).

Fresh scan base-write or exact-reopen failure is a build publication failure: keep the previous usable snapshot, expose the real error, and end maintenance as failed. This does not change the established usable-memory plus per-volume retry policy for incremental delta writes. Allocator heap, mapping file size, working set and private commit must be reported separately.

## Mapped publication after rebuild/compaction (2026-11-06)
`mft::{scan_volume_and_persist,compact_system_snapshot}` persist the newly built owned base, then consume it through `cache::reopen_persisted_snapshot(MftSnapshot) -> Result<MftSnapshot>`. Retain only its exact cache path and mount before releasing the build's owned rows, masks, reference/child maps and search auxiliaries. Open that file with `MappedSnapshot::open` and build fresh auxiliary groups/postings through `MftSnapshot::from_mapped`; persisted file-reference ordering differs from owned row order. Do not transfer row-indexed owned search data.

This is not startup recovery: no candidate enumeration, older-base fallback, delta replay or obsolete-file cleanup at the reopen boundary. The just-written compact base contains the journal identity, cursor, count and row metadata; its empty overlay/new durable checkpoint continues through the original delta writer and restore path. Keep VERSION3 and all base+delta bindings unchanged.

Only a successful exact reopen returns a new snapshot for existing service publication. Write/open/map/validation failures propagate as build/compaction failures, retaining last-good and native io::Error sources; never return owned as success. Original compaction source-cursor rejection, worker input-release-before-terminal, quiescent cleanup and outstanding immutable search leases remain authoritative. No new trim, concurrency policy or search algorithm. Required temporary-file publication/failure/lease/auxiliary/delta regressions: `mapped_publication_` in `mft/cache/publication_tests.rs`; retain `m3_`, `u4_`, `persistence_fault_` and journal fault/replay tests.

## Global single-compaction admission (2026-11-06)
`run_coordinator` owns one global active compaction slot through the original `active_compactions` set. `schedule_snapshot_compactions` returns without spawning while that set is nonempty, and admits at most one eligible volume per call. Hold the slot until its real worker drops the input and sends a terminal event; the coordinator applies/rejects success or records failure, then performs the original worker-quiescent cleanup before another admission. No timed-out/replacement worker bypass.

Pending compactions retain only mount-point strings, never cloned snapshots or built owned bases. Original current overlays remain authoritative. Recheck enabled volume, snapshot presence and unchanged overlay threshold at admission, so disabled/removed/already rebuilt volumes retire their stale pending entry. Polls refresh candidates from current state; success, stale completion and failure permit remaining volumes to advance. Per-volume compaction errors, retry deadlines and earliest-retry scheduling remain independent; another volume's success cannot clear a failure.

Standalone reader EOF drains the already discovered eligible batch, including after a first-volume failure, before returning. It does not discover new work or start future retries. Persistent admitted endpoint disconnect still retires only endpoint I/O; the service coordinator and pending maintenance survive. Active compaction uses the original bounded receive wait rather than an expired poll deadline. SearchExecutor continues against immutable last-good base+delta while compaction is held. Formats, thresholds, native service behavior, build concurrency and working-set trim are unchanged. Required actual coordinator/temporary-file regressions: `serial_compaction_` in `mft/cache/compaction_schedule_tests.rs`.
