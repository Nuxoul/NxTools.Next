# Archive HZ3 batch projection

## 1. Scope / Trigger
Step5 HZ3 summary around original `ArchiveApplication` logical jobs. Evidence: `repo:rust/apps/nxtools-desktop/src/archive/batch.rs`, `repo:rust/apps/nxtools-desktop/src/archive/batch_jobs.rs`, `repo:rust/apps/nxtools-desktop/src/archive/jobs.rs`, `repo:rust/apps/nxtools-desktop/src/archive/launch_entry.rs`. HatchZip reference is [batch-summary](../../../../docs/reference-code/hatchzip/batch-summary.md), not a scheduler to import. No HZ4/HZ5, persistent history or stop-on-error policy.

## 2. Signatures
- `bind_batch(Vec<logical_job_id>, refusal, cx)` records a separate batch UUID and finite membership in original Jobs. `batch_snapshot_for(job)` reads actual original records; native operation/attempt and session/generation remain separate.
- `JobProgressView::apply_batch` receives private snapshots on a deferred application turn. Original progress HWND/Root/controls/prompt/focus/result-location owner stays. Summary is another mode in that surface, not a new window/controller.
- `retry_job(logical_id,cx)` is an explicit action, not an automatic replay. `start_job_observation` reuses `PlatformCommand::ArchiveSpace` v2; `job_observation_result` requires receipt/current connection/request session/generation.
- `bind_confirmation_forms` binds same-launch pending original forms, then `attach_confirmation_jobs` replaces their not-started facts with real logical members. Original cancellation records submission-before-start cancellation without inventing a task.

## 3. Contracts
Original queue remains2running/32queued/2GiBaggregate with FIFO/head-overlap, same-source serialization and cleanup-held slots. Never replace with HatchZip serial Runner, stop siblings after failure or bypass a blocked head for an unrelated batch. Original `validate_batch` checks structural/capacity/memory before synchronous submissions; ensure defer_pump resets on every per-item outcome, and any real accepted/not-admitted split remains truthful.

Batch data is identity/membership/count metadata, not another request/selection/execution store. Project original queued/admitting/started/prompt/paused/terminal records, not private Complete/receipt as Done. Track ever_started separately: queue reservation/admission is not worker Started. Queue-cancelled remains Cancelled and never-started; warning/partial publication/cleanupunknown cannot become aggregate success. Archive-job counts and native file counts are distinct; unknown byte totals do not produce aggregate percentage. Finite output readmission/post-create Test/new explicit attempt cannot add a logical member or duplicate terminal counts.

Retry is fail-closed and limited to single-source Test or unselected Extract. `JobObservation.job: Option<(logical_id, native_attempt_id, retry)>` binds each original observation/recheck. First-baseline acquisition requires original `record.command.operation_id == active_operation`, the same attempt still present in original `Jobs.attempts`, current receipt/connection/session/generation and no native/logical terminal. First valid baseline is immutable. `retire_job_observations` runs at native Terminal BEFORE finite coordinator delivery, attempt dispatch, local failure, disconnect and logical terminal. Missing initial facts cannot be reacquired on a later finite attempt even when logical generation is unchanged. Failed/Rejected, cleanuptrue, `output_published == Some(false)`, no result_location, zero committed, explicitly unpublished/precommit journal and a bounded retryable code are required; legacy absent/null publication is UNKNOWN, not zero. Source/target change, unknown/published/unclean, missing baseline, create/password draft or edit authority requires original form/reopen, not summary replay. Explicit retry obtains a NEW read-only observation with expected_source/expected_target, bound to the completed native attempt, then reenters original queue with SAME logical ID and NEW operation UUID/generation. Native admission still owns source/capability/target/budgets; no recovery manager or duplicate dispatch.

Original ArchiveSpacePreflight already uses held ArchiveVolumeSources/OutputSession.Prepare. Explicit version2 returns optional bounded `source_set { identity, primary, members }` from those original leases; version1 response remains unchanged. Rust/C# strict bounds: v1 opaque ASCII identity<=256, local valid paths,1..1024 unique members, primary and original requested source in members, aggregate UTF8 member bytes<=1MiB; current receipt/session/generation/connection and <=2MiB encoded observation. These private facts never become execution/write authorization or log content. Missing facts refuse dedup/retry.

Whole-selection extraction uses those same source sets before original form/batch admission. Only equal native identity or membership in a successfully validated family can collapse a later-volume selection; do not infer by basename/case/suffix. An unrecognized later volume is refused unless another same-selection validated family covers it. Same basename in different directories remains different. Native observations do not create target directories, run codecs or modify sources. No native volume parser/lease/write-sharing change.

Batch relationship retention is bounded to64 completed groups, coordinated with original64job retirement. `prune_retired_jobs` scans at most the opening retired length; protected IDs are requeued, not lost when popped. Remove only closed, cleanup-complete terminal records outside running/retry-pending/active-or-pending batch protection; stop at64 or after one pass if protected records prevent reaching64. Completion, original background-window close, form retirement and finished/failed retry recheck reuse this original owner. Active/cleanupheld/retrypending/pending-confirmation relationships cannot be evicted for a count. Initialize pending forms BEFORE pruning. No persistent/second history manager.

UI is exact Kit0.8.0 public stateless Table/Header/Body/Row/Head/Cell plus Label/Alert and outlined Medium32 Buttons; parent is direct layout, not Toolbar.child ghost/compact adaptation. One original scrollbody and flex-none reachable footer at480x260; no new palette/fonts/clock/animation. Existing details/control/result-location actions remain original owners. Prompt mode takes precedence and clears secrets on original lifecycle. View-to-owner and owner-to-view writes defer, including immediate observation results.

Diagnostics reuse existing sinks/correlation: batch accepted/member finished/batch finished plus explicit retry accepted, original job start/state/terminal elapsed/native code. Once-only terminal metadata suppresses duplicate summary logs; counts are terminal facts, not fabricated overall success. No paths, member names, contents, credentials, request Debug/exception Display or per-frame/chunk/pointer logging.

## 4. Validation & Error Matrix
Invalid batch/capacity/memory -> original atomic rejection/no jobs. Per-item rejected after acceptance -> preserve accepted/not-started counts and reset defer. Prompt -> waiting; pause -> paused; unstarted cancel -> cancelled+notstarted. Native cleanup false/unknown -> held slot, disabled retry. Same original identity/target after safe precommit failure -> new attempt/same member; changed/stale/missing observation -> no replay. Unknown total -> counts only. Newer attempt/session/connection -> old result ignored. No source-set evidence -> no guessed dedup.

## 5. Good/Base/Bad Cases
Good:3jobs produce2original Starts+1queued, one prompt, one paused and queued cancellation are all visible; cleanupunknown retains slot; legal retry keeps batch member count. Base: original single-task progress/controls remains. Bad:3worker attempts counted as3archives, all-cancelled labelled success, clone serial Runner, reuse raw terminal path as new authority, or initialize empty confirmation batch then prune it.

## 7. Wrong vs Correct
Wrong: batch ID equals active worker ID -> copy request state into second scheduler -> retry unknown result -> count readmission twice. Correct: separate batch membership -> original logical records projected -> safe preterminal native identity + explicit fresh recheck -> original queue/newattempt -> truthful original terminal/counts/held cleanup.
