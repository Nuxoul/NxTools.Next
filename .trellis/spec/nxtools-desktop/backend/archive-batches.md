# Archive HZ3 batch projection

Current framework source lookup follows [Kit0.10.0/defaultpre0.3.12](../../../../docs/reference-code/gpui-kit-0100.md). Earlier versioned evidence below remains historical; the original layout/variants, lifecycle/native and deferred-owner contracts are unchanged.

## 1. Scope / Trigger
Step5 HZ3 summary around original `ArchiveApplication` logical jobs. Evidence: `repo:rust/apps/nxtools-desktop/src/archive/batch.rs`, `repo:rust/apps/nxtools-desktop/src/archive/batch_jobs.rs`, `repo:rust/apps/nxtools-desktop/src/archive/jobs.rs`, `repo:rust/apps/nxtools-desktop/src/archive/launch_entry.rs`. HatchZip reference is [batch-summary](../../../../docs/reference-code/hatchzip/batch-summary.md), not a scheduler to import. No HZ4/HZ5, persistent history or stop-on-error policy.

## 2. Signatures
- `bind_batch(Vec<logical_job_id>, refusal, cx)` records a separate batch UUID and finite membership in original Jobs. `batch_snapshot_for(job)` reads actual original records; native operation/attempt and session/generation remain separate.
- `JobProgressView::apply_batch` receives private snapshots on a deferred application turn. Original progress HWND/Root/controls/prompt/focus/result-location owner stays. Summary is another mode in that surface, not a new window/controller.
- `retry_job(logical_id,cx)` is an explicit action, not an automatic replay. `start_job_observation` reuses `PlatformCommand::ArchiveSpace` v2; `job_observation_result` requires receipt/current connection/request session/generation.
- `bind_confirmation_forms` binds same-launch pending original forms, then `attach_confirmation_jobs` replaces their not-started facts with real logical members. Original cancellation records submission-before-start cancellation without inventing a task.

## 3. Contracts
Original queue remains2running/32queued/2GiBaggregate with FIFO/head-overlap, same-source serialization and cleanup-held slots. Never replace with HatchZip serial Runner, stop siblings after failure or bypass a blocked head for an unrelated batch. Original `validate_batch` checks structural/capacity/memory before synchronous submissions; ensure defer_pump resets on every per-item outcome, and any real accepted/not-admitted split remains truthful.

Batch data is identity/membership/count metadata, not another request/selection/execution store. Project original queued/admitting/started/prompt/paused/terminal records, not private Complete/receipt as Done. Track ever_started separately: queue reservation/admission is not worker Started. Queue-cancelled remains Cancelled and never-started; warning/partial publication/cleanupunknown cannot become aggregate success. Archive-job counts and native file counts are distinct; unknown byte totals do not produce aggregate percentage. Finite output readmission/post-create Test/new explicit attempt cannot add a logical member or duplicate terminal counts.

Retry is fail-closed and limited to single-source Test or unselected Extract. `JobObservation.job: Option<(logical_id, native_attempt_id, retry)>` binds each original observation/recheck. First-baseline acquisition requires original `record.command.operation_id == active_operation`, the same attempt still present in original `Jobs.attempts`, current receipt/connection/session/generation and no native/logical terminal. First valid baseline is immutable. `retire_job_observations` runs at native Terminal BEFORE finite coordinator delivery, attempt dispatch, local failure, disconnect and logical terminal. Missing initial facts cannot be reacquired on a later finite attempt even when logical generation is unchanged. Failed/Rejected, cleanuptrue, `output_published == Some(false)`, no result_location, zero committed, explicitly unpublished/precommit journal and a bounded retryable code are required; legacy absent/null publication is UNKNOWN, not zero. Source/target change, unknown/published/unclean, missing baseline, create/password draft or edit authority requires original form/reopen, not summary replay. Explicit retry obtains a NEW read-only observation with expected_source/expected_target, bound to the completed native attempt, then reenters original queue with SAME logical ID and NEW operation UUID/generation. Native admission still owns source/capability/target/budgets; no recovery manager or duplicate dispatch.

Original ArchiveSpacePreflight already uses held ArchiveVolumeSources/OutputSession.Prepare. Explicit version2 returns optional bounded `source_set { identity, primary, members }` from those original leases; version1 response remains unchanged. Rust/C# strict bounds: v1 opaque ASCII identity<=256, local valid paths,1..1024 unique members, primary and original requested source in members, aggregate UTF8 member bytes<=1MiB; current receipt/session/generation/connection and <=2MiB encoded observation. These private facts never become execution/write authorization or log content. Missing facts refuse dedup/retry.

Whole-selection extraction uses those same source sets before original form/batch admission. Only equal native identity or membership in a successfully validated family can collapse a later-volume selection; do not infer by basename/case/suffix. An unrecognized later volume is refused unless another same-selection validated family covers it. Same basename in different directories remains different. Native observations do not create target directories, run codecs or modify sources. No native volume parser/lease/write-sharing change.

Batch relationship retention is bounded to64 completed groups, coordinated with original64job retirement. `prune_retired_jobs` scans at most the opening retired length; protected IDs are requeued, not lost when popped. Remove only closed, cleanup-complete terminal records outside running/retry-pending/active-or-pending batch protection; stop at64 or after one pass if protected records prevent reaching64. Completion, original background-window close, form retirement and finished/failed retry recheck reuse this original owner. Active/cleanupheld/retrypending/pending-confirmation relationships cannot be evicted for a count. Initialize pending forms BEFORE pruning. No persistent/second history manager.

UI is exact Kit0.8.0 public stateless Table/Header/Body/Row/Head/Cell plus Label/Alert and outlined Medium32 Buttons; parent is direct layout, not Toolbar.child ghost/compact adaptation. One original scrollbody and flex-none reachable footer at480x260; no new palette/fonts/clock/animation. Existing details/control/result-location actions remain original owners. Prompt mode takes precedence and clears secrets on original lifecycle. View-to-owner and owner-to-view writes defer, including immediate observation results.

Diagnostics reuse existing sinks/correlation: batch accepted/member finished/batch finished plus explicit retry accepted, original job start/state/terminal elapsed/native code. Once-only terminal metadata suppresses duplicate summary logs; counts are terminal facts, not fabricated overall success. No paths, member names, contents, credentials, request Debug/exception Display or per-frame/chunk/pointer logging.

## 4. Validation & Error Matrix
Invalid batch/capacity/memory -> original atomic rejection/no jobs. Per-item rejected after acceptance -> preserve accepted/not-started counts and reset defer. Prompt -> waiting; pause -> paused; unstarted cancel -> cancelled+notstarted. Native cleanup false/unknown -> held slot, disabled retry. Same original identity/target after safe precommit failure -> new attempt/same member; changed/stale/missing observation -> no replay. Unknown total -> counts only. Newer attempt/session/connection -> old result ignored. No source-set evidence -> no guessed dedup.

## 5. Good/Base/Bad Cases
Good:3jobs produce2original Starts+1queued, one prompt, one paused and queued cancellation are all visible; cleanupunknown retains slot; legal retry keeps batch member count. Base: original single-task progress/controls remains. Bad:3worker attempts counted as3archives, all-cancelled labelled success, clone serial Runner, reuse raw terminal path as new authority, or initialize empty confirmation batch then prune it.

## 7. Wrong vs Correct

## OPT-03 intake, complete output plans and result facts

### 1. Scope / Trigger
Create/Add input and results stay in the original application/form/browser/job owners. Sources: `repo:rust/apps/nxtools-desktop/src/archive/forms_intake.rs`, `repo:rust/apps/nxtools-desktop/src/archive/clipboard_requests.rs`, `repo:rust/apps/nxtools-desktop/src/archive/create_output_plan.rs`, `repo:rust/apps/nxtools-desktop/src/archive/browser.rs`. No second clipboard controller, selection controller or scheduler.

### 2. Signatures
- `PlatformCommand::ReadClipboardFileDrop(ArchiveClipboardCommand)` / `read_clipboard_file_drop`, capability `clipboard_file_drop_read_v1`.
- `PlatformCommand::ArchiveCreateDestination(ArchiveCreateDestinationCommand)` / `archive_create_destination`, capability `archive_create_destination_v1`.
- `ArchiveJobTerminal.add_result: Option<ArchiveJobAddResult>` carries display-only `{total, members:[{path,outcome}]}`. The private worker emits `op:"add_result"`; C# `ArchiveWorkerRunner.ReadFrames` must admit that frame before validating its Add-only committed context.
- `plan_create_outputs` precedes original `submit_form_admitted`; `prepare_add_refresh` precedes original browser `install`; `job_terminal` merges saved Create facts after optional Test.
- `Jobs.edit_forms: HashMap<Uuid, EditFormOrigin>` stores original `{browser:(window_id,generation,snapshot), connection:u64}`. `open_form` captures the connection before constructing the edit form; input and final admission compare it to the current bridge connection, not only to a per-request capture.

### 3. Contracts
Both observation commands use version1, operation UUID, form session UUID and generation>0; destination observation additionally carries the destination. Pending is registered before send, one per form/max8, timeout7s, bound to the original connection. Validate again after deferred delivery. The edit draft itself retains its creation connection through `EditFormOrigin`; replacing the router connection invalidates intake/submission even before the old Disconnected notification is applied. Add also freezes source, browser context/snapshot and internal folder through picker/Paste/submission; compare the typed directory with the model using `trim_end_matches('/')`, not whitespace trimming.

Clipboard response paths are atomic, <=32 and <=131072 aggregate UTF-8 bytes; Add accepts at most31 external roots. Native CF_HDROP accepts borrowed ANSI/Unicode DROPFILES, balances Open/Close and Lock/Unlock, never frees the borrowed handle and does not require Preferred DropEffect. COPY/CUT never authorizes deletion. Text-focused Ctrl+V stays text paste. Remove is draft-only; render never recursively scans sources.

Destination response contains `destination_missing`, `existing_names`, optional code/native error; <=16384 names and <=262144 aggregate UTF-8 bytes. Native held-root enumeration creates no directories/probe files. Before any child admission, reserve disk names, every original requested name and generated names; suffixes start2 and preserve compound extensions. Index normalized disk and ZIP/7z part families once, rather than rescanning the destination for each candidate. Native final target confirmation/per-volume publication remain authoritative. Original `validate_batch` atomically refuses insufficient capacity; any later accepted/not-admitted split remains explicit.

Add results have <=256 members/65536 aggregate path UTF-8 bytes, total>=subset, outcomes `added|overwritten|renamed`; Skip/merged-only directories are not results. Display limits never truncate execution/catalog. Only matching original job/attempt/generation/context plus committed, published and cleanup-complete terminal may refresh. Actual success/warning results map names to new snapshot IDs after install, preserving the folder or nearest ancestor. Confirmed published late cancellation refreshes without success selection or a result summary; the logical outcome remains cancelled. Descendants may select their visible containing directory. Official Small Alert reports total/subset; no names or paths enter diagnostics.

Create location is captured from held committed output before disposal: ordinary target, split ZIP `.zip`, split7z `.001`. Optional Test consumes that confirmed primary through original native source admission. `job_terminal` preserves Create counts, commit state, journal, publication/location; cleanup is the conjunction of both attempts, elapsed is saturating addition, and Test outcome/code remains. Disconnect during running Test retains the original cleanup-held slot and saved Create facts. A location is private presentation data, never execution authority.

### 4. Validation & Error Matrix
Clipboard malformed/overflow -> whole-list failure, no partial append. Empty HDROP -> empty success. Destination missing -> empty observation/no mkdir; invalid ancestor/access/reparse/budget -> whole failure. Timeout/native failure/malformed reply -> original retryable form; retired form/old connection/late result -> no admission. Changed Add folder/snapshot -> no append/submission/refresh. Missing confirmed Create location -> `created_result_location_unavailable`, no guessed Test source. Unknown publication or cleanup -> no Add refresh/unsafe retry/slot release.

### 5. Good/Base/Bad Cases

Base: ordinary single-output Create keeps its original overwrite confirmation and strict internal-member rules; missing/null optional Add result remains compatible. Bad: truncate301 actual Add results to256 business members, reuse old ordinal71 in a new snapshot, or let Test's `output_published=false` erase Create's publication.

## Scenario: OPT-07 unified surface and protected consent
### 1. Scope / Trigger
Original batch/single Test or ordinary Extract presentation, password decisions, Retry and Locate. Evidence: `repo:rust/apps/nxtools-desktop/src/archive/batch_jobs.rs`, `repo:rust/apps/nxtools-desktop/src/archive/progress.rs`, `repo:rust/apps/nxtools-desktop/src/archive/job_location.rs`. Native secret storage follows [PlatformHost workflows](../../platformhost/archive-workflows.md); browser/intake follows [browser workflows](archive-browser-workflows.md).
### 2. Signatures
`Jobs::{defer_pump,defer_presentation}` are separate staging facts. `show_job` projects one original `JobProgressView`; `BatchMember` carries logical ID, active attempt and generation. Summary Stop calls `request_job_stop(id,attempt,generation)`. `batch_password_eligible(id)` reads original records; `reply_job` validates before clearing the current prompt. `BatchRecord.password_retired`, `retire_batch_password` and `finish_batch_if_terminal` are once-only original lifecycle facts, not a secret cache.
### 3. Contracts
Install batch membership before pumping/presenting members. Deferring a single queued submission's pump must not suppress its window. Summary/details/decision switching retains every simultaneous ticket; background/native close changes presentation only. Two-running/FIFO/source serialization, cleanup-held slots, original Stop ACK/acquired-pause/decline and local queued Stop remain unchanged.

Password reuse starts unchecked on each original Dialog. Read eligibility at render, confirmation and reply admission: generation1, Test/ordinary Extract, one path, no reclamation, original unretired batch, live noncancelling member and no pending Cancel. Invalid consent leaves the current ticket intact and sends nothing. Explicit Retry retires the whole batch's password reuse before generation2 Start, including active siblings; a late reply cannot recreate it. Wire/default/native isolation is in the owning protocol/PlatformHost contracts. Rust stores no retained password candidate.

An already-checked password choice that becomes ineligible refuses `Dialog::on_ok` before constructing `PrivatePassword`, clearing InputState, closing the Dialog or deferring a reply. Keep that same ticket/input/checked Checkbox reachable with the original Field description; only an explicit uncheck permits an ordinary member-only answer. Do not encode failed consent as `remember_batch_password=false`. The final `reply_job` eligibility and one-use ticket guards remain authoritative.

Single Test/full Extract collects its initial native baseline through the same preterminal observation owner as batch members. Keep immutable first baseline, affirmative zero publication, zero committed/skipped, actual cleanup and fresh explicit receipt/attempt/session/connection-bound recheck. No Create/Modify/selected/HZ5/post-Test/unknown/published/unclean replay. Member terminal and final confirmation-form cancellation share one finalizer, including an all-cancelled batch with zero Jobs. No invented aggregate success.

`worker_state: Option<ArchiveJobState>` belongs to the current attempt: clear it at Retry generation transition and original dispatch. A reserved member with no current worker state is Admitting, including after a successful Start receipt; only matching current Started/state events advance it. Queue-not-running remains Queued. `ever_started` remains logical history for `never_started`, never current Running authorization. Pump the original queue before capturing the retry's deferred progress/batch snapshot, so rendered and direct owner projections agree.

Manual Locate requires actual native result location plus actual cleanup on Succeeded/SucceededWithWarnings; automatic location remains Succeeded-only. `prune_retired_jobs` protects both `location_pending` and `auto_location_waiting` until original receipt/timeout/clear, alongside active/cleanup/retry/form protection. Requested destination/cache/drop paths never become result facts.

Keep Kit0.8.0 original Root/window, stateless Table/Progress and direct Medium outlined Buttons, one bounded scroll body/fixed reachable footer. Password uses `Checkbox::on_click`, stable masked Input and original ticket/focus owner. Cross-entity writes defer even on cache-hit paths. Existing correlated accepted/state/terminal and once-only batch events carry counts/elapsed/native codes, never secrets/paths/payload/request Debug.
### 4. Validation & Error Matrix
| Condition | Result |
| --- | --- |
| Two members await different tickets | Switch original detail; answer only the selected current ticket once |
| Queued Stop / running summary Stop | Local cancellation / original confirmation and acquired-pause owner |
| Generation2, retired sibling or invalid remembered reply | No reuse/retention; current prompt preserved on refusal |
| Checked consent expires while the same Dialog remains open | Refuse before copying/clearing/closing/sending; preserve ticket/input/choice; explicit uncheck allows one ordinary reply |
| Retried historical-started member dispatched / receipt / old Started / current Started | Admitting / Admitting / Admitting / Running; historical never-started count unchanged |
| Last pending form cancelled, zero Jobs | One truthful cancelled aggregate and password retirement |
| Pending native Locate under retirement pressure | Keep original Job until actual receipt/timeout/clear |
| Missing/late baseline or unknown publication/cleanup | No Retry; original form/reopen remains available |

Base: a single queue-deferred Job still opens the original progress window. Bad: direct summary Cancel, prompt removal before consent validation, or evicting a Job while its Locate receipt is pending.
