# Archive extraction metadata native boundary

Evidence: `repo:csharp/NxTools.PlatformHost/Windows/Archive/ArchiveOutputMetadata.cs`, `repo:csharp/NxTools.PlatformHost/Windows/Archive/ArchiveMotw.cs`, `repo:csharp/NxTools.PlatformHost/Windows/Archive/ArchiveOutputSession.cs`, `repo:csharp/NxTools.PlatformHost/Windows/Archive/ArchiveWorkerOutputBridge.cs`, `repo:csharp/NxTools.PlatformHost.Tests/ArchiveMetadataTests.cs`.

## Scenario: Bound mtime/attributes and fixed source MOTW

### 1. Scope / Trigger
Extraction-only native metadata restoration,not general path/ADS tools. Rust owns format/time semantics; C# owns Windows calls,protected original source and live owned ordinary final-name output. Read [Rust contract](../nxtools-archive/backend/extraction-metadata.md), [ordinary output alignment](../../tasks/11-02-archive-workflow-optimization/ordinary-extraction-output.md) and the task source evidence first.

### 2. Signatures
`ArchiveExtractOptions(bool CopyMotw = true)` is admission-snapshotted/extract-only. Ordinary `commit{token,metadata}` is the sole file-metadata/close action; Rust retains metadata until it. `directory_metadata{path,metadata}` retains existing layout authority. `ArchiveOutputMetadata.Parse(JsonElement)` rejects unknown/duplicate/missing fields and raw masks. `ArchiveSourceLease.CaptureZoneIdentifier()` reads once; `ArchiveOutputSession.BindZoneIdentifier(ReadOnlyMemory<byte>?)` stays host-only. Only fixed `:Zone.Identifier`,maximum65536bytes.

### 3. Contracts
- Ordinary file order: drain all earlier <=32KiB original-pipe records for the token -> fail with sticky first native write error/code when present -> write bounded fixed ADS -> SetFileTime -> read/merge readonly+hidden via FILE_BASIC_INFO -> verify required observed metadata -> close final-name handle -> record completion. This is an ordering barrier,not `FlushFileBuffers`; there is no output hash/file-ID fingerprint,final rename,published reopen or per-file VerifyDirectory. Exact observed mtime must match requested native precision; API success alone is not restored metadata.
- DOS calendar uses local historical zone only when valid/unambiguous. FILETIME/Unix UTC never converts through local. No metadata mutation after close.
- ADS opens relative to the live final-file handle and verifies same volume/full128-bit ID only for ADS binding; that ID is not retained as an ordinary output fingerprint or rollback credential. Source read share-read denies concurrent ADS writers during capture. Read exact length plus extra byte/recheck; bytes zeroized on lease disposal. Never transmit ADS bytes to Rust/business frames/logs.
- Query GetVolumeInformationByHandleW on the held object; FILE_NAMED_STREAMS0x40000 absence is motw_not_supported,not missing ADS. Do not invent native error50 for a successful capability query. Explicit false does no source ADS read/target ADS write/capability query. Compound provenance is original compressed archive,not spool.
- Track actual exclusive directory creation; preexisting/raced-existing directories are layout-only. New explicit directories finalize deepest-first after files,no recursive rollback. Directory failure after earlier file closes retains true completed counts; cancellation reports completed output when appropriate.
- On commit/metadata/close failure,close and delete only that incomplete owned final-name output,including a directly truncated overwrite once it is opened as the current output. Delayed solid/format integrity may keep a bounded set incomplete and deletes only that set. Successfully closed files/finalized directories and skipped pre-existing targets remain; no hash scan,global rollback,retry/backup/delete-first/fallback.
- Diagnostics use the same operation ID,elapsed/native code,source motw_captured/absent/disabled and coalesced metadata/close/directory stages. The stdout pump has already consumed earlier payload before `session.Commit`; `native_commit_ms` therefore measures only the native metadata/handle-close call, while Rust `output_close_wait_us` covers the full await including queued payload consumption. Ordinary fingerprint/postpublication durations are zero. First exact failing native call owns terminal code/category. Throwing sink cannot affect output. Never log names/paths/ADS/URLs/raw exceptions or chunk events.

### 4. Validation & Error Matrix
Absent ADS -> successful no-mark; empty ADS -> exact empty stream. Over65536 -> motw_budget. Capability unsupported -> motw_not_supported; native errors1/50/120 preserve actual code. Read/write rejection -> motw_read_failed/motw_write_failed. Time/attrs rejection -> metadata_time_failed/metadata_attributes_failed with original native code. SetFileTime success/no-op or precision mismatch -> metadata_time_not_supported. Invalid typed JSON/local ambiguity -> metadata_invalid/metadata_local_time_ambiguous. Failure before close deletes only the incomplete owned final-name output; failure after earlier closes preserves those journal facts.

### 5. Good/Base/Bad Cases
Good: independent file-info/ADS oracle checks the published object and source preservation. Base: original source without mark, legacy caller default-on, explicit disabled. Bad: mutable DOS source reopen, arbitrary ADS name/raw attribute worker authority, readonly before ADS writes, or directory failure claiming FailedBeforeCommit after files published.

### 6. Tests Required

Keep per-format time/attrs,nested/preexisting dirs,default/options/budget/absence,capability flag injection without volume changes,source lease,native denied/unsupported,metadata-stage cancel,overwrite/no-replace,readonly incomplete-output cleanup,external metadata retention,prior completed facts and throwing-log/privacy regressions. Add final-name/no-partial/rename/flush/fingerprint/reopen,commit-carried metadata and incomplete-only cleanup coverage. Run the precise C# fixture selection with zero skips when authorized; source gates/compilation are not native/Phase A/release acceptance.

### 7. Wrong vs Correct
Wrong: missing stream on a non-ADS filesystem means no MOTW,metadata is applied after reopen,or cleanup hashes earlier completed output. Correct: held-volume capability -> fixed identity-bound bounded capture -> Rust-carried commit -> same open final handle MOTW/time/attrs -> observed metadata -> ordered close -> incomplete-only delete on failure.
