# NxTools.Next 全应用 UI 布局品质重规划

## 1. 目标与本次审批边界

重新规划整个应用的视觉结构，使其具备接近 Zed 的**清晰排版、稳定对齐、克制层级、可阅读密度和完整交互状态**。不再以换配色、统一 token 或测试通过代替视觉品质。

**本次批准后执行：设计盘点、完整设计文档、页面线框、可交互设计原型与原型检查。暂不迁移生产 GPUI 页面、不打包。** 原型呈现后由用户确认方向，再提交具体源码实施范围。之前局部全局设置修正只是现状样本，不自动成为全应用标准。

## 2. 已核对的现状与问题

- 主窗口默认 1060×650、最小 920×480；已有 208px 主导航及多种模块内导航。
- 下载主要是任务工作区；速启和剪贴板主窗口页面主要是配置管理，实际使用发生在独立弹窗。它们不应被伪装成相同的仪表盘。
- 已有字体、尺寸、组件与生命周期测试，但组件默认字号、局部布局和重复说明仍会破坏视觉一致性。
- 19:30 安装包的全局设置布局被用户明确否定。最近的左导航/列对齐修正尚未获得全应用视觉验收，也未进入该安装包。
- 已查看 Zed `ButtonLike`、`ListItem` 及本项目参考索引。借鉴组件状态、连续工作面和信息层级，不复制编辑器功能，不认为本项目拥有 Zed 的无障碍 API。

## 4. 统一设计方向

### 4.1 不以换色推进

保留现有石墨色体系和已选定的蓝色动作/焦点角色：`#18181b`、`#1f1f23`、`#121215`、`#27272a`，强调色 `#38bdf8`。只检查角色是否使用正确，不另做主题或大面积强调色。

### 4.2 字体与阅读密度

- 主工作区原型以 **正文/操作 13px、行高 20px；辅助信息 12/18；页面标题 16/24；分组标题 14/20** 作为待验证方案。
- 固定小窗口另使用紧凑档，以现有 12/18 正文为基线，不机械套用主工作区尺寸。
- 普通中文信息不再挤进 10/11px 元数据档；更小字体只用于真正次要、非关键的元数据，必须检查原尺寸可读性。
- 首轮保留 Microsoft YaHei UI；等宽字体只用于命令、哈希等必要内容。若更换字体有收益，必须提供同尺寸原生对照，不猜测字体能解决所有问题。
- 原型比较后再冻结具体值并同步批准规范，不能仅因新数值“更整齐”就直接修改生产 token。

### 4.3 对齐与空间

- 文本、应用名、设置标签左对齐；数字列按列职责对齐；勾选框与功能表头中心对齐。不是所有内容都居中。
- 同一工具栏/表单组共用控件高度与文字中心线。表格表头、数据行和编辑行共用列定义。
- 使用 4px 间距网格；区分控件内部、同组元素和跨组空间，禁止页面随意叠加 padding。
- 默认连续工作面与必要分隔，不做卡片墙、装饰渐变、无意义阴影或用空白掩盖结构问题。
- 主导航提供可见模块名称，不只放图标；去掉每次使用都重复的模块说明。原型以约 176px 导航宽度比较当前 208px，最终由最小窗口与中文阅读验证确定。

## 5. 三类布局与页面蓝图

### A. 工作区：操作对象优先

```text
┌ 标题栏：产品与窗口操作 ───────────────────────────┐
│ 模块导航 │ 页面标题 / 必要状态          主要操作 │
│          │ 搜索 / 筛选 / 排序（同一操作带）       │
│          │ 连续列表或任务表                      │
│          │                                     │
│          │ 按需详情 / 多选操作（有需要才出现）    │
└──────────┴─────────────────────────────────────┘
```

下载保留连续任务表和按需详情，不为了“统一”换成卡片或新增数据概览。名称列优先、状态/进度列稳定；长内容不能挤走操作。

### B. 设置：分类与阅读顺序优先

```text
┌ 标题栏 ─────────────────────────────────────────┐
│ 分类导航 │ 标题 + 一句必要说明                  │
│          │ 设置分组                             │
│          │ 标签 / 描述              控件         │
│          │ 列表及编辑器（确有需要时）            │
├──────────┴──────────────────────────────────────┤
│ 与当前保存语义一致的反馈          次要 / 主操作 │
└─────────────────────────────────────────────────┘
```

速启、剪贴板、下载和全局设置共享布局语法，不强行合并为一个巨大设置窗口。保留各自原有即时生效或草稿保存语义，不为了统一页脚引入新的 Apply/Cancel 行为。

剪贴板当前两大列配置重新按任务分组，避免长说明和横向控件互相挤压。逐应用黑名单保留独立两列规则，编辑区与表格对齐。

### C. 快速操作：当前动作优先

速启以搜索、结果与必要快捷操作为中心；剪贴板以分类、搜索、历史为中心；下载小窗口以当前阶段内容和稳定操作区为中心。辅助预览保持被动，不改为抢焦点的详情窗口。菜单、错误和加载在所属界面内明确呈现，不产生新的布局跳动。

## 6. 必须保留的产品与原生边界

- Rust 负责状态/布局，GPUI 渲染，C# 负责 Windows API；不以样式重做业务或 IPC。
- 保留已认可的新建下载固定交接：普通 560×176 → 新 560×278；媒体预算分别核对。
- 保留普通下载中/完成 440×184、同窗口内容转换，不再引入无意义的 resize；不同尺寸阶段仍保持现有原生居中所有权。
- 保留速启查询代次、结果动作、前台宿主、焦点返回、菜单与文件对话框生命周期。
- 保留剪贴板 300×440 默认面板及可调整尺寸策略、粘贴/复制区别、历史分页、选择和单一被动预览。
- 保留全局逐应用黑名单、原子保存、下一轮应用更新、取消/失败草稿与 Windows 已保存/已应用区别。
- 保留单一键盘激活边界、延迟跨 entity 更新、noactivate、隐藏窗口最终定位再显示及减少动效策略。
- 无障碍 provider 能力缺口继续明确标注；不升级依赖、不修改 vendor、不跨进程注入 provider。

## 8. 原型必须证明的内容

代表原型至少覆盖：
1. 下载主工作区：正常任务、长名称、选中详情与多选状态。
2. 速启设置：普通表单及自定义命令列表/编辑器。
3. 剪贴板设置：行为、保留/隐私与存储的层级。
4. 全局设置：逐应用规则、编辑、空表与错误。
5. 速启弹窗：搜索、结果、动作模式。
6. 剪贴板弹窗：分类、搜索、历史和编辑状态。
7. 固定下载小窗口：已保留的各阶段内容预算。

工具、菜单、通知、预览与扩展至少提供完整线框及组件状态板，不用一张主窗口截图代表全部界面。

原型支持页面切换、尺寸切换、长内容/空/加载/错误/禁用状态、选择与表单动作演示。示例数据为合成数据，不能承诺浏览器原型已经证明 GPUI 字体渲染或原生窗口行为。

## 9. 验证与审批标准

设计阶段：
- 1060×650 默认与 920×480 最小主窗口方案都能说明布局，不靠减小字或放大窗口过关。
- 固定弹窗按照各自实际预算展示，不用超大画布伪装可容纳。
- 原型按 1:1 CSS 尺寸检查与截图；浏览器缩略图不作为文字可读性证据。
- 每页检查五项：阅读顺序、字体层级、横向/纵向对齐、主次操作、长内容与状态稳定性。
- 文档运行 `python tests/architecture/spec-contracts.py`、`git diff --check`；原型检查切换、键盘及溢出。设计阶段无需 Cargo。
- 用户看到真实原型后确认方向，才冻结具体数值并进入生产实施。

后续生产迁移仍按原阶段顺序：**Foundation → Downloads → Quick Find → Clipboard + Tools → Global settings + supporting surfaces**。每个切片先参考行为与 red-capable 回归，再实施并检查真实 GPUI 渲染；原生100/125/150%与安装版验收独立记录。测试全绿只是功能门禁，不能替代视觉验收。

## 10. 不包含与仍需后续授权的操作

这次不修改生产 Rust/C#/扩展逻辑，不 Cargo 构建、不生成安装器、不启动普通产品、不读取用户配置/剪贴板数据、不扫描卷、不操作 Indexer 或 DOpus、不提交/重置工作区。打包、安装、真实数据与服务验证仍需单独授权。

没有当前阻止设计的技术问题。字体密度的最终数值、全应用视觉方向和原生 DPI 品质仍需通过原型及后续实际 GPUI 对照确认，不能预先宣称达到 Zed 品质。
