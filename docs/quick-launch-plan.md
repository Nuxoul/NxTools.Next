## 产品形态

“速启”是独立的按需 GPUI 弹窗，不是主窗口中的搜索页面。全局热键负责呼出或隐藏，键盘完成查询、
选中与执行，失去外部焦点时隐藏并保留进程。主窗口只提供热键、索引范围、排除规则、历史、性能与
诊断设置。

第一条开发原则是每个阶段都交付可实际使用的纵向切片，不先制作无法执行动作的展示界面。

## 模块与职责

### Rust：性能核心

1. `nxtools-finder`：一个深模块，接口只暴露 `search`、`record_activation` 和索引状态；实现内部负责
   查询解析、模糊匹配、分组、排序、历史权重与排除规则。
2. `NxTools.Indexer.exe`：读取 NTFS MFT/USN，构建内存映射快照和增量覆盖层，处理查询取消与结果批次。
3. `QuickLaunchApplication`：拥有弹窗会话、查询代次、选中项、动作编排和持久化，不把领域状态放进视图。

### C#：Windows 适配器

1. 注册/暂停速启全局热键，采集前台 HWND、焦点 HWND、鼠标位置和显示器信息。
2. 执行 Shell/COM 动作：打开、定位、管理员运行、解析快捷方式、提取系统图标。
3. 后续提供资源管理器、打开/保存对话框和第三方文件管理器的上下文适配。
4. C# 不保存索引、不解析查询、不参与排序。

### GPUI：视觉渲染层

1. 独立紧凑弹窗、输入框、虚拟化结果列表、分组标题和动作菜单。
2. 键盘优先：上下选择、Enter 打开、Ctrl+Enter 定位、Escape 清空/隐藏。
3. 只在出现、消失和选中变化时做短动画；空闲状态不持续请求帧。

## 关键接口与 seam

### 桌面进程 ↔ 索引进程

- `SearchRequest { generation, query, limit, context }`
- `SearchBatch { generation, items, complete, elapsed_us }`
- `IndexStatus { phase, indexed_items, drives, last_error }`
- `RebuildIndex / UpdateIndexSettings / Shutdown`

查询代次是接口不变量：旧查询的迟到批次必须被丢弃，绝不能覆盖新查询结果。

### Rust ↔ Windows 适配器

- 平台事件只描述“用户请求呼出”和当前 Windows 上下文。
- Rust 发出 `Open`、`Reveal`、`RunElevated`、`SwitchDirectory` 等动作意图。
- 所有命令保留关联 ID、目标 HWND 和可诊断结果。

### 阶段 1：可用的应用启动器（4–6 天）

- 新增默认双击 Ctrl（可配置组合键）的全局呼出手势和独立 GPUI 速启弹窗。
- 索引开始菜单、桌面快捷方式和安全的系统工具；支持普通模糊搜索。
- 支持键盘选择、打开、资源管理器定位、Escape/失焦隐藏和再次呼出复用。
- Rust 记录启动次数与最近使用时间，排序能随使用行为变化。
- 主窗口展示热键、应用目录扫描状态和诊断，不承载实际搜索交互。

完成标准：从任意应用按热键，输入程序名并按 Enter 能可靠启动目标；关闭弹窗不会退出程序。

### 阶段 2：本地文件与文件夹索引（8–12 天）

- `NxTools.Indexer.exe` 实现 NTFS 卷发现、MFT 初始快照、USN 增量和异常重建。
- `nxtools-finder` 支持多词、排除、精确、前缀、后缀、盘符和路径模式。
- 搜索结果分批返回，输入变化立即取消旧查询。
- 增加索引范围、排除目录、重建和错误恢复设置。

完成标准：百万级条目数据集上不存在主线程扫描；文件创建、重命名、移动和删除能增量反映。

完成记录：独立索引服务、真实 NTFS 卷发现、MFT 初始只读快照、父链路径重建和文件结果合并已接通；
MFT 基线已使用不可变版本文件和内存映射恢复，USN 游标、替换与删除通过配套 delta 跨重启保留。
创建、重命名、跨目录移动和删除会原子发布到后续查询；覆盖层超过阈值时先发布最新增量，随后在后台压实，
压实期间最后可用快照仍可搜索，只有 USN 游标一致的结果才会原子替换。
压实失败按卷从 5 秒指数退避到 5 分钟并上报状态，不会延迟其他卷的 1–8 秒 USN 轮询。
Journal ID 变化、游标过期或畸形记录不会发布半成品，而会触发完整快照重建。普通权限 Rust/GPUI
桌面通过受 ACL 限制的本机命名管道连接 LocalSystem 索引服务，C# 仍只负责一次性 UAC 安装/SCM 启动。
查询支持多词、排除、精确短语、前缀、后缀、OR、盘符、路径、直接子项、父目录选择和临时绕过排除；
索引卷与排除目录由 Rust 配置持久化并同步到索引服务，相同设置重连不会触发重建。
服务端采用临时文件、落盘同步和 last-good 轮换；主/备配置均损坏时先关闭索引范围，等待桌面端重新同步，避免意外退回全盘索引。
局部重建按卷合并快照与错误状态，一个卷恢复不会清除其他卷尚未解决的错误。

### 阶段 3：动作与预览（4–6 天）

- 动作菜单：打开、定位、复制路径、管理员运行，并在其后合并目标自身的 Windows Shell

### 阶段 4：Listary 式上下文导航（8–12 天）

- 识别资源管理器、桌面、原生打开/保存对话框的当前路径和目标窗口。
- 支持快速切换目录和最近目录；不提供收藏目录，也不自动确认文件对话框。
- 高权限目标通过同权限适配器执行，普通桌面进程不整体提权。

完成标准：资源管理器、文件对话框及受支持第三方文件管理器中的导航行为均有独立生命周期测试和
真实交互验证。

首个纵向切片：从既有 Windows 资源管理器呼出速启后，目录结果的动作菜单出现“切换到此目录”；
执行时使用呼出瞬间冻结的 Explorer HWND，在该窗口内导航，不新开窗口。普通打开、定位行为不变。

第二个纵向切片：从 Windows 原生打开/保存对话框呼出后，使用严格结构识别冻结其顶层 HWND；目录
结果复用“切换到此目录”，文件结果则只切换到其父目录；由 C# 在该对话框内写入并提交最终目录，
恢复原对话框焦点以支持连续切换，绝不把文件结果作为 Open/Save 提交。
文件结果不会自动确认打开/保存，普通 `#32770` 弹窗不会被误识别。

第三个纵向切片：从真实 Shell 桌面呼出时冻结 `Progman` 或带 `SHELLDLL_DefView` 的 `WorkerW`，
并将用户桌面目录作为上下文；桌面不能像 Explorer 一样 `Navigate2`，因此目录切换由 C# 交给
Windows Shell 打开目标目录。Rust 在目录打开/切换成功回执后持久化有界、去重的最近目录；只有
存在导航宿主和历史时，折叠搜索栏右侧才显示历史入口，默认呼出仍不自动展开结果。最近目录列表
支持过滤、键盘/鼠标选择、滚动和直接切换。Escape 或再次按呼出热键会在隐藏面板后恢复本次呼出
捕获的宿主 HWND，确保下一次双击 Ctrl 仍能重新获得目录上下文；外部点击和成功执行动作不抢回旧焦点。

第四个纵向切片：第三方文件管理器统一暴露为 `third_party_file_manager` 目录导航能力，具体
Directory Opus、Total Commander、OneCommander 和 Files 身份识别、活动面板路径采集与原窗切换全部留在
C# Windows 适配器注册表内。每次呼出生成一个有界、过期、成功后即消费的活动面板令牌；即使同一
HWND 连续呼出，也不会被后一次焦点采集覆盖。Rust 只冻结宿主 HWND、当前目录与不透明令牌，并
编排既有 `NavigateDirectory` 动作；GPUI 继续复用同一个“切换到此目录”入口。Directory Opus 和
Total Commander 的消息发送及路径回读、OneCommander/Files 的 STA/UIA 采集和导航全部有硬超时。识别和
导航均为按需操作，不在查询或空闲状态轮询宿主。

第五个纵向切片：高权限 Explorer、原生文件对话框或受支持第三方文件管理器不要求 Rust/GPUI
桌面整体提权。普通 C# 主机建立随机、仅当前用户可访问的管道与 256 位令牌；LocalSystem 索引
服务从已连接管道句柄取得真实桌面 PID/会话，只接受管理员部署到受保护目录的 `NxTools.exe`，
再通过该会话的关联高权限令牌在交互桌面启动固定的 `NxTools.PlatformHost.exe` 辅助模式。
安装时从拒绝写入/删除共享且拒绝重解析点的源句柄复制 Indexer、broker PlatformHost 和桌面，
逐级加固 `%ProgramData%\NxTools\NxTools.Next\Service` 的父目录、所有者和精确 DACL，仅允许
SYSTEM/Administrators 写入；SCM、broker 和特权请求都不执行或信任可写的发布目录。安装成功后
发布目录中的启动器会自动切换到字节一致的受保护桌面副本。UAC 已授权的 PlatformHost 在入口
锁定自身映像，构建流程把 Rust Desktop/Indexer 的 SHA-256 写入该安装器；提权安装只接受匹配
这份编译期清单的源句柄，避免授权窗口与实际复制之间被替换。
已经从受保护目录运行时，自修复会跳过同源二进制替换，但仍重新验证并修复目录 ACL、三份哈希、
注册表、SCM 与服务状态。
请求不能指定可执行
文件路径，也不使用每次弹 UAC 的 `runas`。辅助进程通过令牌、实际管道客户端 PID、精确程序路径
、同一 Windows 会话、管理员登记的桌面路径及桌面/PlatformHost SHA-256 验证后，才在高权限侧重新
采集冻结 HWND 并创建独立的有界一次性上下文令牌。面板先显示，高权限采集在热键线程外完成，并
携带原始 HWND/请求时间回填；C# 发布前和 Rust 应用前都执行一秒时效检查，迟到结果不能污染
当前或下一次呼出。普通上下文仍走普通适配器；只有
`elevated:` 令牌进入辅助通道。连接、流式帧读取、有限重试、进程启动、COM/UIA 及导航均有硬
超时并在失败时保留速启面板。
Explorer/OneCommander 等可能产生迟到副作用的超时使用强类型 Fatal 回执；辅助进程发回结果后
退出，普通客户端收到同一标记即作废旧连接并建立新 rendezvous，不让下一次呼出先撞一次死管道。
同名 UIA 操作在旧工作线程真正退出前不再创建第二条线程，第三方宿主令牌的消费、过期与容量淘汰
同时移除顺序节点，避免长驻进程积累后台线程或隐性队列。

第六个纵向切片：自动快速切换只在 C# 观察到“已知文件对话框 → Explorer → 同一个文件对话框”
这一轮前台转换后触发。首次发现对话框不跳转；一次 Explorer 路径只消费一次；禁用功能、宿主变化
或异步采集代次过期会立即作废候选。C# 只采集精确 HWND 与 Explorer 当前路径并发布事件，Rust
检查设置、事件时效和宿主类型后复用既有 `NavigateDirectory`，不在前台钩子中直接执行导航。

第七个纵向切片：受支持的原生打开/保存对话框显示时，C# 发布其精确 HWND、当前目录、物理像素
边界和 DPI；Rust 复用单个无激活 GPUI 附着窗口，在对话框底部显示紧凑搜索栏。
实际交互核对 Listary 后修正为查询全局索引、仅用当前目录做排序加权；目录结果执行精确对话框导航，
文件结果通过独立的 `OpenFileInDialog` 意图写入完整文件路径并提交。搜索窗口以原对话框为 owner，
创建时一次性使用 `TOPMOST + NOACTIVATE` 保证首次可见，后续通过 `NOZORDER + NOACTIVATE` 的
原生快路径随移动、缩放、隐藏和销毁更新，不在 C# 绘制 UI，也不把查询和排序移入 Windows 适配层。
功能和自动快速切换均可在主界面独立关闭。

- 应用目录首批结果目标：P95 不高于 30 ms。
