## 2. 现状评估

按 Nielsen 启发式与 Krug 原则做的快速诊断（满分 10，仅针对主窗口与弹出面板的交互，不含视觉审美）：**约 7/10**。

做得好的部分：

- 模块壳一致：36px 标题栏 + 176px 侧栏 + 48px 模块头部，跨页面不跳动。
- 状态区分细：空库 / 筛选无结果 / 搜索无结果三种空状态分开（`download_page.rs:1289` 起）；错误不伪装成空。
- 操作反馈统一走 NotificationCenter，校验失败保留草稿。
- 速启结果编号快捷键（Ctrl+1…）、右键进入操作模式、预览被动不抢焦点。
- 危险操作（空间回收解压）有独立确认，按钮文案说清后果。

主要扣分点（详见第 3 节）：

| 诊断项 | 结论 | 严重度 |
| --- | --- | --- |
| 系统状态可见 | 批量操作无进度、钩子失效无提示、索引重建原因不可见 | 3（与 H1/H2/H4 同根因） |
| 错误预防 | 同名下载可静默覆盖（M2） | 3 |
| 导航是否自明 | “剪贴板”“速启”点进去是设置页，侧栏把工作区和设置混成一组 | 2 |
| 高效使用 | 主窗口几乎无键盘快捷键（下载列表无 Ctrl+A / Delete / Ctrl+F / Ctrl+N） | 2 |
| 识别而非记忆 | 速启操作模式只能靠 → 或右键进入，界面无提示 | 2 |
| 一致性 | “下载计划”用历史图标；标题栏与模块头部重复显示模块名 | 1 |

## 3. 方案

### P0：代码缺陷对应的用户可见体验（随缺陷修复一起做）

这些不是外观调整，而是缺陷修复时必须同时补上的反馈，否则修好了用户也看不到。

**U1 批量操作的进度与确认（对应 H1）**

- 现状：`batch_action`（`downloads.rs:1248`）在 GPUI 线程同步执行，结束后只在有失败时弹通知；大批量时界面卡住，修复 H1 后也仍然没有中间反馈。
- 方案：
  - 批量删除/取消超过一个阈值（建议 20 项）时，沿用现有删除确认对话框，标题写明数量（“删除 128 个下载任务”）。
  - 执行期间多选操作条按钮进入 Loading 状态并禁用，防止重复提交；完成后通过现有通知给出“已删除 128 项 / 3 项失败”，失败项可“仅选中失败项”。
  - 引擎改为异步执行后，列表依赖 `SnapshotRequired` 刷新，不逐条闪动。
- 组件：现有 `delete_confirmation`、Button loading/disabled、NotificationCenter，无新控件。

**U2 同名文件冲突提示（对应 M2）**

- 现状：重试失败任务可能覆盖他人已完成的同名文件，没有任何提示。
- 方案：提交阶段返回 `DestinationExists` 时，在任务窗口失败态显示冲突原因，并提供“自动重命名后重试 / 覆盖 / 取消”三个动作；“覆盖”为危险样式、需二次确认。默认动作是自动重命名。
- 参考：先对照 AB Download Manager 与旧 NxTools 的冲突处理再定交互（AGENTS.md 要求）。

**U3 全局热键健康状态（对应 H4）**

- 现状：低级键盘钩子被系统移除后，双击 Ctrl 静默失效，能力标志仍显示可用。
- 方案：PlatformHost 能检测到钩子失效后（H4 修复的一部分），速启设置页的“唤起方式”行显示 Alert（“双击 Ctrl 已失效”）和“重新启用”按钮；同时发一条通知。只报告状态变化，不轮询、不刷日志。

**U4 索引状态说明重建原因（对应 H2/H3）**

- 现状：重建期间结果可能不完整，用户只看到“索引中”。
- 方案：速启设置页“索引”页的卷状态行区分“首次建立 / 正在重建（原因：大量文件变动）/ 就绪”，重建期间结果列表底部显示一行“索引更新中，结果可能不完整”。按 AGENTS.md，last-good 快照可搜索时的 `RebuildRequired` 属于维护状态，不显示为错误。

**U5 浏览器扩展只响应真实用户手势（对应 M1）**

- 方案：内容脚本忽略 `isTrusted=false` 事件。用户可感知的变化只有一处：网页脚本触发的“自动下载”不再直接进入 NxTools，而是走浏览器原生下载拦截路径（仍会被接管）。无界面改动。

### P1：信息架构与导航

**U6 侧栏分组：工作区 / 弹出工具**

- 现状：`shell.rs:301` 只有一个 `SidebarGroup::new("工作区")`，六个模块并列：下载、速启、剪贴板、扩展、压缩、其他工具。其中下载、压缩是真正的工作区；速启、剪贴板、其他工具点进去是弹出功能的设置页；扩展是管理页。用户点“剪贴板”期望看到历史，实际看到设置。
- 方案：用同一个官方 Sidebar 拆成两组，顺序与焦点所有者不变：
  - **工作区**：下载、压缩
  - **弹出工具**：速启、剪贴板、其他工具
  - **扩展**：扩展（独立一组，或并入“弹出工具”后面）
- 代价：只改分组与顺序，`FocusedModuleButton` 焦点/Tab 回归需重跑；2026-10-15 用户要求“扩展紧跟剪贴板、位于其他工具之上”，若保持该顺序，扩展留在第二组中间。**需要你确认分组与顺序。**

**U7 弹出工具设置页增加“打开面板”入口**

- 现状：速启、剪贴板设置页没有从主窗口直接打开对应面板的入口，新用户只能记住快捷键。
- 方案：两个页面的模块头部右侧加一个 outline Button：“打开剪贴板面板（Alt+C）”/“打开速启（双击 Ctrl）”，按钮文案包含当前实际绑定的快捷键（读取配置，热键改了文案同步变）。点击走现有唤起命令，与热键唤起同一路径。
- 组件：官方 Button outline Medium，放在 `Toolbar.content` 中以保留边框（遵循组件选择规则第 21 条）。

**U8 去掉重复的模块名**

- 现状：标题栏显示“NxTools · 下载”（`shell.rs:156`），模块头部再显示“下载”。
- 方案：标题栏只保留产品名；模块名由头部负责。属于一处文字删除，需用户确认（这是 Trunk Test 中“我在哪”的冗余，不影响定位）。

### P1：键盘效率

**U9 下载工作区快捷键**

- 现状：主窗口唯一的按键处理是热键录制（`main_window.rs:531`）；下载列表没有任何键盘快捷键。
- 方案（先对照 AB Download Manager 与旧 NxTools 的键位，以参考为准）：

  | 键 | 行为 | 复用的现有入口 |
  | --- | --- | --- |
  | Ctrl+N | 新建下载 | `open_new_download_window` |
  | Ctrl+F | 聚焦搜索框 | 现有 `search_input` |
  | Ctrl+A | 选中当前筛选下全部任务 | 现有多选状态 |
  | Delete | 删除所选（走现有确认对话框） | `batch_action` / 删除确认 |
  | Enter | 打开已完成文件；未完成时打开任务窗口 | 现有双击行为 |
  | Esc | 清除多选，再按关闭详情 | 现有清除/关闭按钮 |
  | Ctrl+1…6 | 切换侧栏模块 | `shell.activate` |

- 实现：GPUI `KeyBinding` + key_context（`DownloadWorkspace`），输入框聚焦时不拦截编辑键；动作全部 `cx.defer` 进入原所有者，不在回调里同步更新可能回写的实体。
- 菜单与 Tooltip 显示对应键位（官方 `Kbd`），保证可发现。

**U10 速启操作模式可发现**

- 现状：进入操作模式只能用 →（光标在末尾时，`panel.rs:492`）或右键（`panel.rs:1200`），返回用 ← / Backspace；界面没有任何提示。选中行右侧显示的是 Ctrl+1。
- 方案（不改窗口尺寸）：仅**当前选中行**的右侧提示位从“Ctrl+1”换为“Enter 打开 · → 更多”，其他行仍显示编号键；操作模式标题行（“操作 项目说明与工作记录.txt”）右侧显示“← 返回”。全部用官方 `Kbd`。
- 备选：在 410 高度内加一条 24px 底部提示栏。会占用结果区域，且属于“若当前已有才保留”的约束，**不推荐，除非你明确要**。

### P2：各界面的局部改进

**下载**

- “下载计划…”按钮用的是 `MaterialIcon::History`（`download_page.rs:1149`），语义是“历史”。改为已有的 `MaterialIcon::CalendarMonth`。
- 头部“下载设置 / 下载计划”是 ghost 图标按钮，按组件规则这是安静命令，可以保留；若希望更易发现，改为带文字的 outline Button 需要更多宽度，最小 920 宽下需验证不挤压搜索框。**建议保持现状。**
- 空状态文案“提交真实 HTTP 或 HTTPS 地址”中的“真实”是开发语境用词，改为“粘贴 HTTP 或 HTTPS 链接，或从浏览器直接发起下载”。

**速启**

- 合成截图中首行图标是一个转圈的样式。若这是图标加载中的占位，建议换成静态的类型图标占位，避免列表里出现动画（设计约束：无常驻动画）。需用真实数据截图确认是否为占位。
- 结果少时（3–5 条）下方留白很大。改为内容自适应高度需要改原生 410 预算与 C# 定位，**本方案不建议**，列为待讨论。

**压缩（与进行中的 `10-30-archive-flow-ux` 合并，不另起任务）**

该任务的 `design.md` 已覆盖：路径改为 InputGroup + 浏览按钮、输入有效前不显示空间预检表、密码与高级选项渐进展开。补充两点：

- 继续空间回收解压“已完成”状态（截图 `continuation-completed-light.png`）只剩一个禁用的主按钮。完成后主按钮应换成“打开目标文件夹”，次按钮为“关闭”，而不是让用户面对禁用按钮。
- 确认对话框（`continuation-confirmation.png`）与表单正文重复了同一段不可撤销警告。表单正文保留一行摘要，完整说明只放在确认对话框，降低重复阅读。安全与不可逆说明保留在决策点，符合现有规则。

**浏览器扩展弹窗（对应 L7）**

- 弹窗每 1.5 秒刷新而端口 1 秒释放，导致反复拉起本机 host。体验上表现为连接状态闪动。修复为订阅/更长轮询后，弹窗显示稳定的“已连接 / 未连接（NxTools 未运行）”状态，未连接时给出“启动 NxTools”提示，而不是持续重试。

**剪贴板 / 扩展 / 通知 / 全局设置**

近期已由用户逐项确认（卡片间距、高度上限、图标取色、目录卡片、通知时长等），本方案**不做改动**。

### P2：设计规则治理

- 现状：UI 规则分散在 `ui-design.md`（336 行，按日期累积的修订记录）、`.interface-design/system.md`、`layout-quality/design-system.md`、`ui-remediation-plan.md`。其中 `.interface-design/system.md` 仍写着 208px 侧栏、18/22px 控件高度、项目自定义配色，已被 176px 侧栏、Kit 默认尺寸和官方主题取代，但文件本身没有标注已过时。
- 方案：
  - 在 `.interface-design/system.md` 顶部标注“历史文档，现行规则见 ui-design.md 与 ui-component-selection.md”。
  - 在 `ui-design.md` 开头增加一张“现行规则速查表”（尺寸、主题、侧栏、通知、各弹出面板预算、已否决方案），修订记录保留在下方作为历史。
- 收益：每个 UI 任务都要求先读这些文件；现在需要读完整个修订流水才能知道哪条生效，容易按过时数值返工。
- 运行 `python tests/architecture/spec-contracts.py` 校验文档导航。

## 4. 明确不建议做的事

- 不更换配色或新增主题；不做卡片墙、渐变、大圆角。
- 不在主窗口新增命令面板（Ctrl+K）：全局已有速启，再加一个会形成两个搜索入口。
- 不把剪贴板历史搬进主窗口：剪贴板定位是弹出工具，布局蓝图已明确拒绝。
- 不在没有用户批准时改任何原生窗口预算（速启 410、剪贴板 300×440、下载窗口系列）。
- 不为了统一而把下载头部的安静图标按钮全部换成 outline 按钮。
