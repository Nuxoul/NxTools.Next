# NxTools extension protocol v1 and opt-in v2 once

Status: W6–W9 source implementation and isolated joint acceptance passed. Scripts can be independently enabled after explicit whole-user trust. No installed/native user-data or Release acceptance, malicious-code isolation or rollback of external effects is implied.

Additive API/UX remediation and authoring contracts: [authoring guide](AUTHORING.md), [manifest schema](manifest.schema.json), [method schemas](methods.schema.json). Existing array methods/packages remain compatible. `requires`, action `accepts`, bounded page methods and scoped catalog search are additive; error completions retain bounded UI text, manual `handled` is successful. No deployment/installed acceptance is implied.

## Package, import and trust

Ordinary Desktop import accepts one ZIP package with `extension.json` at root or inside its only top-level folder. Every package-local script/dependency/asset must be listed in top-level `files`. Validation reads/decompresses bounded bytes only; explicit confirmation stages an immutable content-addressed copy into the application-managed extensions directory, including declarative manifests. The source ZIP may then be removed. New imports/replacements remain disabled and untrusted. Root/wrapper ZIP format, safety limits and unsupported variants: [ZIP import guide](../../.trellis/tasks/10-15-extension-zip-import/usage.md). Legacy lower-level declarative JSON and directory APIs remain compatible; standalone declarative schema is shown in `examples/commands.json`.

Script runtime `program`: `python`, `powershell`, `pwsh`, `node`, or `exe`. Opening environment/trust automatically probes PATH for an unconfigured interpreter using fixed version arguments and bounded ordinary-user Jobs. Existing defaults/overrides take priority; explicit invalid selections never silently fall back. Discovery only updates a draft/informational candidate, not trust or enablement. Explicit trust re-inspects the exact executable/hash and checks current selection/content inside the original locked transaction; an unconfigured detected candidate becomes its package override only upon approval. Run Environment still supports manual/virtualenv paths and explicit Save/Cancel. The host never downloads interpreters/dependencies or changes system PATH. Effective selection changes revoke affected approval and disable; EXE stays staged. Python runs unbuffered; PowerShell uses `-NoLogo -NoProfile -NonInteractive -File`, no automatic execution-policy bypass. JSONL UTF-8, structured arguments, no shell text. [Trust/PATH guide](../../.trellis/tasks/10-15-extension-trust-path/usage.md).

Whole-plugin trust grants all current ordinary-user permissions. Declared permissions and purposes are informational, not a filesystem/network sandbox. No host-assisted administrator/UAC/SYSTEM execution. Runtime/code/declaration changes require new trust. Time/output/process/memory/concurrency/cancel limits remain after trust. Same-user external dependencies cannot be exhaustively monitored; OS/network side effects cannot be rolled back by host.

Settings: text, bool, integer number with min/max, choice, file, folder, password. Save/Cancel explicit. Password defaults and raw config values are rejected; secrets reach the selected trusted handler only through `credentials.get` and the private transport, never argv/environment/log. Generic Windows credential storage accepts at most2,560 bytes; protocol32KiB is a transport limit, not a larger native storage promise. Blank secret draft means unchanged; explicit clear deletes.
Optional `validation` on text/file/folder supports required, Unicode scalar min_length/max_length and <=512UTF8byte full-string bounded Rust regex(compiled/DFA1MiB each); existing32768UTF8byte value cap remains. No filesystem/share existence probes, script validators, password/bool rules or automatic trimming. Required-empty declarations may import/load, but Save/invoke readiness rejects before secret/native effects. Choice accepts original string arrays(including previously valid duplicates) or homogeneous `{value,label}` arrays(unique values); stored/default value is value, not label. Invalid current selections stay explicit. P1 source/isolated checks passed; real UI/installed acceptance is not implied.

## Handler registrations

`feature/entry`: `quick_launch/command`, `quick_launch/provider`, `tools/action`, `downloads/resolve`, `downloads/action`, `downloads/created|completed|failed`, `clipboard/action|committed`. Script action: `{"type":"script","entry_file":"entry.py"}`. Ordinary providers and automatic events are individually default-off. Events come only after feature commit, never progress/pointer/capture callbacks.

Automatic handler failures three times within one minute pause that handler. The manager shows the fixed reason and offers explicit retry; retry waits for a new committed event and does not replay old events. Download/Clipboard owner transactions stay committed even when a handler fails.

Resolver matching: exact host or explicitly included subdomains, bounded path `*`/`?`, declared priority then specificity. Default chooses one handler. A top tie is an explicit conflict, not arbitrary choice. User ordered chains have at most8 distinct stages; previous validated result feeds the next, failure stops, unchanged/not_handled passes through. Repeated changed URL is a cycle. No rediscovery or broadcast after rewrite. No-match behaves as original download path.

## Transport

One UTF-8 JSON object per LF-delimited stdin/stdout line. stdout is protocol only. stderr is bounded but never copied into production logs. Max frame256KiB/input1MiB/stdout4MiB/stderr64KiB. Exit before valid completion fails. Host calls8active/64total; search items keyword200, ordinary3/provider12total. Per-plugin1/global4; queue32, finite native process trees. Deadlines include queue/identity/start/output/effects; timeout cancels owned ordinary process trees.

When `runtime.timeout_ms` is omitted, entry defaults are search3s, download resolver10s, manual/event30s. Explicit values are clamped to search10s/resolver30s/manual-event120s; the chain also has60s total cap. Native jobs currently use512MiB and8processes; broker enforces2GiB aggregate. These are resource limits, not access restrictions.

Initial host frame includes `protocol_version:1`, `op:"invoke"`, UUID `run_id`, `correlation_id`, generation, package/handler/content identity, feature, typed `context`, nonsecret `settings` and host-owned `causality`. Replies must use exactly the same run ID; unknown/duplicate fields or keys reject. Scripts do not provide trusted generation/trust identity.

```json
{"protocol_version":1,"op":"host_call","run_id":"UUID","call_id":"describe","method":"host.describe","params":{}}
{"protocol_version":1,"op":"host_result","run_id":"UUID","call_id":"describe","success":true,"value":{"version":1}}
{"protocol_version":1,"op":"complete","run_id":"UUID","status":"success","value":{"text":"done"}}
```

Completion status: success, handled, not_handled, error. Streaming provider:

```json
{"protocol_version":1,"op":"result_batch","run_id":"UUID","sequence":1,"replace":false,"items":[{"id":"stable-id","title":"Result","subtitle":"Detail","action":{"type":"copy","text":"value"}}]}
```

Stable IDs are package/handler/item namespaced. Sequence starts1 and increases by1. Same ID updates in place; late new rows never displace committed selection. Action types: open(target), copy(text), program(executable,arguments[],working_directory), query(text), invoke(action_id). No elevation fields. Current query/content/trust and selected action are rechecked before effect.

## Host operations

`host.describe` advertises versions, actual headless availability and effective caps. Unknown method returns `unsupported`, not reflection. `credentials.get {key}` returns only own declared password setting. First-release methods through existing feature owners:

- `downloads.list {limit<=32}`, `downloads.get {task_id}`; probe/submit/enqueue `{request,idempotency_key?,resolution?}`; pause/resume/cancel `{task_id}`. Resolver may not recursively probe/submit/enqueue through itself; fixed reentry error avoids same-plugin slot deadlock.
- `clipboard.get {item_id}`, query `{query,limit<=32}`, create_derived `{source_item_id,text}` or paths. Original remains. Image snapshot gives ID/dimensions; image-read is not advertised yet. `clipboard.copy` uses existing native suppression and completion.
- GUI: `common.open {target}`, program `{executable,arguments[],working_directory?}` without elevation, copy `{text}` or paths, notify `{title,message}`. `quick_launch.search {query}` uses current available Finder sources; query updates an already open original input, never implicitly opens a popup. GUI-only methods return `ui_unavailable` in background host.

## Download result and receipts

Resolver invoke context: `{original_url,request,stage}`. `request` is the validated previous effective request, private context goes only to selected handler.

```json
{"protocol_version":1,"op":"complete","run_id":"UUID","status":"handled","value":{"url":"https://download.example/file","file_name":"suggestion.bin","valid_for_ms":60000}}
```

Optional explicit context: `{headers:[{name,value}],cookie:null,referrer:null}` replaces rather than merges. Any origin change drops automatically inherited ALL headers/Cookie/Referrer and old media; transformed resource clears old expected length/media. Existing proxy/TLS/rate/category/schedule/filename/resume validation remains host-owned. Plugin-owned HTTP is not automatically forced through product proxy.

Probe issues a host-owned opaque receipt bounded256/10minutes max, clamped by shorter plugin validity. Submit reuses original resource identity+operation ID, host-stored effective context/content/settings/session approval. Save filename/directory/category/schedule/rate/media choice may be confirmed without rerunning parser; URL/credentials/TLS changes require explicit retry. Forged/expired/evicted/revoked receipt fails resolution-required, not silent rerun. Durable accepted idempotent replay occurs before resolution. Old task resume uses persisted effective request and original validators without requiring a plugin.

Host-call receipt reuse keeps the original request and adds `resolution:{operation_id:"<probe.resolution.provenance.operation_id>",mode:{kind:"receipt",receipt:"<probe.resolution.receipt>"}}` to submit/enqueue (or repeat probe). The following host-call correlation ID may differ. Omitted resolution or `{}` means explicit new Resolve using the host correlation ID. Nil/missing receipt operation IDs, unknown fields, caller-provided effective context and bypass modes reject. Expired/changed/invalid receipt returns `resolution_required`; no implicit resolution. Host cancellation/lease closure and dropped host-call futures cancel the actual engine operation before probe publication or task commit.

## Opt-in v2 once foundation (capability expansion P0)

Omitted `runtime.protocol_version` is1 and omitted `runtime.mode` is`once`; explicit1/once defaults serialize away, preserving old canonical manifests/content hashes. Version2 is explicit: `"runtime":{"program":"python","protocol_version":2}`. Unknown versions reject import. Resident declarations require2, a listed relative `resident_entry_file`, and optional `idle_exit_seconds`30–600(default120), but **resident execution remains unavailable until P7**; it never silently falls back to once.

Host sends `{"protocol_version":2,"op":"initialize","session_id":"UUID","mode":"once","limits":{...}}`; script answers `{"protocol_version":2,"op":"ready","session_id":"same UUID"}` within5seconds and the original queue-inclusive deadline. Host then sends the original invoke fields plus the same session_id and protocol_version2. Every subsequent script frame and host reply carries exact session_id/run_id. Existing host_call/result_batch/complete semantics stay; duplicate/unknown keys and wrong identity fail closed. After complete, script must emit `{"protocol_version":2,"op":"request_finished","session_id":"same UUID","run_id":"same UUID"}` and exit. Success is published only after original native tree exit/cleanup, never merely on complete or request_finished. Completion with unresolved host calls fails.

There is one broker event reader and at most8host-call futures/64total calls. Replies may be out of order by call_id. Ordinary limits remain256KiB/frame(including LF),1MiBhost input and4MiBscript output including handshake/wrapper bytes; stderr64KiB. Explicit v2 supports the bounded progress/data plane below. Original authenticated Start opts into fixed native outer ceilings25MiBinput/28MiBstdout; Rust independently validates the ordinary/data split. Legacy omitted Start fields retain1/4MiB. Unknown/unregistered data is rejected, never exempted. `host.describe.transport` reports active/supported versions, modes, progress/blob availability and effective limits; blob/storage methods have minimum_transport2. Future HTTP/image/full-source search methods remain unadvertised. Storage additionally requires an explicitly composed host owner. Formal GUI/headless Desktop composition injects the app-data owner and performs background locked startup reconciliation. Original Desktop management controls are connected; final P3 checks and native/visual acceptance are recorded separately, not inferred from API availability.

Optional SDKs preserve v1 default. Explicit v2 once: Python `Session(protocol_version=2)`; Node `await Session.start(process.stdin,process.stdout,{protocolVersion:2})`. They perform handshake and finish acknowledgement automatically, do not retry effects, and currently issue host calls serially; direct authors may multiplex within host limits. These are source/owned-process contracts, not installed/native UI acceptance.

## V2 progress and temporary blob plane (P2)

`progress` is a script frame, not a host call: `{protocol_version:2,op:"progress",session_id,run_id,sequence,completed?,total?,message?}`. Sequence must strictly increase. Both counts are absent (indeterminate) or both integers0<=completed<=total<=2^53-1, total>0. Message<=512UTF8bytes/plain text, no controls except newline/tab. At most256frames/run; burst reports are consumed/validated and coalesced, foreground projection publishes at most4times/second. Terminal/cancel removes transient progress immediately. No deadline extension, effect retry, per-tick log/notification or100%=success. Existing manual/activity surfaces render official4DIP Progress; plugin message is UI-only and not persistent history.

Blob methods version1/minimum_transport2, strict parameters:
- `blobs.begin {length,media_type,sha256}` -> `{blob_id,transfer_id,length,media_type,sha256}`. Length0..8MiB, media_type1..128UTF8bytes/no controls, lowercase64hex SHA256. Host reserves exact quota before returning an opaque upload transfer; no extension-supplied paths.
- `blobs.seal {blob_id}` -> `{blob_id,length,media_type,sha256}` only after exact length/digest verification; sealed data is immutable.
- `blobs.read {blob_id,offset?:0,length?}` -> `{transfer_id,length}` starts a bounded span, not one host call per chunk. Offset defaults0; length defaults remaining bytes, each span<=8MiB.
- `blobs.release {blob_id}` -> `{}` removes logical access then attempts actual managed backing cleanup. Failure keeps reservations for bounded cleanup retry; no rollback/secure-erase guarantee. A released incomplete upload is retired from the session. No foreign/stale handle accepted.

Upload frame: `{protocol_version:2,op:"data",session_id,run_id,transfer_id,sequence,offset,data:"base64"}`. Host ACK uses `op:"data_ack"`, same identity/transfer/sequence and offset equal to the next byte. Download uses the same data frame/child ACK. Sequences start1, offsets are absolute within blob, no gap/overlap/duplicate; canonical base64 chunk<=64KiBdecoded. Only host-registered transfers are valid. One outstanding chunk/ACK per transfer, ACK timeout5seconds. Total4transfers(run cumulative),512chunks(upload+download combined), decoded16MiB and exact encoded-wire24MiB independently each direction; ACKs spend ordinary control budget. Frame limit never grows. Completion needs all host calls/transfers/IO quiescent and no unsealed live blob.

Perblob8MiB, aggregate live/run16MiB, global temporary backing64MiB,4live blob slots/run,120second lease never beyond invocation. Logical cancellation/revoke/drop retires access; real blockingIO/backing/delete retains byte/slot reservations until physical cleanup. Failed deletion is retained/retried by one store owner, not a replacement worker. Direct current-user OS authority of trusted scripts is unchanged; these are API resource boundaries, not an OS filesystem/network sandbox.

Python helpers: `progress(completed=None,total=None,message=None)`, `blob_upload(bytes,media_type)`, `blob_read(descriptor,offset=0,length=None)`, `blob_release(descriptor)`. Node/TS: `progress({completed?,total?,message?})`, `blobUpload(Uint8Array,mediaType)`, `blobRead(descriptor,{offset?,length?})`, `blobRelease(descriptor)`. One receiver; Python synchronous helpers, Node serializes at most8accepted helper operations. Direct authors can multiplex within host bounds; helpers never auto-retry or renegotiate v1. These checks are source/owned-process/TestApp evidence, not installed/nativeUI/visual/reader acceptance.

## V2 installation-owned persistent storage (P3 source boundary)

Four methodversion1/minimum_transport2 methods use strict parameters; no package/namespace/path parameter. A configured host resolves the current trusted installation through the original locked Core transaction. `host.describe` and invalid/unknown storage requests do not allocate data. Unconfigured hosts return `capability_unavailable`; v1 returns `unsupported_transport`. Ordinary publication/revoke still invalidates current calls; only the exact host-issued lazy UUID commit updates that invocation's metadata snapshot. This does not grant an OS sandbox or encrypt data; use credentials for secrets.
- `storage.get {key}` -> `{found,value,revision}`. Missing has foundfalse/valuenull; a stored JSONnull has foundtrue. Revision is the namespace revision observed atomically.
- `storage.set {key,value,expected_revision?}` and `storage.delete {key,expected_revision?}` -> `{revision,cleanup_pending}`. Optional CAS compares the namespace revision, conflict returns `storage_conflict` without changing it. No implicit retry or multi-key transaction. Committed data may outlive cancellation; cleanup_pending is not rollback.
- `storage.list {prefix?:"",limit?:32,cursor?}` -> `{items:[{key,revision}],revision,has_more,next_cursor}`. Metadata only,<=32items/128KiB. Opaque cursor expires60seconds, bound to full invocation/query/namespace revision; mutation returns `cursor_stale`, foreign cursor `invalid_cursor`. Explicitly restart without cursor; no automatic requery.

Keys1..128UTF8bytes/no controls; JSONvalue<=64KiB/depth16; namespace<=256keys/4MiBserialized; aggregate128MiB includes retained generations, metadata1024 including pre-reserved orphan records. No silent eviction. One bounded32job IO owner, globalcatalog/quota lock before namespace lock, one durable4MiB physical-copy reservation; real IO/deletion retains capacity after logical cancellation. Corrupt/missing referenced metadata is an error and retained, never empty reset. Upgrade carries the data UUID independently of trust/settings resets; same-ID reimport does not inherit it. Original removal confirmation defaults to retaining data; its separate clear-data Checkbox starts unchecked on every opening. A committed removal plus failed deletion reports data cleanup pending, never registration rollback.

The Core/owner source boundary supports explicit reviewed restore and retained clear/retry. Restore checks current installed trust/runtime, exact retained revision/bytes/state and an empty target; it reserves a fresh UUID and durable intent before the original locked config pointer commit. Recovery reads actual registry pointers and never reactivates old source/target handles, merges values or silently overwrites data. Failed config commit retains old pointer/data; committed pointer plus failed physical cleanup reports pending. Old backing/lock cleanup keeps its bounded metadata reservation until actual deletion. Retained clear/retry compares a fresh registry and exact reviewed metadata and never rewrites config. These are host-only management APIs, not new script methods. Desktop package Settings links to the same data-management page as the workspace entry, which remains reachable with no installed packages. Reads retain at most16 metadata records per batch, never values; the ordering continuation grants no mutation authority. Every restore/clear/retry requires current review and original Dialog confirmation, and terminal changes invalidate the review until explicit refresh. Cancellation does not release busy/resource ownership before actual blocking work finishes. Native/visual/installed acceptance remains deferred.
The data-management page also provides an explicitly confirmed retry for already-authorized `ClearPending`/restore-cleanup obligations, including old lock files that are intentionally excluded from restorable metadata. This rechecks the fresh registry under the original Core lock, never authorizes deletion of ordinary retained generations and never rewrites config. Read/refresh alone does not retry cleanup.

Desktop GUI/headless services inject `AppPaths.data_dir/extensions-data`, outside immutable code staging. Startup reconciliation uses a fresh original Core lock on a bounded background worker and preserves data on corrupt configuration. The original service publication lock covers durable binding through exact runtime application, and background management commits publish before UI callbacks. A bounded revision signal refreshes only exact None-to-committed UUID cache metadata on later GPUI turns; it does not relax ordinary trust/settings identity or cancel current provider requests. Resolver routing/receipt identity excludes this metadata, so lazy binding does not invalidate accepted downloads. Owned-process/TestApp checks cover these source contracts, not product launch or installed acceptance.

Python: `storage_get(key)`, `storage_set(key,value,expected_revision=None)`, `storage_delete(key,expected_revision=None)`, `storage_list(prefix="",limit=32,cursor=None)`. Node/TS: `storageGet(key)`, `storageSet(key,value,{expectedRevision?})`, `storageDelete(key,{expectedRevision?})`, `storageList({prefix?,limit?,cursor?})`. Helpers enforce v2, reuse the original receiver/call cap and never retry conflicts or cleanup failures. Owned-file/process checks are not installed/native/visual acceptance.

## P4 destination declarations (implementation in progress, no HTTP method yet)
Optional manifest `network` must be an object with only optional `origins`, an array of at most32 exact HTTP(S) origins (each <=8192UTF8bytes). Parsing is IO-free and canonicalizes scheme/IDNAhost/effectiveport, including a single trailing slash/defaultport. Canonical IPv4/IPv6, localhost and explicitly declared local/private destinations are allowed. Wildcards, subnets, paths, queries, fragments, userinfo, ambiguous shortened/octal/hexIPv4, unknown fields and normalized duplicates reject. Omitted/empty declarations serialize away and retain literal legacy hashes; nonempty declarations are content/trust bound.
This declaration slice does not register, advertise or execute `http.request`; HTTP capability/SDK/dispatch remains pending in P4. Declared targets are not an OS sandbox/firewall or DNS-rebinding defense, and trusted scripts retain current-user direct OS authority. Local/private declarations require careful trust review. Existing download resolver and direct script networking behavior is unchanged.
