## Verified plugin design

- Three forms: in-process **declarative zero-code interpretation**, external one-shot process, or external resident process using newline JSON-RPC2.0. SDKs wrap the protocol in Python, PowerShell and a C++ header; they are not mandatory.
- Discovery: user plugins under `%LOCALAPPDATA%\WinShun\plugins` take precedence over bundled plugins. Bundled plugins start disabled. Manifest declarations include commands, triggers, actions, settings and optional AI exposure.
- Call chain: `src/app/Launcher.cpp` -> `src/plugin/Catalog.cpp` / `Host.cpp` -> `Runner.cpp` -> non-elevated `WinShunPluginHost.exe` (`src/plugin/runner/main.cpp`) -> external plugin. `Session.cpp` routes resident requests; `Merge.cpp` maps stable item identities into launcher rows. Zero-code uses `ZeroCode.cpp` instead of starting a plugin process.
- Actions are typed effects (hide/keep/query/notification/copy/open/replace), not UI callbacks supplied by plugins. A declarative open can use the existing host execution path; a custom action returns through the external protocol.
- Host source contains stale-query rejection, one-shot debounce, timeouts, resident count (default8), idle exit (default600s), three consecutive timeouts before restart, 1/5/30s backoff and three crashes in5minutes before disablement. These are verified reference defaults, not adopted Next policy.
- Runner creates processes suspended, assigns the nested Job Object, then resumes. `Sandbox.cpp#makeJob` applies kill-on-close, per-process memory limits, optional active-process limit and clipboard/UI restrictions. `Runner.cpp#usableForPlugins` rejects elevated/high-integrity token candidates; Explorer-token startup has a restricted-token fallback.
- Permission truth matters: host-tool access is checked in `Host.cpp#onToolCall`; child-process and direct clipboard restrictions use Job Objects. File-read paths and network access are **declarations**, not OS allowlists. Normal-mode plugins can write what the user can. Strict low integrity prevents ordinary medium-integrity writes but is not a full read/network sandbox or proof that only one directory is writable.
- Password settings use `Secrets.cpp` Windows Credential Manager storage. This avoids plaintext INI storage; it does not protect a secret from the plugin that is intentionally given that secret or from arbitrary same-user malware.
- Optional MCP query/action exposure uses separate switches. A read-only tool annotation does not prove arbitrary third-party query code has no side effects. AI exposure is not part of the initial recommendation.
