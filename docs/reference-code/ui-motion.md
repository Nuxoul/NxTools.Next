# System motion preference boundary

Verified 2026-10-09 for the staged UI common capability. The approved stage design (`.trellis/tasks/10-02-staged-desktop-ui/design.md`) requires only short, user-triggered motion; reducing system animation is an intentional additional accessibility constraint, not a legacy animation migration.

## Native source / verified entries

- Windows SDK `C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\um\WinUser.h` defines `SPI_GETCLIENTAREAANIMATION` as `0x1042` (alongside, but distinct from, `SPI_GETUIEFFECTS` = `0x103E`). `SystemParametersInfoW(SPI_GETCLIENTAREAANIMATION, 0, &BOOL, 0)` reads the system's client-area animation setting. BOOL zero means reduced motion; a failed call requires `GetLastError`, with an explicit `-1` fallback when it reports zero. Do not read an application-persisted flag or mutate the user's preference.
- `repo:csharp/NxTools.PlatformHost/Windows/SystemMotionPreference.cs#WindowsSystemMotionReader` owns the P/Invoke and fail-closed sampling; `#SystemMotionPreference` owns the synthetic-reader seam, snapshot and deduplication.
- `repo:csharp/NxTools.PlatformHost/Windows/WindowsPlatformAdapter.EventWindow.cs#OnSystemUserPreferenceChanged` already subscribes to `Microsoft.Win32.SystemEvents.UserPreferenceChanged` for overlay geometry, because `EventWindow` is an `HWND_MESSAGE` window which does not receive top-level `WM_SETTINGCHANGE` broadcasts. Reuse that subscription, post to its own STA to read the preference and unsubscribe before destroying the handle in `Stop`. Retain existing overlay, clipboard and DOpus handling unchanged.
- `repo:csharp/NxTools.PlatformHost/Protocol/PlatformPipeClient.cs#RunSessionAsync` discards prior queued events on handshake; therefore send one fresh cached preference event **after every acknowledgement/discard**, before starting normal event forwarding. This is independent of the prior session's queue.
- `repo:rust/crates/nxtools-protocol/src/lib.rs#SystemMotionPreferenceChanged` owns the typed v1 event; the same UUID appears in envelope correlation and payload. `repo:rust/apps/nxtools-desktop/src/platform_events.rs#PlatformEventDispatcher` applies that event to `repo:rust/apps/nxtools-desktop/src/ui/motion.rs#UiMotionPreference` without notifying leased application entities. Unknown/disconnected/failed native states disable motion; identical updates do not mutate the GPUI global. `motion_allowed(&App)` and `reduced_motion(&App)` are the render-time API for the separate view migration; durations remain 120/120/160 ms when motion is allowed.

## Invariants and remaining acceptance

Preference observation never shows/hides, places, resizes or focuses any window. No per-frame polling or synchronous cross-entity callback. Read failure reduces motion; diagnostics include only UUID, boolean, native code, elapsed time, and fixed event names. The bounded nonblocking event queue is backed by `PendingMotionPublication`, an event-STA-owned single latest-state slot. A failed `TryWrite` retains that slot, newer samples supersede it, and timer7 retries at250ms on the same STA; successful publication retires once and Stop clears/rejects further staging. A fresh cached state also goes out on every session handshake. Interactive Windows preference toggling, reconnection and supported-DPI acceptance remain separate; synthetic reader/serialization/backpressure tests do not claim native preference mutation or runtime acceptance.

Parent integration consumes the policy in all current desktop animation sites (download inspector/task phase/taskbar, Quick Find results/search/preview/settings scroll, clipboard preview and notifications). `observe_motion` is keyed once per view/window, holds a weak view and defers local notify after global changes; already-open views repaint without cross-owner entity re-entry. The shared nested production MotionSurface regression proves permitted entrance versus exact final geometry after reduce; notifications dismiss immediately with generation guard. Desktop460/protocol40 and exact C# synthetic1 pass; live Windows preference toggle/reconnect acceptance remains separate.

The directed integration review found and closed three concrete gaps: full queue retirement lost a deduplicated preference (now retained/latest-slot retried), reduced motion during notification exit repainted the card (now omitted immediately), and a visual-policy no-change hid native failure/recovery diagnostics (now logged independently of visual deduplication). No animation-frame or retry-tick logging was introduced.

Continuation: native `SetTimer` now captures last-error and its zero return is handled. A failed motion retry timer keeps the pending slot/correlation and records `system.motion.retry_timer_failed` once per failure episode (no retry-tick logs); later native refresh or per-session snapshot can recover delivery. No alternative worker or unbounded polling is created. Synthetic slot tests verify rejected delivery preserves correlation and Stop clears it. Real timer allocation failure injection and live-toggle acceptance are still pending.
