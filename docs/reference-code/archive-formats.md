# Additional archive formats: verified reader boundaries

This approved compatibility expansion has no legacy NxTools general archive browser. The Bandizip family dispatch and WIM native-handler evidence remain in [archive.md](archive.md) and the linked format-family/WIM research. The sources below are the published crate source for the selected implementation, not claims of runtime acceptance.

All readers remain inside `isolated-codecs` child, with original native source acquisition, BrowserContext/source binding, operation/correlation, bounded metadata and output, typed first failure, native partial/commit/abort and original terminal/cleanup. List does not imply test/payload verified. Cancellable output is fixed-size and publication requires a complete decoded/verified member; special and link entries are never published as regular files. Source revision and native source identity are checked before extraction. No payload is logged.

## Supplied-corpus boundaries

The file named `wim-lzms.wim` has header flags0x00000080, chunk_size0 and one image: it is an
uncompressed WIM, not runtime LZMS evidence. The compressed-handler capability above is source-
verified; the supplied native payload comparison does not certify every compression variant.
The Windows bsdtar odc CPIO includes ANSI names and irreversible `?` substitutions. Preserve its
raw names and explicit encoding choice; Test/safe-member preview remain available, while whole
Windows extraction returns UnsafePath rather than silently rewriting those names.

## B7 ALZ/EGG source boundary

[REF-19 source review](../../.trellis/tasks/11-12-reference-b7-format-expansion/ref19-source-review.md) records exact public source revisions, license/sample provenance and actual container/method/volume call chains. ALZ Stored/Deflate/modified-Bzip2 and EGG Stored/Deflate/Bzip2/AZO/LZMA are different capability rows; upstream reader construction does not establish all payloads, passwords, solid variants or header encryption. Their automatic sibling discovery and filesystem extraction are not integration candidates: the existing native complete-volume lease and bounded capability-output chain remain the owners. B7 source investigation does not by itself advertise new product support.

EGG LZMA known-size boundary: pinned EggDotNet `src/EggDotNet/Compression/LzmaCompressionProvider.cs::GetDecompressStream` skips the opaque four-byte SDK prefix, reads five property bytes and constructs `LzmaStream(props, stream, compressedSize - 9, uncompressedSize)`; `Format/Egg/EggFormat.cs::GetDecompressStream` supplies the file sizes. The CC0 `lzma5.egg` blocks decode to the same exact five members as Stored/Deflate using CPython LZMA1; they do not carry EOS. EGG's opaque prefix must not inherit ZIP14's properties-size requirement. Reuse only the existing bounded model/dictionary/known-size stream, retaining exact compressed-consumption and per-block CRC checks. The public unegg LZMA adapter instead builds an unknown-size stream and buffers the entire packed block; that adapter is not adopted.

ALZ password boundary: pinned unalz `extract.rs::extract_entry` calls `encoding::password_to_cp949`, then `crypto.rs::ZipCrypto::check_header` and streaming method decode. The twelve-byte header precedes, but is excluded from, the declared packed payload. Descriptor bit3 selects the DOS-time high byte; otherwise the CRC high byte is the probabilistic verifier. CPython `zipfile._ZipDecrypter` plus strict raw zlib independently verifies the unchanged CC0 `enc_store.alz`, `enc_deflate.alz` and `zip20.alz`, including the latter's unencrypted empty entry and CP949 names. Product adaptation reuses `formats/zip_crypto.rs` bounded traditional reader with explicit password bytes/check byte; ZIP retains UTF-8 password derivation. ALZ failures after a probabilistic verifier, including decoded size/CRC mismatch, remain AuthenticationOrDataError, not definitive WrongPassword. The original `worker.rs::job_password_format` → `worker_password::execute` owns finite no-output preparation, prompt tickets, cancellation and the single subsequent extraction; native Runner/Job retain source/helper leases through actual cleanup.

EGG password boundary: pinned unegg `archive.rs::parse_entry/read_encrypt_payload` → `extract.rs::setup_decryptor/verify_hmac/extract_entry`, `crypto.rs::ZipCrypto`, `aes_ctr.rs::AesCtrDecryptor` and public CC0 EGG specification sections8.5/12 define detached per-file encryption metadata, UTF-8 password bytes, continuous state across blocks, AES little-endian counter1, LEA big-endian counter0 and HMAC-SHA1 over all file ciphertext. Real CC0 producers include Encrypt Info sizes that exceed the method's fixed payload; the fixed method length must end at a valid sub-header boundary, not consume the following block. AES/LEA require the full ten-byte authentication tag for the supported authenticated profile. Global/header/name encryption remains unsupported. The specification's full32-bit traditional multiply and the existing ZIP low16-bit multiply produce the same selected output byte; CPython's independent traditional decryptor verifies genuine EGG bytes, rather than assuming a compatible framing. Product integration reuses the original zeroizing traditional state and AES primitive, with a fixed-size specification-based LEA schedule and no plaintext spool or whole-member buffer. Original `job_password_format` → `worker_password::execute` retains finite no-output preparation, prompt tickets, cancel and one subsequent extraction. Independent CPython/PyCryptodome/specification-vector validation qualifies14unchanged CC0 archives,62files/700,148bytes, including Bzip2, nested names, clear empty entries and overstated encryption lengths.

Five separately labelled project-owned EGG two-block fixtures independently verify cipher state across a455-byte packed boundary and authentication of both blocks. They use a fixed recoverable FILETIME and contribute1,074,210literal bytes; they are not additional producer samples. Native metadata restoration retains its original explicit `metadata_time_not_supported` outcome when Windows cannot restore FILETIME0.

ALZ modified-Bzip2 boundary: pinned kippler/unalz `unalz-0.65/UnAlzBzip2.cpp` → `UnAlzBz2decompress.c` uses a fixed900,000-byte BWT block, unaligned32-bit DLZ01/DLZ02 markers, no block CRC/randomization/combined CRC, and the standard Huffman selector/MTF/BWT/RLE stages. A marker is read only after decoded end-of-block, never found by byte scanning. Public alkegi `decompress/bzip2.rs::extract_bzip2` instead buffers the full member and probes candidate markers; that interface is not adopted. The product-local reader retains one bounded BWT/index workspace, fixed selectors/tables and controlled output through the original per-member size/CRC and publication owner. No upstream implementation is copied or new dependency selected. Independent prerequisite parsing reconstructs each block with its true Bzip2 CRC and requires strict CPython bz2 completion; genuine single-block samples and separately labelled project-owned multi-block evidence remain distinct.

EGG solid Deflate boundary: pinned unegg `extract.rs::extract_all_solid` distinguishes file-size output spans from per-block CRC spans, then decodes one continuous stream; its `SolidSink` routes those independent boundaries. The public adapter's whole-compressed-stream buffer is not adopted. The CC0 `solid.egg` has five files totaling6,342bytes and one Deflate block attached to its last file; the first four files own no block. Independent CPython framing/raw-zlib/CRC verification qualifies that unchanged sample and a separately labelled project-owned three-block stream whose CRC spans do not coincide with file boundaries. The original native source leases and per-commit source checks remain authoritative. Product adaptation must preverify the complete CRC stream before any file publication, then retain one bounded Deflate decoder across sequential file outputs; selected later files require predecessor decoding, not a decoder reset at the selected file. Other solid methods and solid encryption remain separate capability rows.

Selected solid Job preparation follows the original `worker_password.rs::execute` read-only request. That request deliberately carries no output/conflict/delete authority and verifies the complete archive. Its existing finite default decode allowance for Browser single-member/output-readmission requests must also cover `job_extract.selection`; otherwise a valid small selected output is charged for unselected files before extraction. Only preparation uses that existing ceiling. The original extraction request, selection plan, member/output budgets and native publication credit are unchanged.

Native `ArchiveWorkerRunner` → `ArchiveVolumeSources.Open(..., alzegOutputPreflight)` and Rust `SourceSet::open_formats` likewise distinguish finite encoded-source admission from selected target output credit. Original ALZ/EGG Job selections need the same encoded-only default ceiling as output readmission; held content signatures, complete-family leases, metadata/working bounds, immutable source binding and final selected output quotas stay unchanged. Genuine three-part Stored families provide the boundary case:160,000encoded payload bytes versus one40,000-byte selected output with8KiB metadata.

AZO boundary: public CC0 EGG AppendixA defines the32-bit range coder, dual adaptive literal/length models, recent-distance/match histories, big-endian internal block sizes/check, terminal zero block and per-internal-block x86 restoration. The original xunazo decoder supplies an independent source check for finite arithmetic tail semantics; no implementation is copied. Independent Python framing/arithmetic/format-CRC qualification verifies unchanged `azo.egg` and `optimal5.egg`, including exact equality with the existing five-member corpus. The private product reader must stream encoded input and filtered output, retain only a working-budgeted unfiltered ring dictionary, reject excessive lookahead/unused input/invalid matches and require exact terminal/size/CRC before publication. Owned specification samples distinguish effective x86/multi-block/history evidence from producer evidence. Solid, encrypted and split AZO profiles remain separate rows.

EGG kind boundary: pinned unegg `archive.rs::parse_file_entry` reads Windows-specific type bits and20-byte POSIX mode/uid/gid/Unix-mtime metadata. Its sample README identifies unchanged CC0 `posix.egg` as Android-produced. Independent CPython raw-zlib/CRC validation verifies three files/98bytes; production Read/Job/native output preserves those bytes and exact Unix mtime. The private parser accumulates kind identifiers so a later regular header cannot negate an identified Link/Special. Original File-only iteration, native directory handling and skipped-special summary remain authoritative; project-owned mixed-header fixtures verify both orders without creating links or devices.

EGG unauthenticated metadata boundary: source `EncryptionMethod::payload_lengths` also recognizes11/19-byte AES/LEA salt-plus-verifier payloads without the ten-byte HMAC. Product parsing accepts only exact short declarations ending at the mandatory End marker as a recognized unsupported profile, returning UnsupportedEncryption before catalog/output. Invalid size/end/truncation remains CorruptArchive. Existing full21/29-byte authenticated and sampled full-plus-seven records retain their original path; no candidate scanning or declared-size fallback. Independent project-owned AES128/256 and LEA128/256 specimens verify usable ciphertext/size/CRC, not authenticated extraction or producer-profile coverage.

EGG filename boundary: pinned CC0 specification section8.1 and unegg `archive.rs::parse_file_entry` place optional UInt16 locale (flag0x08), then UInt32 parent File ID (0x10), then raw name bytes;0x04 declares encrypted names. Locale932/949 is format metadata, not a user Explicit choice. Current product deliberately returns UnsupportedMethod for locale/parent declarations and UnsupportedEncryption for encrypted-name or reserved Global Encrypt declarations. Five independent specification specimens qualify field order/codecs/parent IDs; two further specimens qualify encryption-declaration refusal only, not producer encryption or decryption. No lossy unknown-locale fallback, leading-character stripping or dropped-parent interpretation is adopted.

Raw-path boundary: existing `path_policy::components/annotate` preserves decoded names and attaches UnsafePath; `worker_formats::admit` applies it before publication. Two independently qualified specification archives exercise15unsafe ALZ/EGG names each, including empty/control names. Browse preserves exact names/ordinals/warnings; read-only Test verifies30payloads/1,410bytes; extract rejects before native candidate output. Production Read preserves native corrupt/unsupported source-admission categories over consequential metadata-pump cancellation. Global Encrypt acquisition fails and releases leases, while parser rejection after acquisition retains source protection through cleanup.
