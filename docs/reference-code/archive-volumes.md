# Bandizip volume support — verified scope

Verified2026-11-09. Installed Bandizip.exe/ark.x64.dll are7.32.0.1; the current official product page advertises7.47. Do not silently apply a newer feature list to the installed binary.

## Public documentation

- [Split creation](https://www.bandisoft.com/bandizip/help/split/): New Archive → More options → Split to volumes; preset/custom sizes. All parts must be transferred and kept together. This page does not give an exhaustive per-format split-write matrix.
- [Split extraction](https://www.bandisoft.com/bandizip/help/split-archive-error/): explicitly shows ZIP (`.zip` entry) and7z (`.001` entry); remaining parts link automatically; keep all parts together.
- [ALZ/EGG](https://www.bandisoft.com/bandizip/help/how-to-open-alz-and-egg-files/): both format descriptions include split archives; Bandizip explicitly supports their listed algorithms/features. This is broader than NxTools' current ZIP/7z/RAR volume scope.
- [Current product](https://www.bandisoft.com/bandizip/) lists ZIP/7Z/ZIPX/EXE and other compression formats. [ZIPX help](https://www.bandisoft.com/bandizip/help/zipx/) says current Bandizip writes XZ-method ZIPX. A writable format is not by itself proof of split creation for that format.

Official HTML responses are retained in session scratch as `bandizip-official-*.html`; public pages were read without launching Bandizip, changing its settings or creating/extracting archives.

## NxTools coverage and remaining gap

The current Phase E implementation scope is ZIP disk-coordinate volumes plus continuous ZIP/7z and RAR4/5 protected source families; creation is ZIP and7z only. ZIP writing rebuilds per-disk local/central/end coordinates, while7z splits a verified continuous encoded stream. Native admission holds each complete same-directory consecutive family through the original worker lifetime. See [volume contract](../../.trellis/spec/nxtools-archive/backend/zip-volumes.md).

This is not full Bandizip volume parity. ALZ/EGG need their format readers and volume/method transitions; ZIP-SFX writing needs executable prefix/output layout and its own split constraints. Those format routes remain outside the approved writer/reader slice. B3 adds explicit generic `.001/.002` raw-file joining as an independent ordinary operation, never inferred from signature-bound ZIP/7z adapters. ZIPX split creation remains unverified in the reference rather than a confirmed NxTools gap. Opening/browsing, Test/extraction, creation and split-set modification must be reported independently; current supported split groups are not editable in place.

## Ordinary numbered join native ownership

`ArchiveSourceLease.Open` holds no-reparse parents and read-only source handles; `ReadmissionIdentity` is full native ID/size/mtime, not a content digest. `ArchiveOutputSession.Prepare` observes the existing destination; `BeginExtractedFile(overwrite:false)` owns the fresh final name, Write accepts at most65536bytes and32GiB/file, and Commit/Cancel close or remove only that owned incomplete output. `BeginFile` is the separate candidate/hash/publication path and is not the raw join boundary. `PlatformPipeClient.RunSessionAsync` owns cancellation/drain; synchronous admission before the detached dispatcher preserves exact cancellation ordering. `BoundedStaOperationRunner` retains its slot until worker finally, but its optional wait cancellation/timeout may return earlier; raw join must wait for physical completion and check cancellation within its finite-buffer operation. Other Tools remains `main_window/tools_page.rs` official ListItem tiles; `platform_events.rs` remains the single notification receiver.

The verified tool-window seam is `main_window/tools_page.rs::render_tools/open_tool_settings_window` with `MainWindow.tool_settings_windows`, `cx.open_window` and one `gpui_kit::base::Root`; existing-window activation is also cross-entity work and must be deferred outside the tile callback lease. `ui/components/titlebar.rs::controlled_titlebar/caption_window_options` owns caption/native close geometry, and `Window::on_window_should_close` is the native close interception boundary. `archive/forms.rs::OperationForm::close` retires local generation before deferring its application owner. `archive_picker.rs` already supplies Files and Save commands with session/generation/native HWND; picker events return through the single `platform_events.rs::PlatformEventDispatcher::forward`. The join slice uses that picker rather than another native dialog or notification consumer. Its close request cancels running work and awaits the original terminal, while a disconnect explicitly leaves output status unknown and delegates physical drain to the original per-pipe native owner.
