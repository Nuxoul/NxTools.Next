## 捕获方法说明(证据边界)

- 本机没有迁移前的历史包(`artifacts` 未随迁移带来),因此基线由 git 历史构建:
  在 detached 工作树 `D:\Code\NxTools.Next-baseline`(commit `36db4aa`)上执行
  `cargo build -p nxtools-desktop`。该工作树含一处**未提交**的本地补丁:
  `nxtools-core::AppPaths::discover` 读取 `NXTOOLS_BASELINE_DATA_ROOT` 环境变量把数据/配置/日志
  目录重定向到隔离目录,以免该快照(支持下载 schema 8)拒绝启动在 schema 9 的真实用户数据上。
  该补丁只影响路径发现,不影响任何渲染行为。
- 两个实例均使用独立空数据目录 `D:\Code\NxTools.Next-baseline-data`(截图中"存储位置"可见),
  未触碰用户真实数据;两个实例均已退出。
- Debug 构建用于双方(GPUI 渲染路径相同),最终 Release 截图矩阵仍按计划单独收口。

| 检查项 | 基线(迁移前) | 迁移后 | 结论 |

## 结论

CL-01 的共享 `settings_split_surface` 迁移在真实渲染中保持了密度、主次层级和长中文可读性;
未发现因组件化造成的舒适度下降。第四十三个切片带来的 0.5–2.5px 中文文本升幅仅使一处说明文字
换行,符合 DS-02"中文普通信息不得小于 11px"的既定规则。CL-01 的自动化实现与本次视觉对照
一并满足后,批次 5 可进入 CL-02(剪贴板弹窗字体、图标、菜单与状态组件)。

验收签字仍归用户;本审计提供对照证据,不替代用户对"舒适度未下降"的最终确认。
